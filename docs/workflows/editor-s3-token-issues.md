# Ada Tours — S3-допуск для приглашённых редакторов через GitHub Issue

**Назначение:** Анна и другие доверенные редакторы получают собственный зашифрованный допуск для прямой загрузки фотографий в `img.adatours.ru` без постоянных ключей Yandex Cloud, без записи изображений в Git и без права изменять `main` только ради загрузки.

## Кто может получить допуск

Авторизуется **GitHub-аккаунт, подключённый в конкретном ChatGPT Work/Codex-сеансе**, а не участие в общем ChatGPT Project. Приглашение в ChatGPT само по себе не является удостоверением для GitHub Actions.

Требуются одновременно:

1. GitHub-login редактора в `data/editorial/authorized-users.json → allowedGithubLogins` (на 30.10.2026: `alexyakovlev79`, `AnnaAdaTours`).
2. GitHub-роль в `alexyakovlev79/adatours.ru`, при которой GitHub присваивает Issue author association `OWNER` или `COLLABORATOR`. Новым редакторам достаточно роли **Triage** (права на Issues, без записи в код). Анне уже предоставлен доступ `write`.
3. Работающий GitHub-коннектор у самого редактора и среда ChatGPT Work / Codex с локальным Node.js, файлами изображений и HTTPS-доступом к S3.

Добавление нового логина в allowlist — отдельное действие владельца репозитория. Не расширять список до `*`, не принимать логины/токены из свободного текста без проверки.

## Каждый чат получает отдельный допуск

1. Прочитай `docs/workflows/direct-s3-upload.md`; подготовь окончательные файлы **вне Git**. Сначала выполни GPT Image, когда изображение требует обработки. Не выдавай загрузку исходника за улучшение GPT Image.
2. На компьютере Work из актуального `main`:
   `node scripts/media-work-session.mjs init --out /tmp/adatours-media-session-<unique>`.
   Сохрани локальные `<requestId>.request.json` и `<requestId>.private.pem`. **Приватный PEM никогда не отправлять в чат, Issue или GitHub.**
3. Под своим GitHub-аккаунтом создай **один новый Issue** в `alexyakovlev79/adatours.ru`:
   - заголовок: `[ADA-MEDIA-TOKEN] <requestId>`, точный идентификатор из JSON;
   - тело: **только полное содержимое публичного `*.request.json` как JSON**, без Markdown-обрамления и лишних полей.
   Это публичный запрос; он содержит только версию, ID, время, название бакета и открытый X25519-ключ.
4. GitHub Actions `Issue encrypted media token for authorized editors` проверит **системное имя автора GitHub, его роль, точный requestId, JSON-поля, X25519 и возраст запроса (меньше 20 минут)**. Только после проверки сервер получает OIDC и обменивает его на IAM-токен сервисного аккаунта. В лог и артефакт попадёт **только зашифрованный пакет**.
5. В комментарии Issue после успешного выполнения будет ссылка на Action run. Найди `SEALED_MEDIA_TOKEN=...` в логах или забери зашифрованный артефакт `encrypted-editor-session-...`. Пакет можно раскрыть только локальным приватным ключом соответствующего запроса. **Срок раскрытия пакета — 10 минут с его выпуска**; при истечении начать новый сеанс (не повторять старый Issue).
6. Выполни локально `node scripts/media-work-session.mjs upload` с параметрами `--request`, `--private`, `--envelope`, `--batch`, `--receipt`, как в `direct-s3-upload.md`. При прокси может понадобиться `node --use-env-proxy`. Подтверди фактический PUT, обратный GET, SHA-256 и receipt.
7. Только затем записывай текстовые ссылки, `src/data/media/direct-s3-uploads.json` и связанные MD/JSON через PR. Файл WebP/JPG/MP4 в Git не коммитить. `S3 upload` ≠ `Pages deployed`: публичную публикацию подтверждай отдельно.

## Разграничение доступа и ограничения

- Выпуск токена выполняет **GitHub Actions этого репозитория**, а не Yandex Cloud от имени индивидуального аккаунта Анны. Сервисный аккаунт `adatours-media-publisher` не передаёт редактору свой постоянный ключ.
- Шифрование защищает пересылку. Важно: **10 минут — срок зашифрованного пакета, а не гарантированный срок действия самого IAM-токена Yandex Cloud**. Права сервисного аккаунта должны быть строго ограничены необходимыми операциями с бакетом `img.adatours.ru`; срок IAM-токена устанавливает Yandex Cloud.
- Не использовать `issue_comment`, `pull_request_target` или произвольные команды из текста Issue для выдачи токенов. Выпуск происходит только на `issues.opened`, с кодом штатной ветки `main` и белым списком GitHub-авторов. Переоткрытие Issue/изменение комментариев не должно выдать новые полномочия.
- Любой ответ 401, отсутствие артефакта, просрочка или отсутствие receipt означает, что загрузка **не подтверждена**. Не заменяй ссылки на сайте фиктивным путём.
- После изменения прав GitHub или списка редакторов проверь доступ тестовым Issue от **самого нового аккаунта**. Успех тестового Issue владельца доказывает работоспособность механизма, но не проверяет авторизацию другого автора.
