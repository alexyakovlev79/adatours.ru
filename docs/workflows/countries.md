# Ada Tours — создание и обновление страны из готового источника

Адреса объектов и правила английских slug: `docs/workflows/urls.md`. Для существующего объекта использовать закреплённые `slug`, `url` и точный `contentPath`; русское название не транслитерировать заново.

Версия: 1.4 · 2026-10-05 · Репозиторий: `alexyakovlev79/adatours.ru`, ветка `main`.

Применяется к выбранной Country с подготовленным источником. Общий процесс — `docs/workflows/master.md`. Для Destination действует отдельный `docs/workflows/destinations.md`. Создавать дополнительные страны без записи и точного source эта инструкция не поручает.

## 1. Точный вход

Каталог стран: `data/source-index/catalogs/countries.json`. Полная запись: `data/source-index/entries/<entityId>.json`; общий индекс — `data/source-index/index.json`. Для продолжения использовать выбранный ID и сохраненную стадию.

Из `entry` взять `id`, `name`, `slug`, `contentPath`, `url`, `sourceUrl`, `text.selected` и `media.images`. Выбранный текст открывается по `text.selected.driveId` / `.url`; его редакционная роль указана в `.kind`. Архив V1 не считается готовым V2, original и очищенный newstep не взаимозаменяемы.

Читать exact entry, точный текст и целевой production MD, если он существует. Полученные в этом цикле неизмененные файлы использовать повторно. Не искать материалы по Drive, исходному сайту, интернету или всему репозиторию. Адресное отсутствие обязательного входа отражается в готовности записи; оно не запускает исследование.

Реестр: `1ZPptMdEcIDA3ZFMOQcFuc5jU88LJlFw9R4URCQSBmmc`, лист `Страницы`. Использовать выбранную строку. Общая сверка реестра, `main` и соседних страниц в задачу не входит.

## 1.1. Интересы не являются полями страны

Не создавать `themes` или `relatedThemes` в Country MD, exact entry либо каталоге стран. По `docs/workflows/interests.md` интересы Country вычисляются из активных размеченных туров; сами тематические хабы выводят страны по сумме весов таких туров. Старые ручные списки удалены и не восстанавливаются при следующем импорте. Обычные country-каталоги и счётчики основных туров сохраняют прежние правила; тематический страновой каталог отдельно подписывает дополнительные посещения.

## 2. Данные Country

Путь — exact `entry.contentPath` в `src/content/countries/`. Canonical URL — exact `entry.url` вида `/<country-slug>/`; `/country/` — общий каталог, прежние `/strany/` и `/strany/<slug>/` — только redirect aliases. Использовать закреплённый английский slug (Бразилия — `brazil`), не переименовывать content-файл из-за адреса. Схема — `src/content.config.ts`; `countryId` и `destinationType` принадлежат Destination и в Country не добавляются.

| Поля | Источник / правило |
|---|---|
| `id`, `locale: ru`, `slug`, `name` | Точные значения Country из entry |
| `status` | Для готовой новой сущности `approved`; действующий согласованный статус сохранять |
| `summary`, основной Markdown после frontmatter | Выбранный готовый текст; summary — его готовый вводный абзац или краткое извлечение без новых фактов |
| `searchAliases`, `regions`, `languages` | Уже подготовленные значения; при отсутствии `[]` |
| `bestTime`, `entryNotes`, `currency` | Только подготовленные подтвержденные строки; при отсутствии опустить |
| `hero: {src, alt}` | Закрепленный source hero страны или уже улучшенный действующий hero |
| `heroVideo: {src, sourceUrl}` | Необязательный MP4-видеофон по явному заданию: подтвержденный S3-файл; только верхний hero, на всех устройствах кроме телефонов. Планшеты и ноутбуки показывают видео независимо от ширины окна. `hero.src` сохраняется для карточек, других баннеров, телефонов и ошибок воспроизведения |
| `imageTextAlign` | Необязательное `left` или `right`; сохранять существующее значение, назначать по явной команде пользователя |
| `featureBands: [{eyebrow?, title, text, image, href?}]` | Только подготовленные блоки существующего шаблона; при отсутствии `[]` |
| `gallery` | Сохранять действующие данные при обновлении; при новом импорте `[]`, если конкретный вывод не предусмотрен |
| `featuredTours`, `featuredExcursions` | Для новой записи `[]`; текущие публичные списки строятся автоматически |
| `sourceUrl`, `sourceSnapshot`, `updatedAt` | Точные источники и дата изменения по правилам ниже |

Если `entry.sourceUrl` равен `null`, опустить поле `sourceUrl`: схема ожидает optional string и не принимает YAML `null`. `sourceSnapshot` — `text.selected.url` либо подтвержденная ссылка на родительский источник. Не подставлять выдуманный URL.

В `featureBands` обязательные `title`, `text` и `image` уже подготовлены; `image` — строка URL. Не создавать дополнительные блоки ради одинакового наполнения всех стран. Основной текст можно целиком сохранить в body.

Команда «перенеси текст Никарагуа влево» означает изменить только `imageTextAlign: left` в Country MD Никарагуа. Общие компоненты используют это значение в hero страны и во всех баннерах/карточках, показывающих страну с текстом поверх ее фотографии, вместе с CTA и метаданными. Для переноса вправо используется `right`; без поля сохраняется нынешнее расположение шаблона. Фото, crop и обычный текст вне фотографии не меняются. Такая команда не запускает импорт источников или фотопроход; достаточно целевой правки и одного штатного commit/CI.

## 3. Перенос текста и фото

Перенести выбранный текст без повторного рерайта, сокращения и новых фактов. Сохранить географию, названия, числа, сезонность и условия. Не уточнять актуальность виз, валют, цен или иных сведений через интернет в рамках импорта; отдельное изменение фактов выполняется по самостоятельному заданию.

Если отсутствует конкретное необходимое поле либо найдено реальное противоречие, использовать соответствующий фрагмент exact original, закрепленного в записи. Уже выполненную сверку не повторять. Не заполнять необязательные сведения догадкой.

Из `media.images[]` взять готовые `url`, `role`, `order`, `alt`. Перенести source hero и только дополнительные фотографии с заранее назначенными слотами `featureBands`. Старый hero-slider и gallery не копировать целиком; текущий CountryLayout не выводит отдельный общий gallery-блок.

Для внешних фото разрешены только закрепленные raw URL `https://brasiltours.ru/image/...` с исходным расширением. `/image/cache/` запрещен. Фотографии не скачивать, не запрашивать для повторной проверки, не восстанавливать URL, не улучшать и не искать замену. Отсутствующий raw URL — конкретный дефект входной записи. Уже улучшенные локальные assets сохранять.

## 4. Связанные разделы формирует CountryLayout

Шаблон автоматически использует активные RU-сущности:

- места — по `Destination.countryId`, по убыванию числа связанных туров, затем по русскому названию;
- туры — по основным странам маршрута: `Tour.routeCountries`, а при отсутствии поля по `Tour.countries`; тот же набор используется для подсчета числа туров и сортировки стран; по убыванию рейтинга `2 × число основных стран маршрута − |durationDays − 13|`; при равном рейтинге — по русскому title; тур без `durationDays` идет после туров с вычисляемым рейтингом;
- экскурсии — по геостране `excursionGeography()`, как в полном каталоге: страна основного места, при отсутствии места — `Excursion.country`; по убыванию числа связанных туров, затем по русскому title;
- темы — автоматически по активным тематическим турам через страну, с учётом основных и дополнительных меток Tour; `Country.relatedThemes` запрещено.

Лимиты общие для всех стран и всех размеров экрана. После сортировки CountryLayout выводит только начало каждого списка:

| Блок | Максимум на странице страны | Плитка на десктопе | Ссылка при превышении лимита |
|---|---:|---|---|
| Места | 15 | Три цикла `1+2+2` | `<Название страны>: все красоты` → `/<country-slug>/place/` |
| Туры | 10 | Действующие полноширинные баннеры | `<Название страны>: все туры` → `/<country-slug>/tour/` |
| Экскурсии | 5 | Один цикл `1+2+2` | `<Название страны>: все экскурсии` → `/<country-slug>/excursion/` |

Ссылка располагается под соответствующим блоком и появляется только когда полное число объектов строго больше лимита. При равенстве или меньшем числе ссылки нет; пустой блок не выводится. На мобильных сохраняется одноколоночное отображение. Лимит применяется к серверному выводу карточек, а не через скрытие лишних элементов CSS.

Полные каталоги уже формируются `src/pages/[...path].astro`; их состав и счетчики не ограничиваются. Ссылки строятся через `destinationCountryPath()`, `tourCountryPath()`, `excursionCountryPath()` и `withBase()`, без ручного составления URL. Полные массивы сохраняются для счетчиков поиска и настроек `imageTextAlign`; сокращение витрины не меняет данные сущностей, связи или тексты.

Добавляющий страну чат не читает все связанные MD, не подбирает карточки вручную, не создает недостающие места, туры или экскурсии и не пересчитывает рекомендации. При публикации связанных сущностей их блоки обновляются следующей сборкой. Пустой список не требует наполнения посторонним материалом.

Поиск, breadcrumbs, canonical, общие стили и форма уже определены шаблонами. Country MD не требует их отдельного проектирования или проверки страниц.

## 5. Один рабочий цикл

1. Прочитать выбранную entry, `text.selected` и целевой MD, если он существует.
2. Подготовить один Country MD: сохранить identity, перенести текст, известные поля и закрепленные фотографии.
3. Отправить один подготовленный commit и сохранить его SHA.
4. Получить результат одного штатного Actions run: offline-проверка внутри `npm run build`, затем предусмотренная публикация. Дополнительный local build и другие проверки не нужны.
5. После публикации один раз обновить выбранную строку реестра: E — `Добавлена`, F — дата первого добавления, H — stable ID, I — фактический служебный комментарий. URL строки должен соответствовать entry; существующую дату сохранять, G «Принята» не менять.
6. Сообщить название страны, GitHub Pages URL без UTM, commit и фактический результат. Сохранить курсор следующей записи.

Результат привязан к commit задачи или его потомку с неизмененным целевым файлом. Несвязанный новый HEAD не запускает повторение. При сбое исправить конкретную причину или продолжить сохраненную стадию.

Чат не выполняет визуальную приемку, desktop/mobile, скриншоты, оценку фото или проверку страниц и не делегирует их Work. В отчете нет заявлений о такой приемке и оговорок о ее отсутствии. Замечания пользователя к результату становятся отдельной точечной задачей.

## Представление страны в интересах и общая форма

В `CountryLayout` тематические связи вычисляются по активным турам; списки `relatedThemes` вручную не добавлять. Внутри страницы интереса страна показана полноширинным `DestinationBand`, с актуальным тематическим счетчиком и ссылкой на `/interests/<interest>/tours/<country>/`. Для видимого блока Theme фоновые туры распределяются между максимум 7 странами снизу вверх по текущему страновому рейтингу: каждая страна получает первый еще не использованный `Tour.hero` из своего тематического списка. Один Tour не повторяется; при исчерпании уникальных туров используется `Country.hero`. Число и обложка обновляются при следующей сборке после публикации/архивирования/изменения тура. Сторону текста определяет `Country.imageTextAlign`.

У страницы страны и всех ее полных каталогов одна форма перед подвалом, которую добавляет `BaseLayout`. Дочерняя страница задает только `leadTitle` и `leadEntityId`, без повторного `<LeadForm>`. См. `interests.md` и `forms.md`.
