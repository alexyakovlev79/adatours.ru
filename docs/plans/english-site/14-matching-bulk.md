# Ada Tours EN: рабочая инструкция массового сопоставления Word ↔ Tour

Дата: 2026-10-29. Репозиторий: \`alexyakovlev79/adatours.ru\`.
Код координатора: \`feat/english-site-foundation\`.
Очередь: \`i18n/matching-staging\`.
Только сопоставление, **не массовый перевод**.

## Условие запуска

Из \`data/i18n/matching/v1/index.json\` рабочей ветки получить:
\`matchingEnabled=true\`, \`pilotOnly=false\`, \`translationEnabled=false\`.
При отсутствии этих фактов **не захватывать** задания. Не менять
\`index.json\` или сегменты состояния вручную.

Координатор разрешает до **четырёх параллельных Work-чатов** на
первую волну, затем до 6–8 после проверки ограничений GitHub API.
**Не более 6 уникальных Tour на один чат**: ограничение
enforced by \`matching-remote.mjs\` and persisted under ownerAssignments.
\`worker_quota_reached\` означает нормальное завершение чата.
Если все остальные jobs сейчас чужие leased, сообщить \`busy\`,
не выдавать это за ноль оставшихся заданий.

## Команда, которую пользователь вставляет в КАЖДЫЙ новый Work-чат

> Рой ADA: массовое сопоставление EN. Репозиторий
> \`alexyakovlev79/adatours.ru\`. Прочитай действующие
> \`docs/workflows/english-site.md\` и
> \`docs/plans/english-site/14-matching-bulk.md\` из ветки
> \`feat/english-site-foundation\`. Работай только по CAS-диспетчеру
> \`i18n/matching-staging\`: сначала status, затем claim. На каждый
> назначенный Tour найди соответствующий полный английский Word,
> сначала в 2027, затем в 2026, если 2027 не подошёл.
> Проверь маршрут, дни, длительность, страны и существенные услуги,
> а не только совпадение имени. Сохрани файл/редакцию/SHA-256
> и точные ссылки на дни и тарифные строки DOCX. Для
> уверенного Word 2027 зафиксируй новые цены как
> \`priceAmendments\` для общей RU/EN записи без ручного review
> расхождений. Если ни один Word не подошёл, обоснуй
> отрицательное решение по обоим годам и альтернативным
> материалам. Через complete сохрани immutable результат.
> После подтверждения сразу бери следующий, максимум шесть
> разных туров за чат. Соблюдай lease и resume; не дублируй
> обработку, не переводи контент и не меняй \`main\`.

## Рабочий технический цикл

1. Один раз в чате загрузи **обе** версии
   \`scripts/i18n/matching-core.mjs\` и
   \`scripts/i18n/matching-remote.mjs\` из одного актуального
   SHA ветки \`feat/english-site-foundation\`. Используй
   утверждённый Code Mode пример из
   \`docs/plans/english-site/12-matching-pilot.md\`, меняя
   только содержательную задачу, не ветку CAS.
2. \`ownerId\` и \`token\` создаются один раз на чат; при
   повторном вызове сохраняются без переименования.
   Если инструмент вернул неопределённый результат,
   прежде всего прочитай status/checkpoint и повтори
   тот же claim/submit idempotently.
3. \`claim\` выдаёт один job и его immutable descriptor,
   в том числе список \`candidates.2027\` и
   \`candidates.2026\`. Это **предложения**, не
   разрешения копировать текст. Используй
   \`data/i18n/programme-sources.json\` для
   поиска иных/дублирующихся кандидатов.
4. До решения \`not_found_both\` проверь обе
   папки по стране, длительности, имени и характерным
   объектам, включая допустимые отложенные документы.
   Не приписывай соответствие из одного filename score.
5. Для Word получить полный DOCX: обычный textual
   Google Drive preview может пропустить вложенные
   таблицы цен. Запиши реальную версию/modifiedTime,
   SHA-256 исходных байтов, XML locators дней,
   \`sourceYearFolder\`, документ и результаты проверки.
6. \`selected_2027\` может включать точные
   \`priceAmendments\` для всех строк тарифов, с
   \`amount\`, \`currency\`, \`priceBasis\`,
   \`sourceLocator\`, SGL/DBL/TPL, типом размещения,
   сезонными условиями. Не редактируй RU Tour MD
   непосредственно. \`selected_2026\` не переносит
   старые цены 2026 в текущие коммерческие поля.
7. \`not_found_both\` требует
   \`checkedYears:[2027,2026]\` и
   \`quarantinedCandidatesChecked:true\` с
   конкретными доказательствами; пустые кандидаты
   в manifest этого **не доказывают**.
8. \`complete\` подтверждается только \`saved\` или
   \`already_saved\`. После каждого подтверждения
   можно взять следующий job до лимита. При ошибке
   source fingerprint — \`stale_source\`; при
   временном сбое — \`retryable\`; при отсутствии
   доступа — \`blocked_external\` с конкретной
   причиной. Не выдавай такие статусы за готовый тур.
9. На \`worker_quota_reached\`, \`empty_or_busy\`,
   исчерпании доступных заданий или завершении
   шестого job остановись, покажи фактический
   статус и сдавай управление. Никаких повторных
   действий «чтобы чем-то заняться».

Важный факт: \`ready\` относится только к
сопоставлению, но ещё не к переводу. Переводчики
получат отдельную очередь с stable block maps после
завершения matching.
