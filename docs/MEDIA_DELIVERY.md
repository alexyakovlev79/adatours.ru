Актуально с 09.10.2026. Страницы остаются на GitHub Pages. Хранилище фотографий и будущих коротких фоновых видео — Yandex Object Storage, публичный домен https://img.adatours.ru/media/.

## Публикация фотографий

1. В Tour/Country/Destination/Excursion MD, исходных материалах и реестрах сохраняются логические пути вида `/media/...`, stable ID и история происхождения файлов.
2. Для каждого push в main GitHub Actions перед сборкой сайта вызывает инкрементальную синхронизацию в S3 через OIDC-федерацию. Точка отсчета: успешно скопированные и проверенные 2981 медиафайл из commit `f542614802123ef6342c10683faf475ed1a7ba83`. Ручной workflow допускает полный повторный аудит.
3. Существующую S3-копию с другими байтами перезаписывать нельзя: требуется новое уникальное версионированное имя файла. Запись нового файла проверяется по SHA-256 через публичный HTTPS.
4. В production-сборке проверяются контент, каталог и JSON-LD, затем `scripts/prepare-pages-media.mjs` заменяет URL в готовом HTML, CSS, JS, Open Graph и структурированных данных. Pagefind строит индекс уже с внешними адресами. Из пакета GitHub Pages исключается только `dist/media`; из исходного GitHub `public/media` ничего не удаляется.
5. Если выгрузка в S3 или сборка не прошла, деплой не должен выполняться. Предыдущая успешная версия сайта остается доступна.
6. Это промежуточная совместимая схема. Она пока оставляет бинарные файлы в истории Git. Отдельно предстоит безопасный прямой путь GPT Image / Work → S3 с ограниченными полномочиями и автоматическим подтверждением доступности. До демонстрации этого пути не удалять оригиналы и историю Git.

## Видеофоны для избранных стран и туров

По запросу Анны отдельные страницы Country и Tour смогут использовать короткий зацикленный видеофон hero. Текущий перенос сам по себе **не включает видео**; для него требуется адресное расширение схемы и компонента Hero.

- Основной `hero.src` с качественным WebP **остается обязательным**: это первый кадр, fallback для мобильных, медленных соединений, `prefers-reduced-motion`, `Save-Data` и ошибок видео, а также изображение для Open Graph и SEO.
- Будущий независимый необязательный блок `heroVideo` с путями к видео и постеру не меняет существующую фотографию и остальные свойства hero.
- Рекомендуемый первый формат: MP4/H.264 с faststart, без звуковой дорожки, примерно 5–12 секунд, 24 кадра/с, 1280×720, ориентир 2–6 МБ. Допустима отдельная WebM-версия. Не загружать исходные гигабайтные видео на страницу.
- Для воспроизведения: `muted`, `autoplay`, `loop`, `playsinline`. Видео загружается только после показа постера, не конкурирует с LCP; на мобильных и при снижении движения по умолчанию остается фотография. Никаких сдвигов верстки или блокировки CTA.
- Сохранять уникальные версии файлов и корректные MIME `video/mp4` / `video/webm`, поддерживать запросы Range. URL имеют ту же структуру `/media/...` и работают на будущих языковых версиях без дублирования видео.
- Перед публикацией каждой видеостраницы проверить PageSpeed Mobile, LCP/CLS, доступность текста и работу в Safari iOS, Chrome Android и на десктопе.

Ключи S3 и постоянные учетные данные в чат, Markdown и публичный репозиторий не передавать.
