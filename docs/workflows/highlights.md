# Ada Tours — изображения «Главных впечатлений»

Адреса объектов задаются `docs/workflows/urls.md`; использовать текущий URL из entry. Смена публичного slug не переименовывает существующие content-файлы, медиа и их реестровые ID.

Версия: 2.2

Дата: 05.10.2026

Канонический документ: `docs/workflows/highlights.md`

Репозиторий: `alexyakovlev79/adatours.ru`, ветка `main`.

## 1. Отдельная задача

Применять только по явному запросу добавить или сгенерировать картинки для указанных впечатлений конкретного тура. Обычное создание тура, экскурсии, места или страны этот workflow не запускает. Отсутствие изображений впечатлений не блокирует создание страницы: общий компонент поддерживает текстовый режим.

Здесь GPT Image создает новую фотографическую иллюстрацию по готовому тексту. Улучшение существующей фотографии выполняется отдельно по `docs/workflows/photo-enhancement.md`. Не искать фото-референсы и не скачивать изображения с Brasiltours, Drive, из поисковой выдачи или старых реестров ради генерации впечатлений.

Перенос текста сущности на фотографии влево/вправо выполняется полем `imageTextAlign` по `docs/workflows/master.md`, раздел 8.4, и не запускает генерацию highlights. При работе с картинками сохранять существующее значение владельца; без поля остается действующее расположение шаблона. Обычные тексты над или под иллюстрацией эта настройка не перемещает.

В workflow нет визуальной приемки генерации или страницы, проверки desktop/mobile, скриншотов, сравнения вариантов и повторов «пока не станет красиво». Требования к содержанию и композиции передаются в промпте. Отдельное конкретное исправление выполняется по замечанию пользователя.

## 2. Входные данные и границы

Определить точный production-путь тура по `data/source-index/index.json` и записи `data/source-index/entries/<id>.json`. Сохранить его `id`, `slug` и опубликованные тексты. Текущий Tour MD прочитать один раз.

Для каждого указанного впечатления использовать:

- его `title` и полный `text`;
- относящиеся к нему дни маршрута и географию;
- содержание canonical Excursion, только если релевантный `excursionRef` раскрывает смысл этого впечатления.

Связанные экскурсии открываются по известным ID, без поиска. Их тексты используются как контекст; не копировать их обратно в Tour MD, не менять `Excursion.hero`, body, lead или связи. Не обходить все экскурсии тура, если они не нужны для выбранных впечатлений.

Не читать заново весь проект, исходный сайт, все snapshots или все фото. Если необходимого факта нет в закрепленном тексте, не добавлять его в сюжет и не восполнять интернет-поиском. `/image/cache/` и альтернативные URL не используются.

Посчитать только указанные пользователем элементы. Существующие `image` сохранить; новые нужны только для отсутствующих либо явно заказанных замен. Для команды «ко всем впечатлениям» обработать недостающие изображения этого блока. Частный запрос об одном впечатлении не расширять до всего тура.

## 3. Один сюжет и один промпт на впечатление

Одна картинка передает один узнаваемый сюжет соответствующего впечатления. Не склеивать несколько разных мест в панораму и не заменять смысл случайным красивым пейзажем страны. Если впечатление объединяет несколько событий, выбрать одну репрезентативную сцену, а не коллаж.

Включать только подтвержденные текстом элементы: место, главный объект, ландшафт, реальное действие или животное. Свет и погода допустимы как нейтральный художественный выбор, если не противоречат фактам. Не выдумывать новый туристический продукт, событие, маршрут или достопримечательность ради картинки.

Смысловая часть промпта индивидуальна для каждого изображения. Сохраняется общий хвост:

> Photorealistic premium editorial travel photography, natural realistic lighting and colors, believable geography and scale, detailed but not oversharpened, immersive travel atmosphere. Wide horizontal 16:9 composition designed for a website editorial block. One coherent photographic scene, no collage, no split screen. No text, no captions, no logos, no watermark, no border, no frame, no artificial blank areas. Avoid CGI, illustration, surrealism and impossible geography.

Композицию сразу задавать под 16:9, с главным объектом внутри полезной области кадра. Не использовать одну новую картинку для двух разных впечатлений и не брать изображение другого тура только из-за совпадающего города.

## 4. Генерация и техническая подготовка

Для каждой отсутствующей или явно заменяемой картинки — один вызов GPT Image. Полученный результат сохранить без самостоятельной приемки и альтернативных вариантов. При технической ошибке инструмента, когда результат не создан, допустим один повтор того же вызова. После повторной ошибки отметить конкретный элемент как невыполненный; не запускать другие способы генерации или поиск замен.

Сохранять уже полученные результаты и их связь с `tour ID + индекс highlight + промпт`. При возобновлении задачи использовать готовые файлы, не генерировать их заново. Общий пакет может содержать все запрошенные элементы одного блока; не подключать изображения по одному отдельными commit.

Production-формат:

```text
1536 × 864 px
16:9
WebP
ориентир по весу: 150–300 КБ; мягкий предел около 400 КБ
```

Нормализовать размер стандартным преобразованием в этот формат без искусственных полей. Подготовка выполняется технически, без отдельной оценки композиции и перегенераций из-за результата кадрирования. Сделать обычную WebP-оптимизацию; не устраивать цикл уменьшения веса ради жесткого попадания в цифру. Более тяжелый файл допустим, если стандартная обработка дала такой результат.

Файлы WebP сохранить во временном каталоге **вне Git**, затем загрузить через `docs/workflows/direct-s3-upload.md` под логическими ключами:

```text
media/tours/<tour-file-stem>/highlights/
01-short-descriptive-slug-enhanced-YYYYMMDD.webp
02-short-descriptive-slug-enhanced-YYYYMMDD.webp
```

Номер соответствует порядку `highlights`. Для явной замены использовать следующую версию файла, не перезаписывать прежний asset. Не употреблять `final`, `new`, `copy`, `(1)`.

## 5. Данные и существующий компонент

В указанные элементы добавить только `image.src` и короткий русский `image.alt`:

```yaml
highlights:
  - title: "Существующее название"
    text: "Существующий утвержденный текст без сокращения"
    image:
      src: /media/tours/<tour-file-stem>/highlights/01-scene-enhanced-YYYYMMDD.webp
      alt: "Краткий сюжет из промпта с названием места"
```

`alt` формируется по подтвержденному сюжету промпта; он не является отдельной процедурой просмотра результата. Не превращать его в набор ключевых слов и не повторять весь заголовок. Не приписывать сгенерированному изображению реального фотографа, событие съемки или документальное происхождение. Существующие атрибуции других изображений сохранить.

Используется `src/components/tour/HighlightsEditorial.astro`; текущая схема `src/content.config.ts` уже поддерживает `highlights[].image`. Не менять эти файлы и не делать локальный компонент или CSS ради обычного добавления данных.

Предусмотренное поведение компонента сохраняется: фотография остается в блоке, текст раскрывается по `+`. Когда `image` заполнено у всех элементов, включается режим с изображениями; при неполном наборе остается текстовый режим. Это определяется данными, без проверки в браузере. Если пользователь заказал только часть картинок или отдельная генерация технически не получилась, не генерировать незаказанные элементы ради переключения режима; сообщить фактическое состояние.

Hero тура, фотографии дней, itinerary, цены, включенные услуги, FAQ, ID, slug, другие страницы и связанные сущности остаются вне этой задачи.

## 6. Канонический реестр и один пакет

Все новые GPT Image assets записать в `src/data/media/photo-enhancements.json` тем же commit. Существующий контракт — объект с `version`, `description` и массивом `enhancements`; структуру и чужие записи сохранить. Для новой генерации допустимо совпадение `source` и `enhanced`:

```json
{
  "source": "/media/tours/<tour-file-stem>/highlights/01-scene-enhanced-YYYYMMDD.webp",
  "enhanced": "/media/tours/<tour-file-stem>/highlights/01-scene-enhanced-YYYYMMDD.webp",
  "enhancedAt": "YYYY-MM-DD",
  "method": "gpt-image",
  "revision": 1
}
```

Это отметка происхождения генерации и защита от последующего автоматического улучшения. Для явно заказанной новой версии зарегистрированного изображения сохранить исходный `source`, обновить `enhanced` и `enhancedAt`, увеличить `revision`. Не дублировать запись для уже подготовленного файла.

До публикации загрузить успешные WebP напрямую в S3, сверить SHA-256, сформировать текстовые receipts в `src/data/media/direct-s3-uploads.json`, затем собрать изменения Tour MD, реестра и целевых строк таблицы. Не размещать новые WebP в Git. Один раз технически проверить файлы, `1536×864`, корректность MD/JSON, соответствие путей и полноту реестра для новых assets. Не запускать приемку внешнего вида.

Фиксация: один пакет **текстовых MD/JSON/S3 receipts без бинарных файлов** → один commit → одно обновление `main` → одно целевое пакетное отражение в листе «Фото». Новый репозиторий не создавать. При запросе только подготовить изменения внешних записей нет.

Таблица и точные существующие колонки описаны в §8 `docs/workflows/photo-enhancement.md`: spreadsheet `1ZPptMdEcIDA3ZFMOQcFuc5jU88LJlFw9R4URCQSBmmc`, лист `Фото`, sheet ID `1174354857`. Использовать ключ конкретного тура и слота highlight. В `Источник фото` указать `GPT Image`; реального автора не выдумывать. Для выполненного подключения используется существующий технический статус `REPLACED`. Колонку «Дата проверки» не заполнять. Старые поручения о визуальном QA не выполнять. Никаких новых колонок или дополнительного GitHub commit для таблицы.

Если таблица недоступна после commit, сохранить только невыполненное отражение; при продолжении повторить его, без генераций и повторной публикации тех же изображений. Если часть генераций закончилась технической ошибкой, перечислить конкретные незавершенные элементы; их не считать готовыми.

## 7. Завершение

Публичную страницу, desktop/mobile, работу `+` и компоновку не проверять. Штатную автоматическую сборку и публикацию не превращать в отдельный цикл ожидания и повторной приемки.

Сообщить число добавленных изображений, выполненные явные замены, оставшиеся технические блокеры и статус фиксации. Дать ссылку на тур без UTM. Если изображений пока недостаточно для режима с фотографиями, прямо сообщить об этом, не называя блок полностью готовым.

## Отличие от фоновых изображений интересов

Иллюстрации 13 Theme не являются `Tour.highlights`. Их отдельная генерация выполняется только по прямому заданию для соответствующего интереса; готовые результаты после прерывания используются повторно. Ключ S3 — `media/themes/<interest-slug>/hero-enhanced-YYYYMMDD.webp`, в MD — `/media/...`; происхождение GPT Image обязательно отражается в `photo-enhancements.json`. Правила технического WebP и отсутствия выдуманного фотографа сохраняются.

Фоны стран внутри страницы интереса вообще не генерируются отдельно: это текущие `Tour.hero` динамических TOP-1 по `interests.md`. Обычная генерация highlights не меняет метки, сортировку, счетчики и формы сайта.
