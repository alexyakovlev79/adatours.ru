# Закреплённые источники Ada Tours

Индекс подготовлен 2 октября 2026 года для 722 сущностей из вкладки «Страницы»: 24 стран, 216 мест, 342 туров и 140 экскурсий. Он хранит точные идентификаторы, будущие URL, адреса файлов Google Drive и исходных фотографий.

## Обычное добавление известной сущности

1. Возьми её `id` из колонки H вкладки «Страницы».
2. Прочитай один файл `data/source-index/entries/<id>.json`.
3. Открой непосредственно `text.selected.url`; возьми исходные фотографии из `media.images`.
4. Создай Markdown по точному `contentPath`, используя закреплённые URL и идентификаторы.

Поиск источников, листание Drive-папок, просмотр всех альтернатив, обход brasiltours.ru и скачивание фотографий в этот поток не входят. Наличие очищенного или исходного снимка вместо V2 не запускает отдельный повторный рерайт. Перенеси относящийся к сущности текст в предусмотренные поля шаблона, сохранив факты и условия.

Публикация известного Markdown **не требует менять индекс или его каталоги**, если его константы уже закреплены. Исключение — первый разбор программы тура: если уточняются страны маршрута, места или итоговый URL, эти поля одной записи и компактные каталоги обновляются в том же commit. Текущее существование страницы определяется по точному `contentPath`; изменяющийся статус публикации в индекс не дублируется. Текущие улучшенные фотографии в production Markdown и реестре `src/data/media/photo-enhancements.json` сохраняются.

Колонки J–L вкладки «Страницы» служат видимым зеркалом указателей: J — запись сущности в GitHub, K — выбранный текст Drive, L — исходный hero URL. Источник самих констант — JSON-запись в репозитории. Пустой L у уже улучшенного изображения без подтверждённого donor URL не является заданием искать замену.

## Файлы и поля

| Путь или поле | Назначение |
|---|---|
| `index.json` | Метаданные и компактные записи всех известных сущностей |
| `catalogs/countries.json` | Идентификаторы и имена стран |
| `catalogs/destinations.json` | Места с подготовленной записью источников; исходный набор — 216 мест |
| `src/data/catalog/destinations.json` | Единственный каталог идентичности всех мест: исходных, новых резервов и уже заполненных |
| `src/data/catalog/destination-reservations.json` | Очередь подготовки новых мест: ID, происхождение, материалы и состояние; название, страну и URL не дублирует |
| `catalogs/tours.json` | Идентификаторы и источники туров |
| `catalogs/excursions.json` | Экскурсии, включая выделенные из туров; имена и закреплённые aliases помогают найти каноническую сущность |
| `entries/<id>.json` | Полные константы и источники одной сущности |
| `reserved-destinations.json` | Постоянный указатель на каталог идентичности и очередь; не вторая копия мест |
| `entry.schema.json` | Формат отдельной записи |
| `id`, `type`, `name`, `url`, `slug` | Канонические значения из реестра и существующего проекта |
| `contentPath` | Точное имя существующего Markdown либо заранее закреплённый путь будущего |
| `sourceUrl` | Точный URL старой страницы или `null` для сущности без такой страницы; URL донора не выдумывается |
| `countryIds`, `destinationIds` | Закреплённая география; у ещё не созданных туров список мест определяется при создании тура |
| `relatedDestinationIds` | Дополнительные подтверждённые места экскурсии; соответствуют `Excursion.relatedDestinations` и не меняют основное место её URL |
| `routeCountryIds` | Необязательные страны основной программы тура, подмножество `countryIds`; определяют URL, крошки, страницы стран и подсчет туров. Соответствуют `routeCountries` в Markdown |
| `routeDestinationIds` | Необязательные основные места маршрута, подмножество `destinationIds`; места только факультативных экскурсий остаются вне этого списка. Соответствуют `routeDestinations` в Markdown |
| `legacyUrls` | Прежние адреса этой сущности для сохранения опубликованных ссылок |
| `destinations` | Имена, URL и страны указанных мест; не ручной список обратных связей |
| `destinationType` | Тип места по закреплённому каталогу |
| `destinationName` | Имя связанного места экскурсии; `null`, если точное место не заявлено |
| `aliases` | Уже известные альтернативные названия; новые синонимы не выдумываются |
| `text.selected` | Единственный выбранный текст: точный файл Drive либо сохранённые предоставленные материалы |
| `text.original` | Точный исходный снимок для целевого уточнения фактов при необходимости |
| `text.verification` | Проверка личности файла; `textBodyReviewed=false` не выдаёт метаданные за редакторскую приёмку |
| `text.sourceScope`, `text.provenance` | Границы фрагмента и происхождение сущности из тура |
| `media.images` | Подтверждённые raw URL brasiltours.ru или предоставленные пользователем оригиналы с ролью, порядком и alt; производные cache-пути исключены |
| `media.current` | Уже назначенные изображения у сущностей из фрагментов; могут содержать локальные улучшенные файлы |
| `media.status` | `ready`, `existing_enhanced_preserved` либо `provided_originals` |
| `readiness` | Наличие источников и границы оставшейся штатной работы, а не дополнительные проверки |
| `sheet` | Точная таблица, вкладка и строка очереди |

Идентификаторы исходных Drive-папок закреплены в `index.json` → `metadata.folders`. Папка `page_texts_newstep` содержит очищенные туры; её дочерняя `Excursions` — очищенные самостоятельные экскурсии. Настоящий исходный снимок расположен в `page_texts_original`. V1 и непомеченный отдельной версией `page_texts_rewrite_excursions` не выдаются за V2.

## География и автоматические связи

Для каждого известного места страна и будущий URL уже определены. Для 140 экскурсий география закреплена: у 138 указано конкретное место, у двух точного места нет. `readiness.geography=no_destination_asserted` означает намеренно пустой `destinationIds`, а не просьбу подобрать место. Так отмечены кофейные фазенды штата Рио-де-Жанейро и Пеулья с водопадами Петроуэ.

У ещё не созданного тура `readiness.geography=resolve_when_creating_tour`. Его `countryIds` могут содержать только известную основную страну из снимка. При создании тура нужно прочитать его программу, определить полный список стран и выбрать все подтверждённые места из каталога. Если страна присутствует только в факультативной поездке, полный список связей сохраняется в `countries` / `countryIds`, а страны основной программы закрепляются в `routeCountries` / `routeCountryIds`. Для мест действует тот же принцип: `destinations` / `destinationIds` содержат все подтвержденные места программы, а `routeDestinations` / `routeDestinationIds` — основные места фактического маршрута без факультативных выездов. В остальных случаях отдельные route-поля не нужны. Новое место резервируется через `scripts/reserve-destination.mjs`; самостоятельную страницу без собственного контента создавать не требуется. Самостоятельная экскурсия, отсутствующая в production, создаётся вместе с туром.

Обратные списки туров и экскурсий на страницах мест вычисляются общими шаблонами. Основные туры берутся по `routeDestinations`; туры, где место присутствует только в полном `destinations`, показываются отдельно как маршруты, к которым можно добавить экскурсию в это место. Основное `Excursion.destination` задаёт географию адреса; дополнительные подтверждённые остановки записываются в `relatedDestinations`. Обе стороны связей с опубликованными местами включаются автоматически. Добавляющий место чат не пересматривает все туры и не активирует связи вручную.

Страна экскурсионного продукта и страна места могут отличаться, если это выезд через границу. Например, существующая экскурсия в Монтевидео оформлена как продукт из Аргентины, а `destination_uruguay_montevideo` остаётся местом Уругвая.

## Канонические URL

Первый уровень адреса — страна. Общая формула живёт в `src/lib/routes.ts`; индекс и сайт используют один helper. Slug существующей сущности не меняется при переносе адреса.

| Объект | Адрес |
|---|---|
| Страна | `/<страна>/` |
| Место | `/<страна>/place/<место>/` |
| Тур одной страны | `/<страна>/tour/<тур>/` |
| Мультистрановый тур | `/multi-country/tour/<тур>/` |
| Экскурсия с определённым местом | `/<страна_места>/<место>/<экскурсия>/` |
| Экскурсия без определённого места | `/<страна>/excursion/<экскурсия>/` |

Крошки мультистранового тура показывают страны основной программы на одном уровне, через `·`; каждая страна — отдельная ссылка. Страна URL экскурсии берётся из её места, если оно задано. Старые фактически опубликованные адреса получают статические страницы перехода; новые страницы и внутренние ссылки используют канонические адреса. Источники Drive и URL фотографий при этой миграции не меняются.

## Новое место и предоставленные материалы

Полный короткий порядок — в `docs/workflows/destination-reservations.md`. Резерв сохраняет ID, точное название, страну, slug и будущий URL в каталоге идентичности. В очереди хранится доказательство из конкретного тура/экскурсии либо явная просьба пользователя. До получения собственного описания и хотя бы одной фотографии резерв не имеет Markdown, source-entry и публичной пустой страницы. Тур уже может ссылаться на его ID; общие шаблоны показывают карточку, когда появляется опубликованное место.

Для заполнения резерва или прямой просьбы создать новое место из готовых материалов:

1. Разреши идентичность через тот же каталог и aliases; новое название проходит тот же резервирующий механизм. При неоднозначности новая сущность не записывается.
2. Сохрани предоставленное описание дословно в `data/source-index/materials/<id>.md`. В `text.selected` укажи `kind: provided_materials`, этот `repositoryPath`, имя и `mimeType: text/markdown`. Если пользователь дал точный файл Drive, вместо `repositoryPath` допустимы `driveId`, `url`, `name`, `mimeType`. Загрузка текста обратно на Drive не является обязательным шагом.
3. Укажи `sourceUrl: null`, если старой страницы не было. `text.original` может указывать на тот же предоставленный материал; он не называется исходным снимком brasiltours.ru.
4. Публичный URL оригинала можно использовать напрямую. Уже загруженный файл фотографии сохрани без изменения байтов в `public/media/destinations/<id>/original-01.<ext>` и используй `/media/...`. Точный приватный файл Drive при необходимости извлекается один раз для сохранения оригинала; ссылка просмотра Drive не является `src` изображения. Поиск, генерация и улучшение фотографий в создание места не входят.
5. Добавь запись источников с `media.status: provided_originals`, `media.provenance.kind: user_provided`, фотографией с ролью `hero` и соответствующим `readiness.media`. Создай Destination под прежними ID/slug/страной. В этой же задаче переведи запись очереди в `added`, синхронизируй компактный каталог и отрази добавление в таблице.

Текст экскурсии и её единственное фото сами по себе не заменяют независимый контент места. Улучшение предоставленных оригиналов выполняется позднее штатным Work-проходом; сохранённые локальные оригиналы повторно не скачиваются.

## Фрагменты туров и уже улучшенные фотографии

У 27 экскурсий, выделенных из туров, нет отдельной старой страницы. Их `text.selected.kind=tour_excerpt` сохраняет точный `parentTourId`, файл тура и происхождение выделенного текста. Перейра также использует определённый фрагмент `kolumbiya-c-kofe`; её `text.sourceScope=destination_excerpt` не позволяет принять всю программу тура за текст места.

У десяти уже существующих экскурсий из туров исходный donor URL улучшенного изображения не восстановим из имеющихся точных записей. Для них сохранены `media.current`, `media.status=existing_enhanced_preserved` и provenance. **Пустой `media.images` в этих записях не означает необходимость скачать, искать, генерировать или заменить изображение.** Используется существующий успешный локальный результат. Индекс не откатывает улучшенные изображения к оригиналам.

## `newEntryMaintenance`: новая экскурсия из тура

Этот шаг нужен только для новой сущности, которой ещё нет в `entries`, или при явном исправлении её констант. Благодаря записи следующему чату известна каноническая экскурсия, и он не создаёт дубль.

1. Создай новую Excursion Markdown и новую запись `entries/<newExcursionId>.json` в рамках той же задачи тура.
2. Перенеси в запись фактические `id`, название, slug, `contentPath`, страну, место и назначенное изображение новой Excursion. Если отдельной старой страницы нет, укажи `sourceUrl=null` только в JSON индекса; необязательный `sourceUrl` в production Markdown просто опусти.
3. Для `text.selected` используй точный файл уже известного родительского тура, добавив `kind=tour_excerpt`, `containerKind` исходного файла и `parentTourId`. `text.original` возьми из записи тура. Сохрани, какой блок тура стал экскурсией, в `text.provenance`. Нового поиска источников здесь нет.
4. Синхронизируй каталоги одним из двух способов ниже и включи все изменения вместе с туром и новой экскурсией в один содержательный commit.

Если доступна файловая среда, выполни:

```bash
node scripts/sync-source-catalogs.mjs
```

Скрипт читает только уже подготовленные `entries/*.json`, использует стандартные средства Node и JSON, обновляет `index.json` и четыре компактных каталога. Сеть, Drive, исходные страницы, изображения, Astro build и публикация не вызываются. Неизменившиеся каталоги не дают изменений Git.

Если чат работает только через GitHub API, подготовь точные изменения **трёх JSON-файлов**:

| Файл | Изменение для одной новой экскурсии |
|---|---|
| `entries/<newExcursionId>.json` | Добавить полную запись |
| `index.json` | Добавить одну компактную запись в `entries`; увеличить `metadata.entityCount`, `metadata.counts.types.excursion` и соответствующий счётчик `metadata.counts.media` |
| `catalogs/excursions.json` | Добавить ту же компактную запись в `entries` |

Компактная запись содержит `id`, `type`, `name`, `url`, `slug`, `contentPath`, `countryIds`, `destinationIds`, `sourceUrl`, `entryPath`; `aliases`, `routeCountryIds`, `routeDestinationIds`, `relatedDestinationIds`, `legacyUrls` добавляются только при непустом списке. Для новой сущности без отдельной старой страницы `sourceUrl=null`, поэтому счётчик различных донорских URL не меняется. Порядок — номер строки очереди, затем ID. У новой записи без ещё назначенной строки допустим `sheet.row=null`; такая запись помещается в конец. Для места аналогично обновляется `catalogs/destinations.json` вместо каталога экскурсий. Все изменения проходят одной публикацией задачи, без отдельного служебного commit для каталога.

При смене названия или aliases существующей экскурсии обновляются её entry и те же две компактные записи. Общее чтение всех Markdown и повторная инвентаризация источников не требуются.

## Административная сборка исходного набора

`scripts/build-source-index.py --inputs <папка_подготовленных_JSON>` воспроизводит первоначальную сборку из `text-sources-by-id.json`, `raw-media-by-source.json`, `excursion-geography.json`, каталога мест и текущих frontmatter. Это отдельная административная операция; скрипт не включён в сборку сайта и не выполняется при поштучном добавлении страниц.

Крупные исходные CSV, JSONL-снимок сайта и содержимое текстов Drive в репозиторий не копируются. Обычный `npm run build` не обращается к источникам и не скачивает медиа.
