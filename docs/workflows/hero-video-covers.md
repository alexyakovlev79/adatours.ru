# Видеообложки: один вариант на устройство

Решение Алексея, 21.10.2026: перед видео показывать первый кадр именно выбранного ролика. Не загружать отдельную редакционную фотографию, которую затем закроет другой сюжет видео. Допустим пустой фон, если кадр ещё не подготовлен. Эксперимент P03.

## Общий контракт

`Hero` принимает `video: { src?, mobileSrc?, poster?, mobilePoster? }`. Варианты независимы: `src` для компьютеров/планшетов, `mobileSrc` для телефонов. Любой из них может отсутствовать. Определение телефона — существующий `src/lib/phone-device.mjs`, не ширина окна. Устройства без своего ролика получают обычное адаптивное фото. Нет автоматического переключения на чужой ролик.

`poster`/`mobilePoster` — исключительно первый декодированный кадр соответствующего видео. Если явные поля отсутствуют, компонент ищет точное соответствие `src` в `src/data/media/hero-video-posters.json`. Реестр привязан к версионированному видеофайлу, а не к URL страницы, стране или месту показа; один ролик/постер переиспользуется. При замене ролика меняется его ключ и извлекается новый кадр. SHA-256 исходного видео и кадра сохраняется в реестре, S3 receipt — в общем ledger.

`HeroVideo.astro` — переиспользуемая декоративная видеообложка. Фото (`<picture>` или CSS-поверхность) передаётся в default slot. Родитель задаёт позиционированную изолированную поверхность с `data-video-surface` и размеры; компонент не зависит от маршрута страницы и наблюдает эту поверхность. Интегрирован с Hero и явно включённой широкой карточкой Бразилии на главной (решение Алексея, 22.10.2026, P04). Это не включает видео во всех упоминаниях страны автоматически. Обычные видеоплееры внутри текста этим контрактом не управляются.

Для будущих MD-страниц, у которых пока нет видео, отдельно добавить/расширить `heroVideo` в нужной content schema и передать его в Hero. Наличие ролика в медиареестре само по себе не включает воспроизведение. В широкой карточке Бразилии передаётся только desktop src: телефоны сохраняют фото, даже если позднее у Country появится mobileSrc.

## Загрузка и отказ

Оригинальное `<picture>` хранится в `<template>` и `<noscript>`. До выбора режима нет активного `src/srcset` фотографии: preload scanner её не запрашивает. В фото-режиме клонируется только исходное picture, включая мобильные crops и приоритет загрузки. В видео-режиме активируется только выбранный первый кадр, затем при видимой поверхности — выбранный ролик. Вторая пара остаётся data-атрибутами, исходное фото — в инертном template. Нет одновременного poster-атрибута с другим фото.

Первый кадр и видео имеют одинаковые `object-fit: cover` и `object-position: center`; не применять к кадру фокус редакционной фотографии. До `playing` виден кадр. При блокировке autoplay остаётся кадр и кнопка запуска. При ошибке видео остаётся кадр; если кадра нет, только тогда активируется и реально показывается фото. Без JS обычное фото доступно через noscript. Пауза пользователя, скрытая вкладка и выход поверхности за экран сохраняются. Политика выбора устройств не меняется на reduced motion/Save-Data в этой задаче.

## Карточки и lazy load (P04)

`DestinationBand.video` включает общую видеообложку с `lazy` и `controlsPosition="cover"`. Ссылка покрывает карточку, а кнопка воспроизведения — её сосед, не вложенная кнопка внутри ссылки. Обычные карточки без video сохраняют прежний HTML.

`src/lib/media-loading-window.mjs` использует тот же `isWithinImageWindow`, что изображения сайта: поверхность имеет размеры, пересекается по горизонтали, её верх строго меньше двух высот окна, низ выше минус одной высоты окна. Это текущий экран плюс по одному соседнему. Постер, MP4 и фото-ветка ждут этого окна. При большом окне карточка может попасть в него уже при открытии страницы; высота, прокрутка, восстановление страницы и изменения layout учитываются. На desktop у загружаемого заранее MP4 устанавливается preload=auto, но play разрешён только при фактическом появлении поверхности в viewport. Скрытие вкладки и уход за экран ставят паузу, ручная пауза сохраняется.

Постер и ролик Бразилии переиспользуют существующие S3-объекты и реестр первых кадров. Редакционное фото с мобильным фокусом остаётся инертным template до выбора фото-режима и попадания в окно загрузки. Наличие URL в data-атрибутах не начинает запрос. Верхние hero не получают lazy: их прежний приоритет первого кадра и начало воспроизведения сохраняются.

## Новый первый кадр

Из точного MP4 извлечь первый декодированный видеокадр (без `-ss`, без выбора другого красивого момента), сохранить WebP с исходным соотношением сторон, без увеличения. Пример: `ffmpeg -i video.mp4 -frames:v 1 -vf "scale='min(iw,1280)':-2" -c:v libwebp -quality 82 frame.webp`. Использовать версионированное имя; загрузить напрямую в S3 по `direct-s3-upload.md`, проверить SHA-256, дополнить ledger и реестр. Новые бинарные медиа в Git запрещены.

## Проверки

Выбор телефона/планшета/десктопа, desktop-only/mobile-only, отсутствие кадра; инертность фото до выбора; отсутствие чужого ролика; сохранение фото без JS; autoplay block, error, pause, visibility. После согласованного изменения — три независимых Mobile/Desktop PSI по `performance.md`; изменение веса картинки не выдавать за доказанное улучшение LCP.
