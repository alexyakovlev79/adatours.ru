# Ada Tours — английские URL и постоянные идентификаторы

Версия: 1.2 · 2026-10-03. Общий контракт для всех новых стран, мест, туров, экскурсий, интересов и служебных разделов.

## 1. Как выбирать slug

Публичные адреса используют общепринятые английские названия или устоявшееся собственное имя на языке места, записанное латиницей. `slug` — нижний регистр ASCII, слова разделены одним дефисом, диакритика удалена. Примеры: `brazil`, `brasilia`, `rio-de-janeiro`, `sao-paulo`, `buenos-aires`, `el-chalten`.

Русское название страницы сохраняется в `name` / `title`. Его нельзя автоматически транслитерировать для нового URL. Для названия тура или экскурсии нужен короткий английский перевод, сохраняющий смысл и различия между продуктами; для географического объекта — его принятое название. Нельзя добавлять `-ru`, переводить уже общепринятое собственное имя заново, выдумывать место или соединять разные продукты ради похожего slug. Если принятое написание неизвестно, подтвердить именно его при подготовке записи источников и закрепить результат; обычный импорт использует уже готовую запись.

## 2. Канонические пути

Иерархия начинается со страны, как и прежде. Единственная функция построения адресов объектов — `canonicalPath()` и остальные helpers в `src/lib/routes.ts`.

| Назначение | Путь |
|---|---|
| Общий каталог стран | `/country/` |
| Страна | `/<country-slug>/`, например `/brazil/` |
| Общий каталог мест | `/places/` |
| Места страны | `/<country-slug>/place/` |
| Страница места | `/<country-slug>/place/<destination-slug>/`, например `/brazil/place/rio-de-janeiro/` |
| Основные туры через место | `/<country-slug>/place/<destination-slug>/tour/` |
| Туры с факультативным посещением места | `/<country-slug>/place/<destination-slug>/optional-tours/` |
| Общий каталог туров | `/tours/` |
| Туры одной основной страны | `/<country-slug>/tour/`, `/<country-slug>/tour/<tour-slug>/` |
| Туры нескольких основных стран | `/multi-country/tour/`, `/multi-country/tour/<tour-slug>/` |
| Общий каталог экскурсий | `/excursions/` |
| Экскурсии страны | `/<country-slug>/excursion/` |
| Экскурсии места | `/<country-slug>/<destination-slug>/` |
| Экскурсия с основным местом | `/<country-slug>/<destination-slug>/<excursion-slug>/` |
| Экскурсия без основного места | `/<country-slug>/excursion/<excursion-slug>/` |
| Туры с конкретной экскурсией | `<canonical-excursion-path>tour/` |
| Продолжение любого каталога туров, мест или экскурсий | `<catalog-root>page/<n>/`, только целые `n >= 2` |
| Интересы | `/interests/`, `/interests/<theme-slug>/` |
| Деловые делегации | `/mice/business-delegations/` |
| Для турагентств; условия DMC | `/dmc/travel-agencies/`, `/dmc/terms/` |

Существующие английские разделы `/multi-country/`, `/vip/`, `/mice/`, `/dmc/`, `/about/`, `/contacts/`, `/cases/`, `/reviews/`, `/team/`, `/articles/`, `/privacy/` и `/personal-data/` сохраняются. У экскурсии страна адреса определяется основным `destination`, в том числе зарезервированным; без него используется страна продукта. Дополнительные места не меняют адрес экскурсии.

Каталоги туров места строятся helpers `tourDestinationPath()` и `optionalTourDestinationPath()` под URL страницы места, отдельно от пространства URL экскурсий. Это производные непустые подборки для опубликованных активных мест, а не новые Tour или Destination. Каталог экскурсий места включает полный набор связей `destination` + `relatedDestinations` через `excursionDestinationIds()`, без дублей; его страна берется из записи самого места. Подробнее о составе, сортировке и лимитах обзорной страницы: `docs/workflows/destinations.md`, раздел 4.

Каталог туров экскурсии строит `tourExcursionPath()`; все полные каталоги делятся на страницы по 10 объектов, сохраняя доступ ко всему списку. `catalogPagePath()` из `src/lib/catalog-pagination.ts` возвращает корень для страницы 1 и `page/<n>/` для продолжения. У каждой части собственный абсолютный canonical, у продолжения есть ссылки на первую и соседние части. `/page/1/` и пустые продолжения не создаются. «Показать еще» дополняет обычные ссылки пагинации и не меняет canonical. Полный контракт SEO, кнопки и проверки — `docs/workflows/catalog-pagination.md`; прежняя формулировка «полный каталог без сокращений» означает весь доступный набор, а не бесконечную первую страницу.

## 3. Существующие объекты и миграция

`id` не зависит от публичного URL или языка. **Существующие stable ID и точные `contentPath` не переименовывать**, даже если в них осталась историческая транслитерация. Файл может называться иначе, чем его нынешний публичный slug. Для добавления или редактирования известного объекта брать `slug`, `url` и `contentPath` из текущей exact entry и канонического каталога, не восстанавливать их из заголовка или архивного URL.

Полная карта известных старых и новых адресов хранится в `data/url-migration/2026-10-02.json`, включая запланированные объекты без MD и source entry. Если существующий ID не найден в entry, сначала проверить его в этой карте и текущем каталоге, затем использовать уже закреплённый путь. Например, `theme_coffee` пока не имеет source entry/MD, но его адрес уже определён как `/interests/coffee-tours/`; создавать новый slug для него нельзя.

Ключ записи Astro loader — `locale:stableID` по `src/lib/content-identity.mjs`. Его нельзя восстанавливать из slug: одинаковое имя места, например `la-paz` в разных странах, допустимо при разных stable ID и канонических путях. Ни внутренний storage key, ни content-файл не переименовываются вслед за публичным URL.

По явному глобальному поручению пользователя 02.10.2026 выполняется однократный переход существующих публичных slug на английские. После этой миграции вновь действует обычное правило: использовать закреплённые поля без переименования по инициативе добавляющего чата. Согласованная миграция URL не меняет ID, точный content-файл, `sourceUrl`, ссылки/имена original и V2 на Drive, исходные медиа и пути уже сохранённых фотографий.

Все прежние публичные пути, включая старые общие каталоги, плоские и country-first адреса, остаются redirect aliases навсегда. Сохранять накопленные `legacyUrls` и прежний `url`; не отдавать старый путь другому объекту, не удалять aliases при повторной сборке индекса. Alias ведёт сразу на конечный canonical URL и не входит в sitemap, поиск или обычные внутренние ссылки. Все новые ссылки, canonical, данные схем и адреса реестров используют текущий путь.

При административном пересоздании индекса приоритет identity: текущий content → текущая source entry → текущий канонический каталог. Архивный snapshot может дать старый alias или источник текста; его URL не является основанием вернуть старый slug либо изменить `contentPath`.

## 4. Новый резерв места

Сначала выполнить обычное сопоставление имени, aliases, страны и при необходимости точного `destinationId`. Существующее место переиспользуется без новых `slug` или `englishName` и сохраняет свою identity.

Для действительно нового места JSON-заявка обязана содержать **`slug` либо `englishName`**. `slug` уже записан как английский lowercase ASCII kebab-case; `englishName` содержит принятое имя латиницей и может иметь акценты. `destinationSlug()` нормализует только явно переданное латинское имя, отвергает кириллицу и не использует русское `request.name`. Переданное `englishName` сохраняется как известный alias. Если заданы оба поля, для адреса используется явный `slug`.

Пример: `{countryId: "country_brazil", name: "Сан-Паулу", englishName: "São Paulo", discoveredIn: {...}}` создаёт slug `sao-paulo`. Проверка коллизий, неоднозначностей и уже занятых ID/URL обязательна; случайные числовые суффиксы запрещены. Полная процедура — `docs/workflows/destination-reservations.md`.

## 5. Будущие языки

Сейчас новые языковые версии не создаются. Русская версия работает в корне. Будущие `/en/`, `/de/` (немецкий), `/ka/` (грузинский) используют тот же stable ID и общий английский путь объекта после языкового префикса, например `/en/brazil/place/rio-de-janeiro/`. Язык меняет текст, а не географическую identity или написание сегментов. Префикс `/ge/` для грузинского языка не использовать.

## 6. Реестры

После изменения URL обновлять адреса нового сайта в реестре страниц, фотореестре и очереди материалов: включая ссылки внутри комментариев и колонки «Где встречается». Менять только совпавшие публичные пути; сохранять окружающий текст, статусы, даты, stable ID и точные ссылки на brasiltours.ru, Google Drive и оригинальные медиа. При добавлении известного объекта копировать уже закреплённый английский URL из entry.
