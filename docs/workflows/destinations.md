# Ada Tours — создание места из готового источника

Версия: 2.1 · 2026-10-02 · Репозиторий: `alexyakovlev79/adatours.ru`, ветка `main`.

Эта инструкция применяется к добавлению или точечному обновлению одной известной Destination. Она заменяет `ADA_TOURS_DESTINATION_GITHUB_WORKFLOW_v2_2026-10-02.md`. Общий шаблон и связи уже реализованы; задача чата — заполнить данные выбранного места.

Если готового самостоятельного материала места еще нет, использовать `docs/workflows/destination-reservations.md`: это резерв ID/URL и заявка Анне, без Destination MD. Если пользователь предоставил текст/фото для резерва, сначала закрепить их по разделу заполнения того же workflow; он возвращает сюда готовую entry с `provided_materials` / `provided_originals`. Эти три режима не смешиваются; описание экскурсии не копируется в статью места автоматически.

## 1. Точный вход

Общие правила и завершение задачи: `docs/workflows/master.md`. Индекс источников: `data/source-index/index.json`; выбранная запись `entry`: `data/source-index/entries/<entityId>.json`. `entry` — единственная точка входа для данных создаваемого места. Каталог `src/data/catalog/destinations.json` используется кодом сайта и сборкой; повторно сверять с ним готовую запись не нужно.

Открыть только выбранную `entry` и соответствующую строку реестра. Поля записи: `id`, `type`, `name`, `slug`, `contentPath`, `url`, `sourceUrl`, `countryIds`, `destinationIds`, `destinationType`, `text.selected`, `media.images`, `readiness`. Drive-текст доступен через `text.selected.driveId` / `url`; предоставленный текст при `kind: provided_materials` может лежать в точном `repositoryPath`. `name` и `kind` внутри `selected` определяют источник. Готовые фотографии находятся в `media.images` как `{url, role, order, alt}`. Для продолжения использовать уже выбранную запись и сохраненный прогресс.

Реестр: `1ZPptMdEcIDA3ZFMOQcFuc5jU88LJlFw9R4URCQSBmmc`, лист `Страницы`. Не читать заново весь реестр, весь `main`, папку Drive или историю чатов ради одной записи. Проверить существование только целевого production MD; если он уже создан, продолжить его вместо создания дубля.

Открыть именно `text.selected`, без обязательного поиска второго текста. Для `kind: provided_materials` допустим точный `repositoryPath` материала из сообщения/файла вместо Drive; его не требуется еще раз сохранять на Drive. `page_texts_original` и `page_texts_newstep` — разные источники; не подменять один другим и не использовать адрес папки туров для поиска места. Если точный файл недоступен, зафиксировать конкретный блокер выбранной записи. Искать альтернативные тексты на сайте доноре или в интернете не нужно.

## 2. Что создать

Файл указан в `entry.contentPath`: `src/content/destinations/<slug>.md`.

Действующая схема: `src/content.config.ts`. Использовать ее имена полей в camelCase. Готовые ID, slug и URL `/<country-slug>/place/<destination-slug>/` уже закреплены в `entry`; не создавать новые варианты транслитерации или ID. `/<country-slug>/place/` — каталог мест страны, а `/<country-slug>/<destination-slug>/` — каталог экскурсий этого места; это разные страницы. Прежний `/napravleniya/<country>/<destination>/` остается только redirect alias. Content-файл не переносится в папки URL.

| Поля | Откуда брать |
|---|---|
| `id`, `locale: ru`, `slug`, `countryId` | `entry.id`, `entry.slug`, единственная каноническая страна из `entry.countryIds` |
| `destinationType` | Готовое `entry.destinationType`; подтип уже опубликованного места сохраняется |
| `name`, `summary`, основной Markdown после frontmatter | Указанный готовый русский текст |
| `status` | `approved` для готовой к публикации сущности |
| `searchAliases`, `themes` | Известные значения записи; иначе `[]` |
| `hero: {src, alt}`, `gallery: [{src, alt}]` | Закрепленные фотографии этой сущности |
| `imageTextAlign` | Необязательное `left` или `right`; сохранять существующее значение, назначать по явной команде пользователя |
| `facts: [{value, label}]` | Только уже подтвержденные факты; иначе `[]` |
| `featureBands: [{eyebrow?, title, text, image}]` | Только подготовленные в источнике блоки; иначе `[]` |
| `relatedDestinations`, `featuredTours`, `featuredExcursions` | Для новой сущности `[]`; списки вычисляет шаблон |
| `sourceUrl`, `sourceSnapshot`, `updatedAt` | Непустой `entry.sourceUrl`, точная `text.selected.url` либо `repositoryPath` предоставленного материала, дата изменения |

Допустимые `destinationType`: `city`, `region`, `island`, `national_park`, `resort`, `natural_area`, `route_cluster`. Подтип уже установлен при подготовке `entry`; новая классификация при создании места не нужна. Не подставлять `city` по умолчанию.

У Destination ровно одна страна в `countryId`. Одноименные места по разные стороны государственной границы не объединять. Бразильский Игуасу (`destination_brazil_iguacu`) и аргентинский Пуэрто-Игуасу (`destination_argentina_puerto_iguasu`) — разные сущности со своими ID, страной и URL. Название «Игуасу» само по себе не определяет сторону границы; использовать готовую точную запись.

Основной текст можно целиком сохранить в body. Не требуются новые facts, дополнительные подзаголовки или featureBands ради одинакового заполнения шаблона. Если готовый материал уже содержит такие блоки, перенести их без повторного рерайта.

`imageTextAlign` переносит текст поверх фотографий этого места вместе с CTA/метаданными в собственном hero и в показывающих место баннерах/карточках. Без поля сохраняется действующее расположение шаблона. Фото и обычный текст вне изображения не меняются; отдельная команда переноса требует только целевого MD и штатного commit/CI, без фотопрохода или source-index.

Если `entry.sourceUrl` равен `null`, поле `sourceUrl` в MD опустить: действующая схема допускает отсутствие URL, но не значение `null`.

## 3. Текст и фотографии

Перенести выбранный текст, сохранив конкретные названия, географию, числа и условия. Готовый утвержденный материал не переписывать и не отправлять на повторную редакционную приемку. Структурные поля извлекать из этого же текста. Отсутствующее необязательное поле оставить пустым; если обязательное значение нельзя определить по точной записи и тексту, отметить конкретный пробел источника. Не заполнять его внешними фактами.

При обычном импорте известного материала brasiltours.ru использовать `entry.media.images`: закрепленные raw URL вида `https://brasiltours.ru/image/...` с реальным исходным расширением. `/image/cache/` запрещен во всех режимах. Поле `role` определяет hero и остальные слоты, `order` — порядок, `alt` — готовую подпись изображения. Один URL не дублировать в нескольких слотах без необходимости; общий шаблон уже исключает из видимой gallery hero и изображения featureBands.

Исключение для заполнения нового резерва: `media.status: provided_originals` использует уже предоставленные public image-src либо сохраненные исходные файлы `/media/destinations/<id>/original-...`. Их первоначальное размещение описано в workflow резервов; это не скачивание старой галереи brasiltours.ru. Подготовленные файлы и текст повторно не получать.

При обычном импорте фотографии не скачивать и не локализовать; при заполнении нового места предоставленные файлы размещаются только по описанному исключению. Во всех режимах не улучшать фото, не искать замены, не повторять инвентаризацию или восстановление raw URL. Отсутствующий закрепленный источник или cache URL — конкретный дефект, а не разрешение искать другое изображение. Готовый local original в `provided_originals` является допустимым источником без внешнего donor URL. При обновлении существующего MD сохранять уже улучшенные локальные фотографии.

## 4. Связи активируются по готовому ID

Создающий тур чат заранее записывает в `Tour.destinations` все подтвержденные места программы, включая еще не опубликованные и места факультативных экскурсий. Основные места фактического маршрута отдельно записываются в `Tour.routeDestinations`; если поле отсутствует, основными считаются все `Tour.destinations`. Создающий экскурсию чат также использует будущий ID в `Excursion.destination` / `Excursion.relatedDestinations`. Поэтому при публикации Destination эти связи активируются автоматически на следующей сборке.

Создатель места не читает тексты туров и экскурсий, не ищет упоминания места, не восстанавливает семантические связи и не меняет соседние сущности. Достаточно правильного ID выбранной Destination. Старые пропуски в связях относятся к отдельной задаче исправления данных.

Общий `DestinationLayout.astro` формирует:

- основные туры через место по `Tour.routeDestinations` (fallback: `Tour.destinations`): до 3, по `priority`;
- отдельно туры, где место есть только в полном `Tour.destinations`: это блок «Можно добавить» для факультативной экскурсии в данное место;
- экскурсии по `Excursion.destination` / `Excursion.relatedDestinations`: до 6, по русскому названию;
- «Куда поехать дальше» по общим основным маршрутам: до 10, по числу общих туров, затем по русскому названию.

Текущая сущность исключается, страна и URL каждой рекомендации берутся из ее собственной записи. Если опубликованных связей пока нет, соответствующий блок отсутствует. Ничего подбирать вручную или добавлять для заполнения пустого блока не нужно.

## 5. Один рабочий цикл

1. Открыть целевую запись, точный готовый текст и целевой MD, если он уже есть.
2. Собрать или точечно обновить один Destination MD. Сохранить ранее согласованные ID, URL и уже улучшенные изображения.
3. Отправить все подготовленные изменения одним логическим commit по `docs/workflows/master.md`.
4. Использовать один успешный Actions build этого commit: `npm run build` уже включает offline-проверку схемы, ссылок и запрета cache URL. Дождаться успешного deploy. Отдельную локальную сборку или дополнительную проверку опубликованной страницы не запускать; рекомендации вручную не пересчитывать.
5. После успешного deploy один раз обновить выбранную строку Google Sheets: E — `Добавлена`, F — дата первого добавления, H — stable ID, I — необходимый служебный комментарий; URL в A и source URL в B должны соответствовать записи. G (`Принята`) не менять; существующую дату первого добавления сохранять. При заполнении резерва также перевести его единственную строку отдельной очереди материалов Анны в `Добавлено`, сохранив материалы; второй commit не нужен.
6. Сообщить название, ссылку и результат публикации. На этом проход закончен.

При ошибке машинной проверки исправить конкретную ошибку. При сбое доступа или deploy сохранить целевой ID и стадию; продолжить с нее, не повторяя уже выполненные выбор источника и подготовку текста.
