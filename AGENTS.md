# Ada Tours: рабочий вход

**SEO/GEO v3.1 — быстрый старт «пиши SEO».** До написания статей **один вызов `functions.exec`** по готовому коду `docs/workflows/seo-geo-fast-claim.md`: в нем читается фиксированный SHA `seo-geo/staging`, параллельно выбираются кандидаты из `claims.json` и семи JSON фаз, большая `05-tours.json` разбирается внутри инструмента; сразу создаются единый tree/commit и безопасный CAS-резерв до 3 URL. В ответ выводить только `order`, канонические URL, `previousWork`, SHA и время захвата. **После подтвержденного `reserved` немедленно писать статью 1/3.** Чужие действующие claims (60 минут) неприкосновенны, просроченные `draft` имеют приоритет и используют готовый MD при наличии. При ошибке CAS не начинать писать до подтвержденного SHA; максимум два повтора внутри вызова. Не читать для запуска `main`, Sheets, историю, Actions и все статьи; не выводить гигантский JSON в контекст модели. Другие правила — §8 `docs/workflows/seo-geo-registry.md`.

**SEO/GEO — один commit на готовую статью.** После подготовки утвержденного MD одновременно записать саму статью, `work: prepared` и снять только собственный claim в одном CAS-коммите `seo-geo/staging`. Переход в `prepared` не требует отдельного preflight, двух Git-коммитов, proof-SHA, ожидания Actions или запуска сборки. Ссылки, архив и корректность HTML проверяет единственная штатная сборка мастер-чата при `публикуй SEO`; автор проверяет конкретные ссылки по текущим каноническим данным во время написания. Google Sheets — зеркало, и ее недоступность не задерживает начало/продолжение статей. Чужие активные резервы (60 минут после продления) сохранять, CAS-конфликты обрабатывать максимум двумя адресными повторами, без force push. Только мастер публикует в `main`. Детали: `docs/workflows/seo-geo-registry.md`, раздел 8.

**Дополнение к написанию SEO/GEO-статей:** в новых текстах и явно заказанной редактуре проектировать обычные таблицы под ~300–340 CSS px мобильной ширины (как правило, 2 компактные колонки, не 3 длинных текстовых); подробности выносить за таблицу. Расставлять **контекстные внутренние ссылки прямо при содержательных упоминаниях** опубликованных мест, экскурсий, туров и подходящих каталогов «страна + интерес»; **в перечислениях давать ссылку на каждый доступный объект**. Нет лимита «одна ссылка на URL» или «1–3 ссылки на раздел»: полезные повторные переходы разрешены; избегать только бессмысленных дублей рядом и ссылок на архив, резерв, пустую подборку или себя. Полные критерии и примеры — раздел 12 `docs/workflows/seo-geo-registry.md`. Старые статьи без отдельного заказа не переписывать.

**FAQ в новых SEO/GEO-статьях:** если FAQ нужен, оформлять только `## Частые вопросы…` (H2) → `### Вопрос?` (H3 для каждого вопроса) → обычный абзац(ы) ответа. Не писать `**Вопрос?** Ответ` в одном абзаце и не делать заголовок всего FAQ уровнем H3. Содержательные старые FAQ менять лишь в отдельной заказанной миграции; пока не включать жесткую массовую проверку, которая ломает сборку на старых форматах. Пример и условия — §12.0 `docs/workflows/seo-geo-registry.md`.

**Встроенные фото Word/PDF:** `docs/audits/word-photo-enhancement-queue-20261011.md` и `data/audits/word-photo-enhancement-queue-20261011.json` — сверка 11.10.2026: 76 уникальных Word-фото и отдельно 46 PDF-фото, без подтвержденного GPT Image; 221 действующий слот листа `Фото` помечен `NEEDS_REPLACEMENT`. Для «следующих 10 фото из Word» выбирать `origin: word_embedded` по `documentQueueOrder`; для всей очереди документов — `queueOrder`. Перед каждым пакетом сверять текущий слот/архив/реестр и переиспользовать уже готовый enhancement. WebP-конвертация, S3 receipt и первоначальный статус `REPLACED` не подтверждают улучшение. Архив исключать.

**Главные впечатления туров:** `docs/audits/tour-highlights.md` и `data/audits/tour-highlights-20261011.json` — рабочая очередь иллюстраций, срез 11.10.2026. Брать `workStatus: pending` по `queueOrder`, перед работой сверять актуальный MD и архив; правило генерации — `docs/workflows/highlights.md`. Существующие title/text сохранять; после подключения фото обновлять затронутую запись очереди и счетчики. Обычное создание тура эту очередь не запускает.

**Внешние профили и соответствия объектов (sameAs / hasMap):** `data/external-identity/README.md` и `data/external-identity/manifest.json`. Таблицы CSV/JSON и индекс по stable ID/canonical URL; актуальный срез, изменения и ограничения онлайн-проверки — в manifest.json и refresh-report.json. Новые страницы — new-pages.csv, исчезнувшая пагинация — removed-pages.csv. VIP × страна × интерес: очередь vip-catalogues.csv/json с фильтрами и пагинацией; проверка — vip-sameas-check-20261012.json. Для VIP-очереди сохранять только подтверждённые sameAs; тематические/функциональные аналоги не добавлять. Продолжать исследование по этому реестру, сохранять доказательства и статусы. JSON — редактируемый источник; после изменений `python scripts/export-external-identity.py`. Внедрение связей в schema.org — только по отдельной команде Алексея; текущий реестр к разметке не подключён.

**Архивирование только туров и экскурсий:** `docs/workflows/archive.md`, `data/catalog-archive.json`. Страны, места и интересы не архивируем. Архивные Tour/Excursion не возвращать в каталоги, счетчики, поиск и массовые фотоочереди; существующие карточки доступны с `noindex, nofollow`. При архивировании в том же пакете **содержательно исправить** рекомендации на архивируемый объект в опубликованных SEO/GEO-статьях: подтвержденный активный дубль — корректная замена, иначе убрать обещание доступной поездки, сохраняя связный текст. Проверить готовые статьи `seo-geo/staging` и не публиковать stale-ссылки. Актуальные таблицы: листы `Страницы`, `Фото`, `SEO-GEO тексты`, производная `Сводка`, опись Word и исторические реестры фото/внешних связей; записи не удалять. Для «следующих N фото» — первые N уникальных исходников строк `Фото!T = NEEDS_REPLACEMENT`, `ARCHIVED` пропускать; `scripts/photo-queue.mjs` только для явной сверки очереди.

**Опись программ Drive и оставшихся туров:** `docs/audits/tour-inventory.md`; редактируемый реестр `data/audits/tour-inventory-drive-20261009.json`; правила `docs/workflows/tour-inventory.md`. При создании/восстановлении тура из этой папки обновить подтверждённый `entityIds` и отдельный статус проверки содержания в реестре, затем `node scripts/sync-tour-inventory.mjs --apply` в том же commit. Похожие варианты и архивные дубли с активной заменой не считать новыми задачами автоматически. GitHub Actions пересчитывает наличие страниц; он не читает Drive и не подтверждает сверку полного текста с Word.

Выполнять актуальный запрос пользователя. Для типового наполнения читать только выбранный workflow и точную запись `data/source-index/entries/<entityId>.json`.

**Ускорение и PageSpeed:** `docs/workflows/performance.md`, `data/performance/pages.json` и журнал Google Sheets из workflow. Каждый следующий эксперимент сначала обсуждать с Алексеем; после согласованного изменения — 3 независимых PSI-прогона Mobile и Desktop, медианы и сравнение с эталоном. Бразилия с видео — отдельные строки для устройств. Не смешивать ERROR / REUSED / DRIFT с VALID и не вычислять эффект lazy load без замеров «до».

`docs/workflows/urls.md` — единый контракт английских URL: общие каталоги `/country/`, `/places/`, `/tours/`, `/excursions/`, `/interests/`; country-first иерархия объектов сохраняется. Русская транслитерация для новых slug запрещена. Существующие stable ID и точные `contentPath` не переименовываются. Для действительно нового резерва нужен явный `slug` либо латинское `englishName`; существующее место переиспользуется без этих полей.

**Интересы:** закрытый справочник из 14 ID в `src/data/interest-registry.json`. Активный Tour: 1–2 `primaryThemes` + непересекающиеся дополнительные `themes`; Excursion/Destination: собственные `themes`, без наследования. `Country.relatedThemes` и ручные списки Theme запрещены. Метки production MD и точных source-index entry/catalog обновляются вместе. Полный контракт: `docs/workflows/interests.md`.

`docs/workflows/master.md` — общий контракт и справочник, не обязательное полное чтение перед каждой сущностью. Исторические handoff и прежние версии workflow не задают действия.

При импорте известной сущности тексты, raw-фото, ID и URL берутся из её записи. Источники не ищутся, фотографии brasiltours.ru не скачиваются. Новые материалы, предоставленные пользователем, принимаются по workflow резервов: текст можно сохранить прямо в репозитории, приложенные фото — исходными файлами; обязательного повторного сохранения в Drive нет. Экранные проверки и пересчет соседних связей не выполняются. `/image/cache/` запрещен. Один подготовленный commit и один штатный Actions build/deploy завершают content-задачу; build не обращается к источникам.

Tour заранее указывает все канонические Destination ID маршрута. Для нового названия сначала сопоставить страну, имя и aliases в едином каталоге мест. Однозначно существующее место переиспользовать; только действительно новое — зарезервировать и сразу связать stable ID. Неоднозначность сообщить с конкретными кандидатами, не создавать дубль. Каждое место принадлежит одной стране; две стороны Игуасу — разные Destination.

Резерв не создаёт Destination MD, текст или фото и не публикует пустую страницу. Материалы места предоставляет Анна; описание экскурсии не становится текстом места автоматически. При заполнении сохраняются ID и будущий URL, готовые связи активируются сами. У Excursion основной `destination` задает URL; `relatedDestinations` хранит другие подтвержденные посещаемые места и дает обратные связи без переезда экскурсии. Известная экскурсия получает обе группы ID из готовой entry без нового поиска. Недостающие самостоятельные Excursion создаются вместе с туром и сразу используются через `excursionRef`.

Canonical URL вычисляет `src/lib/routes.ts`; старые плоские URL туров/экскурсий — только aliases. В туре страны основных маршрутов показаны одним уровнем через `·`, каждая ссылка отдельно. Не записывать ложную последовательность вложенных стран в breadcrumbs.

Явная глобальная миграция URL 02.10.2026 один раз меняет публичные slug; после неё использовать только закреплённые текущие поля. Все старые пути остаются redirect aliases навсегда. Архивные source URL, Drive originals и пути медиа не изменять. Языковые версии сейчас не создавать; будущие `/en/`, `/de/`, `/ka/` используют те же stable ID и английские пути объектов.

Публичные вводные и три полные словоформы каждого интереса — `src/data/interest-copy.json`; текущие количества — только расчет из активных туров. `/interests/` сортируется по количеству. География Theme — full-bleed `DestinationBand`: обложка первого тематического тура только по показанной стране, иначе `Country.hero`. Multi-country hero для фона страны не используется; географию самого кадра отдельно не определять. Распределение максимум 7 стран снизу вверх, без повторов Tour. Полный контракт: `docs/workflows/interests.md`. Hero каталога «интерес + страна» берется из `Theme.hero`. Одну нижнюю форму всегда создает `BaseLayout`; в дочерних страницах передавать `leadTitle`/`leadEntityId`, не дублировать `<LeadForm>`.

## Обязательное правило: новые медиа только напрямую в S3 (09.10.2026)

**Никогда не записывать в Git новые или изменённые бинарные файлы** из `public/media/` — WebP, JPEG, PNG, MP4, WebM и прочие. Все старые файлы в Git и историю коммитов сохранить, не удалять. GitHub Pages продолжает принимать только HTML/CSS/JS/SEO; медиа отдаются по `https://img.adatours.ru/media/...`.

ChatGPT Work при любой новой генерации/улучшении изображения или видеоролика использует `docs/workflows/direct-s3-upload.md`: локальный файл вне Git → одноразовый X25519 сеанс → зашифрованный временный OIDC IAM-допуск → прямой S3-upload → проверка SHA-256 → текстовый receipt в `src/data/media/direct-s3-uploads.json` → commit MD/JSON/реестров без бинарного файла. `hero.src` и прочие поля содержат прежний логический путь `/media/...`. Новым файлам всегда новое версионированное имя, S3-объекты не перезаписывать. GitHub Actions проверяет ledger и наличие файла до публикации.

Если прямой upload из конкретного чата недоступен, **сохранить задание и назвать блокер; не возвращаться к Git binary fallback, не связывать неподтвержденный S3 путь и не утверждать, что фото опубликовано**. GPT Image и финальные WebP требуют Work с локальным файлом и сетевым доступом, у GitHub connector нет команды прямой передачи бинарного файла в Object Storage.

Для выборочных видеофонов отдельного Country/Tour hero предусмотрена загрузка MP4/WebM точно так же, но проигрывание включается только в отдельной задаче. Оригинальный WebP-постер остается обязательным для LCP, SEO, мобильных устройств и `prefers-reduced-motion`. Подробнее: `docs/MEDIA_DELIVERY.md`.
