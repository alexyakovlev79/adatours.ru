# Пошаговый план внедрения и контрольные точки

28.10.2026. Номер этапа — порядок зависимостей, не обещание срока. Каждый
законченный этап фиксируется отдельным GitHub checkpoint с фактическими counts,
SHA, проверками и оставшимися блокерами. Основной рабочий код один.

| Этап | Работа | Когда этап действительно завершён |
| --- | --- | --- |
| 0. Основание и доступ | GitHub branch, snapshot кода, Drive inventory, аудит metadata/schema, архитектура, initial i18n libraries и UI copy | Артефакты сохранены в Git, focused tests пройдены, статус без заявления о полном EN |
| 1. Полный mapping | Содержательно разобрать 358 активных Tour, дубликаты/редакции, карантинные кандидаты; закрепить 2027/2026/not_found_both; определить Offer-конфликты | У каждого активного Tour есть объяснимое решение, не только name score; архив исключён |
| 2. Стабильные блоки | Постоянные ID дней/абзацев, source parser/full DOCX, общие Excursion, зависимости фактов, glossary | Полный извлекатель покрывает видимый текст, ничего не теряет/не дублирует; 3–5 реальных сквозных mapping packets |
| 3. Единый locale resolver | Адаптер текущих MD → shared facts/media + locale overlay; cache по locale; география по ID; code/SEO shared | Взаимосвязанный пилот страны/места/тура/экскурсии собирается в RU/EN без копирования цен и медиа |
| 4. UI/SEO/schema/search | Подключить подготовленные строки/шаблоны, все RU filters, FAQ, alt, shell postprocessor, формы, счётчики, language pairs | Закрыт checklist L01–L16 в metadata spec; нет скрытого русского fallback и ложных ценовых агрегатов |
| 5. Dispatcher и пилот | CAS shards/index, claim/renew/checkpoint/submit/resume/status, reaper/retry, source reconciliation | Гонки/обрывы/повторы проверены; минимум два worker реально сохранили 3–5 задач; расходы/API измерены |
| 6. Перевод 2027 | Проверенные Word-пары первого приоритета, их Excursion зависимости, AI gaps | Полное покрытие разрешённых задач; review отдельно; точные Word passages и факты сохранены |
| 7. Перевод 2026 | Только оставшиеся Tour без 2027, та же приёмка | Пары 2026 закрыты без изменения текущих коммерческих фактов |
| 8. Остальные тексты | AI-only Tour после отрицательных решений; страны, места, экскурсии, themes, коммерческие/служебные страницы, SEO/GEO | Нет неподтверждённых заглушек; voice QA в первом проходе; все internal dependencies разрешены |
| 9. Двухъязычный release | EN target, immutable артефакты, exact receipts, формы, release ledger, rollback | Оба target обслуживают подтверждённые версии, статус synchronized подтверждён |
| 10. Домен и постоянная синхронизация | Утверждённый host, карта old .com redirects, CORS/analytics, push/watch/outbox + retries | Смена host не требует правки текстов; любые текущие writers попадают в reconciler; Word changes не теряют одобрения |

Этапы 1–2 и подготовка интерфейса/адаптера могут частично идти параллельно.
Массовая выдача перевода зависит от matching, block identity и диспетчера. Новый
домен не нужен для инвентаризации, переводов и тестирования; нужен для финального
production release и CORS/redirect настроек.

## Конкретные изменения runtime следующего этапа

1. Добавить `getLocalizedCollection(type, locale)` поверх текущего shared source,
   не размножая MD с фактами. Заменить жёсткие RU selectors в catch-all,
   layouts/header/catalog/VIP/multi-country и schema loadRecords.
2. Ввести явный build context locale/origin/base/release mode. Использовать
   `locale-site` как общий источник адресов; planned EN не допускать в public.
3. Нормализовать текстовые `route`/`places` в entity references там, где возможно,
   сохранив текущие ID/URLs/aliases и текущую RU видимость.
4. Передавать locale в публичные компоненты и клиентские сообщения. Меню и
   одноразовые строки уже переведены координатором; source inventory проверяет
   появление новых строк, а не запускает рой для каждой кнопки.
5. Подключить metadata spec к общей типизированной формуле. Не выполнять
   `seoFill` RU-регулярками над английским текстом. База цены — структурное поле.
6. Разделить alt/hover/caption по `(assetId, locale)` и сохранить общий asset src.
   Не перегенерировать изображение из-за нового языка.
7. Использовать один JSON-LD renderer, общий Organization ID, локальные
   WebSite/WebPage IDs, exact language pairs и publisher/provider связи.
8. Обновить locale-aware FAQ parsers, SEO/GEO tokens, search JSON, Pagefind,
   social preview text и `dedupe-site-shell` на обоих выходных каталогах.
9. Обновить форму: английские состояния/ошибки, корректный международный телефон,
   payload locale+offerId, серверный allowlist реального host, без смены контактов.
10. Добавить diff hook после всех принятых source commits, в том числе прямых MD
    изменений и daily workflow; это гарантирует отсутствие незамеченных writers.

## Предметный пилот перед масштабом

Нужен маленький полный граф: две страны, два места, одна общая экскурсия в двух
турах, один Word-exact кандидат, один Word+AI-gap, один действительно AI-only
после matching, каталог и пагинация, SEO/GEO FAQ, форма, пустая выборка, архив,
404. Если AI-only пока не доказан, использовать синтетический тест, а не
самовольно объявлять реальный тур без источника.

Для Word-пилота уже сохранены восемь источников с конкретными конфликтами.
Рекомендуемые первые смысловые проверки: Rio 4 days (язык услуги), Easter
Island (общие excursion blocks), Colombia Essential (сохранение принятой
географической поправки). Mexico Lindo — обязательный отрицательный тест:
перевод не должен заменить цены на EN Word-тарифы.

Проверить изменения: priceFrom и priceBasis; факт даты в прозе; фото с тем же
subjectId; фото другого объекта и alt; перестановка/вставка дня; source Word
revision; одновременная RU/EN правка; новый фильтр; временный EN origin;
истёкший worker lease; потерянный ответ submit; отказ одного deployment.

## Что можно решать без ожидания владельца

Разбор источников, уточнение matching по предоставленным материалам, сохранение
неизменённых Word-пассажей, перевод текущего RU, подготовка словарей/адаптера,
узкие тесты и feature checkpoints входят в текущее поручение.

Что требует содержательного решения до конкретной публикации: реальный host
и замена существующего `.com`; трактовка разных коммерческих предложений;
новые условия виз/платежей/договора для иной аудитории; внешние ресурсы/права,
которых у настроенного pipeline ещё нет. Нерешённые вопросы сохраняются адресно,
остальная работа продолжается. Это не повод повторно спрашивать доступ к GitHub,
который в этом сеансе уже подтверждён.

## Как оценивать объём после mapping

Не считать бюджет по 732 исходным документам. Сначала дедупликация и покрытие:
количество уникальных принятых Word-пассажей, уникальных AI gaps, общих Excursion,
SEO/GEO-статей и фактических конфликтов. Стоимость/сроки становятся осмысленными
после 3–5 реальных пакетов с измеренной скоростью, API и долей возврата QA.
План не содержит выдуманной даты запуска и не считает candidate match готовым
переводом.

## Definition of done

Новый EN-сайт действительно опубликован; конфигурация домена заменяема; код,
факты и медиа едины; все заявленные страницы переведены и прошли QA; текущие
writers запускают reconciliation; очереди не теряют задачи после обрыва;
оба deploy подтверждаются; `published` не подменён `ready`; старые URLs имеют
проверенные переходы. Нынешний foundation checkpoint закрывает этап 0 и часть
подготовки этапов 1–4, но не эту финальную приёмку.
