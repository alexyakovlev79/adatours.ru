## Важно о безопасности

Репозиторий alexyakovlev79/adatours.ru и его GitHub Issues публичные. **Нельзя** помещать в Issue непубликуемые Word, закрытые цены, личные данные, секреты, ссылки с приватными токенами. Публикуется только конечный текст, уже предназначенный для сайта. Обработчик работает исключительно с разрешенными полями существующих публичных content MD. Новые фото, целые новые туры, связи и сложный Word-импорт пока обрабатываются прежними доверенными процессами, не через эту редакторскую заявку.

Список допущенных GitHub-пользователей: data/editorial/authorized-users.json. Действующий состав редакторов определяется файлом `data/editorial/authorized-users.json`. Имя создателя Issue сверяется с GitHub, а право создавать редакционные заявки не означает право записи в основной репозиторий. Администратор вносит точные GitHub-логины Анны и менеджеров — все получают одинаковые редакторские права. Пользователям не нужны и не должны выдаваться роли Write/Maintain/Admin на основном репозитории. Их ChatGPT должен быть подключен к личному GitHub и иметь возможность создавать Issue. По тексту Issue или заявленному имени права не определяются.

## Скопировать в инструкции ChatGPT Анны и менеджеров

Ты редактор контента сайта Ada Tours. Для точечной правки опубликованной страницы сначала найди ее stable ID и точную запись в data/source-index/entries на актуальной ветке main репозитория alexyakovlev79/adatours.ru. Для страницы интереса (theme), если source-index entry отсутствует, проверь stable ID/slug в src/data/interest-registry.json и найди ровно один src/content/themes/*.md с совпадающими id и slug. Открой точный content-файл и получи **точный Git blob SHA** файла. По устному или письменному запросу подготовь минимум нужных изменений опубликованных полей, без догадок о стоимости, датах и составе услуг. Создай GitHub Issue в этом же репозитории с заголовком [ADA-EDIT] и кратким названием, с телом в формате **чистого JSON без Markdown-ограждений**. После создания дай ссылку на Issue. Проверь комментарии к Issue и сообщи об успехе публикации только после фактического подтверждения GitHub Pages. Не создавай дубликаты при неизвестном результате. Если требуется новый тур из Word, новая картинка, новая сущность, перестройка программы, изменение URL, связи, схемы или кода — этот узкий редакторский инструмент не подходит: сообщи об этом и передай задачу на действующий полный workflow.

Пример структуры (ID и SHA из примера нельзя использовать без повторной проверки GitHub):

## Разрешенные правки

Типы: tour, excursion, destination, country, theme. Один Issue меняет ровно одну уже опубликованную сущность и максимум 12 полей.

Tour: title, lead, format, priceFrom, priceNote, priceBasis, dates, included, notIncluded, notes, body, hero.alt, hero.caption; itinerary[0].text/title/label; highlights[0].title/text; faq[0].question/answer.

Excursion: title, lead, duration, format, priceFrom, priceNote, included, notIncluded, notes, body, hero.alt, hero.caption.

Destination: name, summary, body, hero.alt, hero.caption, featureBands[0].eyebrow/title/text, facts[0].label/value.

Country: name, summary, bestTime, entryNotes, body, hero.alt, hero.caption, featureBands[0].eyebrow/title/text.

Theme: name, summary, body, hero.alt, hero.caption.

Номер внутри квадратных скобок — индекс существующего элемента, начиная с нуля. Списки можно заменять целиком. Поле должно уже существовать. Число priceFrom не определяет само по себе цену за человека или за группу, поэтому правильное условие нужно сохранять в priceNote или priceBasis, если поле присутствует. Запрещены raw HTML, ссылки javascript/data и шаблонные директивы. Новые бинарные фотографии, изменение hero.src, ID, slug, status, routeCountries, destinations, themes, excursionRef, схем, CSS, JavaScript и workflows технически запрещены.

## Как устроен процесс

GitHub Action ada-chatgpt-editor.yml запускается на открытие Issue с [ADA-EDIT]. Она читает настоящее имя создателя Issue из GitHub, а не из JSON, сверяет allowlist, source-index, идентичность MD и ожидаемый blob SHA, разрешенные поля и безопасность текста. Изменяет ровно один Markdown-файл. Перед записью запускает узкие unit-тесты и стандартную полную сборку. В main записывает лишь этот файл, через workflow_dispatch запускает существующий deploy.yml. Отдельный ada-chatgpt-editor-finalize.yml комментирует подтвержденный результат Pages deployment. Если исходный файл изменился с момента чтения, задача безопасно отклоняется; нужно открыть текущую версию и заново составить правку. При ошибке/гонке не делать вид, что обновление опубликовано.

Ночная обработка новых Word 2027 и ручные правки работают независимо. Ночная версия может перезаписать значения. Отдельная защита на этот счет не создается.

Полный импорт новых/измененных туров из Word идет по docs/workflows/tour-2027-daily.md и связанным регламентам с обработкой мест, экскурсий, медиа, SEO/GEO и реестров. Эта редакторская функция не пытается реализовать их в упрощенном виде.

## Работа с приложенным Word 2027: немедленное обновление и отдельное хранение

**Разные команды означают разные действия.** При «сохрани этот Word в папку 2027» выполнить только безопасную загрузку/обновление бинарного DOCX на Google Drive, подтвердить file ID и не утверждать публикацию. При «я немного поменяла тур, обнови [на русском сайте]» с вложенным Word **сразу маршрутизировать в `docs/workflows/tour-from-word.md`, раздел 0.2**, и выполнять в текущем поручении весь адресный цикл до подтвержденной публикации либо реального блокера. **Одна загрузка в Drive и ожидание ежедневной задачи — недостаточный и неправильный результат такой команды.**

Корневая папка: Google Drive «2027 Russian Programs», ID 1J50jX8rfa5bNq8qvo_WNiUYzxJmqs_NK. Использовать личные разрешения Google Drive и настоящий `file_uri` прикрепленного файла; для подтвержденной новой редакции того же документа сохранять существующий file ID через `update_file` при наличии права записи, иначе безопасно зарегистрировать новый Drive ID. Не заявлять успешную загрузку без ответа Drive и не помещать закрытый DOCX в публичные GitHub Issue. Полное чтение Word включает таблицы и встроенные картинки, которые нужно сопоставить по содержимому и контрольным суммам.

Существующая ежедневная задача «Обновление туров Анны 2027» по `docs/workflows/tour-2027-daily.md` **отдельно** обнаруживает незаявленные изменения папки. Она остается на прежнем расписании; ручная команда не должна ждать ее, запускать дубль или выдавать ее будущую работу за выполненную. Полный Word-цикл с медиа требует доступа к файлу, Work/Codex-компьютера, GitHub и защищенного S3-маршрута; при отсутствии возможности назвать конкретный блокер. Обработчик `[ADA-EDIT]` не подходит для полного Word-импорта и бинарных медиа.

Фотографии, добавленные непосредственно в Word и достоверно связанные с программой, обрабатываются существующим полным Word-процессом. Для отдельной фотографии, которую пользователь прикрепил к ChatGPT, есть безопасный маршрут `editor-s3-token-issues.md` → `direct-s3-upload.md` → адресная текстовая правка MD и receipt → Pages deploy. Для работы нужен ChatGPT Work/Codex с Node.js, HTTPS и доступом к прикрепленному файлу. **В `[ADA-EDIT]` по-прежнему нельзя менять `Person`, `photo.src` или загружать бинарные файлы.** Не предлагать искать новый портрет в `public/media/` или коммитить его в Git.

### Темы без source-index entry

Тематические страницы сохраняют stable ID в `src/data/interest-registry.json`. Редактор и сервер сверяют именно этот реестр с реальным `id` и `slug` существующего `src/content/themes/*.md`. Отсутствие отдельной source-index entry для темы не блокирует разрешенную текстовую правку. Не создавать фиктивную запись источника, новый ID, новый slug или файл темы ради редакторской операции.
