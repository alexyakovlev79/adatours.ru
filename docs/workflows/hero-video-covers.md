# Видеообложки: первый кадр, выбор варианта и запуск

Решения Алексея 21–22.10.2026, P03–P05. До видео показывать первый декодированный кадр именно выбранного ролика. Редакционное фото, которое затем закроет видео, не загружать. Один общий механизм для hero любой страницы и для областей, переиспользующих hero другой страницы. Никаких специальных правил для отдельных стран или названий карточек.

## Источники

`heroVideo: { src?, mobileSrc?, sourceUrl? }` доступен в общей content schema. `src` — горизонтальный ролик, `mobileSrc` — вертикальный. Для первого hero самой страницы сохраняется прежний выбор по устройству: телефон получает mobileSrc, desktop/tablet — src. Для заимствованного hero выбор определяется реальной областью показа: ширина >= высоты — src, высота > ширины — mobileSrc, на любом устройстве. Нельзя подменять отсутствующий вариант другим форматом.

`src/lib/hero-video-catalog.ts` один раз за build читает действующие RU-сущности и строит связь **точный hero.src → heroVideo + canonical owner**. Данные главной добавляются как запись самостоятельной страницы. `hero-video-catalog.mjs` нормализует логические/CDN пути; собственная страница не получает заимствование своего же фото. Совпадение страны или названия недостаточно. Если одно фото связано с разными роликами, сборка сообщает конфликт вместо произвольного выбора. Ролик без зарегистрированного первого кадра в автоматический каталог не включается.

Шаблоны собственных Country/Destination/Tour/Excursion/Theme/Case передают heroVideo в Hero. Hero без явного видео может получить заимствованный вариант по своей фотографии, включая каталоги. Место Hero на странице остаётся первым hero, даже если его фото заимствовано: на touch действует исключение первого hero, но формат заимствованного источника выбирается по форме.

`poster`/`mobilePoster` общего компонента — только первый кадр соответствующего src. Точное соответствие хранит `src/data/media/hero-video-posters.json`, привязанный к версионированному видео, а не к странице или месту показа. При замене MP4 меняются ключ и кадр; SHA-256 и S3 receipt сохраняются. Фото остаётся для устройств/областей без нужного варианта и для no-JS.

## Переиспользование на сайте

- `HeroVideo.astro` — общий SSR-контракт; `src/scripts/video-covers.mjs` — единственный клиентский контроллер.
- `DestinationBand` автоматически подключает заимствованный hero в обоих вариантах карточки. Ссылка и кнопка не вложены друг в друга; у descriptionBelow поверхностью является только фото, без текста снизу.
- `BorrowedHero.astro` оборачивает существующую CSS/HTML фотографию в инертный slot; используется плиткой интересов, StoryPair и карточками мест/экскурсий страны. Родитель задаёт позиционированную изолированную область с data-video-surface.
- `HeroImage.astro` — обычный img без изменения поведения, если связанного видео нет. При заимствовании создаёт отдельную измеримую область; применяется в галереях, главных впечатлениях, днях тура/встроенных экскурсиях и фотокарточках главной. `fill` сохраняет абсолютную область исходного фото; `background` — слой под градиентом. Подписи и alt сохраняются. В ссылках декоративный плеер не создаёт вложенную кнопку.
- Новое видео подхватывается из данных и реестра; отдельное условие по entityId/стране в карточках не нужно. Обычные видеоплееры внутри текста этим контрактом не управляются.

## Загрузка

Редакционное фото хранится в template/noscript до выбора ветки. В видео-ветке активируется только собственный первый кадр; фото остаётся инертным. В фото-ветке клонируется оригинал с прежними мобильными crops, фокусом и атрибутами. Смена ориентации повторно измеряет область и выбирает свой вариант, удаляя неактивные слои.

У дополнительных областей кадр/фото активируется в общем окне lazy load: `isWithinImageWindow` из lazy-images — текущий экран плюс соседние (верх < двух высот окна, низ > минус высота окна, ненулевые размеры и горизонтальное пересечение). **MP4 получает src только при разрешённом запуске**, не при одном попадании в окно загрузки. У первого hero кадр сохраняет высокий приоритет. URL в data-атрибуте не начинает запрос. Native poster с другой картинкой отсутствует.

Первый кадр и видео имеют одинаковые object-fit:cover и object-position:center. Фокус редакционного фото не переносится на кадр. До playing, при отказе autoplay или ошибке остаётся первый кадр. При ручном запуске кнопка вызывает play в пользовательском событии, сохраняя ограничения области.

## Воспроизведение

1. **Desktop с мышью:** play только при курсоре внутри области и полной видимости. Уход курсора — pause, скрыть видеослой, вернуть первый кадр, сбросить время в0. Это относится и к первому hero.
2. **Телефон/планшет:** первый hero играет автоматически, пока целиком видим. Дополнительная область ждёт, пока её вертикальная середина достигнет середины visual viewport. Пересечение отслеживается между кадрами, точное пиксельное совпадение не требуется. У восстановленной страницы уже пройденная середина учитывается.
3. **Ряд на touch:** одинаковые top/height с допуском2 CSS px образуют ряд. Доступные ролики идут по фактическим координатам слева направо; ended передаёт ход следующему. После последнего — снова первый. Нативный loop у таких видео выключен. Ряд может продолжаться после прохождения середины, пока текущая карточка целиком видима; новый ряд получает ход после своего пересечения середины. Ширина окна не превращает desktop в телефон; планшет с trackpad остаётся touch-режимом.
4. **Любой режим:** если хоть один край области вышел за visual viewport — pause и первый кадр. Это важнее продолжения очереди. Слишком большая область, не помещающаяся в экран, не играет. Невидимая вкладка и скрытый блок не играют. Ручная пауза сохраняется; уход/возврат не отменяет её.

## Мобильные страны главной

В P05 обе разновидности карточек стран до760 CSS px уменьшены на12,5%: clamp(360px,105vw,460px) → clamp(315px,91.875vw,402.5px). Нет отдельного условия для Бразилии. Реальная форма её карточки теперь позволяет общий выбор горизонтального видео и на телефоне. Остальные области сайта по высоте не меняются.

## Новый первый кадр

Из точного MP4 извлечь первый декодированный кадр без -ss: `ffmpeg -i video.mp4 -frames:v 1 -vf "scale='min(iw,1280)':-2" -c:v libwebp -quality 82 frame.webp`. Сохранить пропорции, не увеличивать. Новое версионированное имя, прямой S3-upload по direct-s3-upload.md, проверка SHA-256, ledger и реестр. Новые бинарные медиа в Git запрещены.
