# Ada Tours EN — обновление уже переведенных страниц после RU-правок

Дата решения: 14.11.2026 (Москва; точное время не указывается).
Источник истины: `alexyakovlev79/adatours.ru` (`main`); английская техническая публикация — `alexyakovlev79/adatours-en` (noindex).
Применяется только к страницам, для которых уже был сохранен утвержденный/допущенный перевод. Не запускает новую массовую очередь, не перезаписывает результаты переводчиков, не меняет русскую страницу, цены или медиа.

## Событие и порядок

При содержательном изменении ранее переведенного русского Markdown:
1. Найти точные затронутые файлы и их текущие Git blob SHA. Сопоставить с уже примененными EN-фрагментами и зафиксированным source SHA. Изменение build-кода без изменения исходника перевода не создает задачу.
2. Если текущий SHA уже имеет полноценную EN-ревизию и она опубликована, ничего не создавать. Для новых RU-изменений перевести весь затронутый текст (или только действительно измененные блоки Tour), сверив все названия, внутренние ссылки, числа, цены, валюты, годы, длительности, маршруты, состав услуг и ограничения. Исходные русские факты имеют приоритет. Сохранить полноценный живой английский, без дописанных фактов.
3. Для любой из 7 056 FULLTEXT-единиц использовать существующий номер `number` и исходный `frozenSha` из immutable определения очереди `data/i18n/fulltext-swarm/v1/definitions/` в `i18n/translation-mass-staging`. В `data/i18n/fulltext-publication-repairs/2026-11-12.json` добавить одну новую запись в необязательный массив `sourceFullRevisions`: `{number,path,frozenSha,approvedCurrentSha,enMarkdown}`. В `approvedCurrentSha` — точный Git blob SHA текущего RU файла; `enMarkdown` — полный английский Markdown с переведенными текстовыми полями, исходной идентичностью, точными ссылками и местами динамических вставок. Старые переводы и уже сохраненные записи не удалять. Повтор записи для тех же `number + approvedCurrentSha` запрещен.
4. Для переведенного Tour использовать действующий source-bound механизм полей/блоков и его CAS/receipts, а не подменять программу другой версией Word и не считать общую FULLTEXT-ревизию поддержкой Tour. Если безопасная точечная публикация невозможна, сохранить адресный блокер, не объявляя страницу переведенной.
5. Одно логическое изменение с подготовленными EN-ревизиями записать в `main` без force и без чужих правок, запустить штатный тест/сборку/публикацию. Английский `adatours-en` сверяет новую основную SHA на своем ежечасном расписании. Проверить `en-fulltext-receipt` (нужный файл `applied`, не `withheld`/`partial`), отдельный успешный Actions Pages run и актуальный `canonicalSourceSha` до заявления о публикации.
6. При сбое повторять только неопубликованную стадию; уже сохраненные ревизии не пересоздавать, CI не запускать в цикле, двойных GitHub Issues и вторых релизов избегать. Если текущий источник снова изменился в процессе перевода, прежний EN нельзя использовать для новой версии: требуется отдельная ревизия с ее SHA.

## Автоматизация и ограничения

Наблюдение и перевод выполняет ChatGPT Automation с подключенным GitHub, максимум раз в час: GitHub Actions сам не запускает пользовательский ChatGPT-чат. Ранее отключенный платный OpenAI API не включать, новые платные источники не подключать. Ежечасный EN Pages cron может добавить ожидание до следующего успешного deploy; обещать мгновенный перевод и публикацию нельзя. Между обновлением RU и готовой EN-ревизией текущий строгий механизм вправе показать русский fallback вместо устаревшего перевода.

Проверка должна быть дешевой: сравнить текущий main, последний подтвержденный EN source SHA и релевантные недавние изменения. Не пересканировать все 7 056 Markdown на каждом пустом запуске, не пересоздавать старые переводы. Если изменений нет, ничего не коммитить и не отправлять уведомления. При расхождении точного source SHA выбирать лишь затронутые ранее переведенные единицы; при ошибке редакторской проверки сообщать конкретный ID и причину.
