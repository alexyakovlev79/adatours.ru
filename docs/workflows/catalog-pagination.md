# Ada Tours — каталоги, пагинация и «Показать еще»

## Тематические каталоги — 05.10.2026

Общие правила этого документа применяются также к `/interests/<theme-slug>/tours/` и `/interests/<theme-slug>/tours/<country-slug>/`. Реализация — `src/pages/interests/[...catalog].astro`; модели и веса — `interests.md`. Фильтрация активного ассортимента и тематическая сортировка выполняются до `paginateCatalog`; размер страницы остаётся 10. Подкаталог страны содержит тематические туры с основной либо явно дополнительной страной, последняя подписывается у тура. Пустые каталоги не создаются. Self-canonical, полная навигация, load-more, ItemList, sitemap и тесты общие. Старые URL объектов не меняются.


Версия: 1.0 · 2026-10-03. Репозиторий: `alexyakovlev79/adatours.ru`, ветка `main`.

Контракт реализации пунктов 2 и 3 задания пользователя о длине страниц. Дополняет `docs/workflows/destinations.md`, `excursions.md` и `urls.md`. Полнота каталога означает доступность всех объектов через страницы, а не вывод всего списка одним HTML.

## 1. Обзорные страницы

| Страница | Подборка | Максимум | Ссылка при превышении |
|---|---|---:|---|
| Страна | Места / туры / экскурсии | 15 / 10 / 5 | Действующие ссылки на каталоги страны |
| Место | Основные туры / факультативные туры / экскурсии | 10 / 5 / 5 | Действующие точные каталоги места |
| Экскурсия | Туры с этой экскурсией | 10 | `Все туры с этой экскурсией` |

Полные отсортированные массивы сохраняются для связей и счетчиков. `slice()` применяется только в выводе обзорного блока. Ссылка появляется при числе строго больше лимита. Пустой блок отсутствует. Рекомендации «Куда поехать дальше» и «Другие экскурсии» сохраняют прежний максимум 10 и прежний алгоритм.

Связь тура с экскурсией извлекается через `excursionIdsForTour()` из всех поддерживаемых `excursionRef`. Новый каталог туров экскурсии находится под ее собственным адресом: `tourExcursionPath(excursion)` → `${excursionPath(excursion)}tour/`. Каталог создается при непустом списке активных туров; основная экскурсия тоже должна быть активной. Порядок: по убыванию рейтинга `2 × число основных стран маршрута − |durationDays − 13|`; при равном рейтинге — по русскому title; тур без `durationDays` идет после туров с вычисляемым рейтингом. Canonical самих продуктов не меняется.

Каталог экскурсий места использует **все** `excursionDestinationIds()` — основное место и дополнительные `relatedDestinations`, с уникальным ID каждой экскурсии. Страна каталога определяется самим местом. Этот полный набор сохраняется и при пагинации.

## 2. Какие каталоги разбиваются на страницы

Все перечисленные виды используют `src/pages/[...path].astro`, `EntityCatalogLayout.astro` и `src/lib/catalog-pagination.ts`:

- общие `/tours/`, `/places/`, `/excursions/`;
- каталоги страны: `/<country>/tour/`, `/<country>/place/`, `/<country>/excursion/`;
- экскурсии места: `/<country>/<destination>/`;
- основные и факультативные туры места: `/<country>/place/<destination>/tour/` и `.../optional-tours/`;
- туры конкретной экскурсии: `<canonical-excursion-path>tour/`;
- многострановые туры: `/multi-country/tour/`.

Общие каталоги перенесены из трех отдельных `index.astro` в единый генератор; их публичные адреса, первые hero и редакционные вступления сохранены. Страницы стран, мест, самих туров, экскурсии как продукты, темы и коммерческие страницы не превращаются в каталоги.

`CATALOG_PAGE_SIZE = 10`. Сначала выбирается полный активный RU-набор без `draft` / `archived`, затем сортируется, затем делится на десятки. Последняя страница содержит остаток. Все автоматические списки туров используют один порядок: по убыванию рейтинга `2 × число основных стран маршрута − |durationDays − 13|`; при равном рейтинге — по русскому title; тур без `durationDays` идет после туров с вычисляемым рейтингом. Места и экскурсии сортируются действующими helpers по числу связанных туров.

## 3. Постоянные URL и SEO

- Первая страница остается на прежнем корне каталога: `/brazil/tour/`.
- Продолжение имеет реальные статические URL: `/brazil/tour/page/2/`, `/brazil/tour/page/3/` и далее.
- `/page/1/` не создается и нигде не используется. Кнопка «Назад» на второй странице ведет непосредственно в корень. Нулевые, отрицательные, дробные и выходящие за конец серии страницы не генерируются и получают штатный 404 хостинга; страницы не подменяются первой десяткой.
- Каждый HTML сразу содержит один абсолютный self-referencing canonical на свой чистый URL без параметров и фрагментов. Страницы 2+ **не** канонизируются на первую.
- `title`, meta description и H1 страниц 2+ содержат номер страницы; description также показывает диапазон. Сохраняется один H1. Open Graph URL совпадает с canonical.
- На каждой странице есть обычные `<a href>` на соседние страницы и номера. На страницах 2+ есть отдельная ссылка на первую сверху и снизу, а номер 1 всегда доступен в навигации.
- BreadcrumbList продолжения сохраняет ссылку на корень конкретного каталога и добавляет текущую страницу. Новые каталоги туров экскурсии связаны с самой экскурсией.
- ItemList описывает только видимую десятку с реальными URL и сквозными позициями. Фиктивные цены, рейтинги и обещания расширенного результата не добавляются.
- Все непустые канонические страницы серии входят в штатный sitemap. Старые redirect aliases исключаются существующим механизмом. Основные туры, места и экскурсии сохраняют собственные ссылки и sitemap entries.
- Для страниц пагинации не вводится отдельный `noindex` и не добавляется запрет в robots.txt. **Действующий общий запрет индексации тестового GitHub Pages из BaseLayout сохраняется**; этот релиз не является переключением на основной домен или разрешением индексировать тестовый хост.
- Новые варианты сортировки, URL фильтров и языковые копии не создаются. Canonical отсеивает параметры отслеживания от чистого адреса; смена фильтров была бы отдельной задачей.
- `rel="prev"` / `rel="next"` оставлены на обычных ссылках навигации для семантики. Работа Google не основывается на этих атрибутах: Google больше не использует их для распознавания пагинации.

Основание: официальные рекомендации Google Search Central, проверены 03.10.2026:

- https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading
- https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls
- https://developers.google.com/search/docs/specialty/ecommerce/designing-a-url-structure-for-ecommerce-sites

## 4. Дублирующая кнопка «Показать еще»

`CatalogPagination.astro` выводит оформленную как кнопку ссылку на следующую страницу. Без JavaScript это обычный переход. `src/scripts/catalog-load-more.ts` перехватывает только обычное нажатие и получает HTML следующей страницы того же каталога. Номера страниц остаются отдельными обычными переходами; Ctrl/Cmd+клик сохраняет стандартное поведение ссылки.

При успешной загрузке добавляется следующая десятка и обновляется диапазон. Уже показанные объекты сохраняются. Порядок чередования изображений рассчитывается по сквозной позиции, а не начинается заново после нажатия. После последней части кнопка скрывается. При двойном клике выполняется только один запрос. При сетевой ошибке, изменении состава каталога между сборками, неправильном ответе или повторяющихся ID список не повреждается: показывается сообщение, остаются повторная попытка и обычная пагинация.

Отпечаток полного упорядоченного списка ID защищает от смешивания разных версий каталога. Состояние подгрузки имеет отдельный курсор. Адрес документа, серверный canonical, title и выделенный номер **не меняются JavaScript**: они относятся к реально открытой странице, а не к последней добавленной десятке. Подгрузка не является заменой постоянных URL.

У элементов управления предусмотрены focus-visible, область живого статуса, aria-busy и понятное сообщение об ошибке. После вставки клавиатурный фокус переносится на первый добавленный объект без принудительной прокрутки.

## 5. Проверка и дальнейшее наполнение

Штатный `npm run build` выполняет unit-тесты пагинации, Astro build, `scripts/check-catalog-pagination.mjs` по сформированным HTML и затем Pagefind. Дополнительной ручной визуальной приемки и обхода опубликованного сайта нет.

Машинная проверка проверяет размер каждой части, полноту всех частей, отсутствие повторов, сохранение исходного порядка по отпечатку ID, существование целевых страниц объектов, единственный self canonical, Open Graph URL, один H1, нумерованный title, ссылки на первую/предыдущую/следующую страницу, fallback кнопки, отсутствие `/page/1/`, ItemList и включение в sitemap.

Это производные страницы. Для очередной публикации Tour, Destination или Excursion не нужны новые ручные MD каталогов, записи source-index, отдельные строки импорта в Google Sheets, изменение JavaScript или пересчет навигации: все пересобирается по активным данным. Тексты и фотографии продуктов этот механизм не меняет.
