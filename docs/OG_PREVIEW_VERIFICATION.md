# Ada Tours — проверка OG-изображений

## При обычном деплое

Скрипт scripts/build-social-previews.mjs формирует Open Graph и Twitter-метатеги для всех HTML-страниц, но проверяет по сети только новые идентификаторы изображений.

Список ранее проверенных объектов берется из https://adatours.ru/social-preview-manifest.json последней успешно опубликованной версии GitHub Pages. Публичный JSON содержит лишь хешированные S3-ключи JPEG без секретов и исходных URL медиа. Если манифест отсутствует, недоступен, поврежден или имеет чужую версию, выполняется полная проверка всех объектов. Новые изображения проходят прежний HEAD-контроль типа/размера и при необходимости загружаются в S3 с проверкой SHA-256.

Скрипт продолжает обновлять OG/Twitter-метатеги всех страниц. В dist/social-preview-report.json есть checked (проверено через сеть), alreadyVerified (переиспользовано из предыдущей публикации), uploaded (новых загрузок). Список ключей следующего релиза автоматически сохраняется в dist/social-preview-manifest.json.

Первый деплой после введения манифеста выполняет один полный проход для создания базы. После успешной публикации обычные сборки проверяют только новые ключи.

Важно: ключ OG-файла зависит от версии генератора и пути исходной фотографии. Исходные изображения не перезаписываются под тем же URL. При изменении способа рендеринга OG или логотипа требуется изменить SOCIAL_PREVIEW_VERSION, чтобы создать новые превью с отдельными ключами.

## Полная проверка

GitHub Actions .github/workflows/audit-social-previews.yml каждое воскресенье в 03:20 по Москве (00:20 UTC) проверяет HEAD-запросом все OG-ключи из опубликованного манифеста. Также доступен ручной запуск workflow_dispatch. Ни сборка Astro, ни деплой, ни IAM-доступ на запись в S3 не требуются.

Неверный тип/размер, отсутствующий объект или недоступный манифест приводят к ошибке Actions, не к замалчиванию проблемы.
