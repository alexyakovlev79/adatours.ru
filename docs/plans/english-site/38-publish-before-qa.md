# Ada Tours EN: переводы → сайт → независимый QA по запросу

**Владелец: решение 05.11.2026.** Ежечасная независимая ChatGPT QA
`6aeb7f87aac08191afc7d34f35f32f66` отключена в Automations.

## Рабочая последовательность

1. **Переводчик** получает очередной пакет в уже созданной
   `i18n/translation-mass-staging`, переводит до 8 блоков
   и сохраняет один результат CAS `saved_for_review`.
   Не делать самостоятельный QA и не ждать чужого `ready`.
2. **Общая Astro-проекция** подставляет подписанные
   `review` и `ready` по исходному `stableId` и
   `blockId` в единую русскую модель. Проверяет source hash,
   Git blob receipt, полный состав пакета, provenance,
   целевое поле и отсутствие конфликтов. Если изменён
   русский текст либо блок ошибочен, сохраняет **только
   соответствующий** RU fallback. Прочие EN поля работают.
   Цены, медиа, маршруты, ID и связи берутся из общей базы.
3. **GitHub Pages** автоматически выкладывает полное
   `/adatours-en/en/` один раз в час при изменении
   `main` или staging SHA. При совпадении с прежним
   успешно опубликованным `translation-receipt.json`
   дорогой build пропускается. Ручной
   `workflow_dispatch` по-прежнему возможен.
   Deploy подтверждается конкретным Actions run и receipt.
4. **Независимая смысловая QA только по будущей ручной
   команде** Алексея. Правки хранят новую неизменяемую
   версию результата/receipt; автоматическая EN-сборка
   включает исправленный текст без повторного перевода
   или независимой копии сайта.

## Состояния и границы

`review` — перевод сохранён, независимый QA ещё не было;
`ready` — прошёл настоящую QA; `applied` — технически
валидные текстовые поля попали в конкретный build;
`deployed` — успешный Pages deploy.
`withheld` — точное поле не попало из-за несовпадения
source, Git blob, структурной ошибки или конфликта.

`publicationEnabled=false` у переводчиков сохраняется
как запрет записи в основную ветку; не является
блокирующим флагом для **отдельного noindex Pages**.
Сохранённые исходники и результаты не перезаписывать,
не создавать другую очередь, не форсировать ref.

Остаются технические QA сборки, проверки маршрутов,
форм, схемы, внутренних ссылок и валидности assets.
Это **не** независимая семантическая приёмка.
На индексируемый домен и новые hreflang/canonical
переключаться только отдельным релизом.
