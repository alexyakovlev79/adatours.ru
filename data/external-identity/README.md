## Формат и поиск

JSON — редактируемый источник; CSV — его табличное представление с исходными русскими заголовками. Каждый JSON содержит `columns` (имена полей), `headers` (заголовки), `rows` (массивы ячеек). Все ячейки — строки, пустая ячейка — `""`, даты — ISO `YYYY-MM-DD`. Такой формат сохраняет все столбцы и позволяет читать отдельные строки без загрузки электронной книги. Большие CSV могут отображаться на GitHub лишь частично: для полного чтения скачивать файл или читать его из checkout.

```python
import json
from pathlib import Path
root = Path('data/external-identity')
table = json.loads((root / 'ru-brasiltours.json').read_text())
index = json.loads((root / 'index.json').read_text())
row_number = index['by_entity_id']['country_brazil']
record = dict(zip(table['columns'], table['rows'][row_number]))
print(record['ru_url'], record['brasiltours_url'], record['match_status'])
```

После изменений JSON обновить CSV, индекс и контрольные суммы:

```sh
python scripts/export-external-identity.py
python scripts/export-external-identity.py --check
```

`manifest.stats`, даты среза и исходная методика описывают первоначальный аудит, а не постоянно пересчитываемый текущий сайт. При новом полном аудите явно обновить эти метаданные; при точечных внешних проверках сохранить дату и доказательство в соответствующей строке. Не менять старые snapshot HTTP/хеши на текущие наблюдения. Новые столбцы добавлять вместе в `columns`, `headers` и каждую строку.

## Как продолжать

1. Основной ключ — постоянный ID объекта adatours.ru; URL сверять с актуальным `src/lib/routes.ts` и точной записью `data/source-index/entries/<entityId>.json`.
2. Следующий этап: adatours.com, vipdeluxetravel.ru, vipdeluxetravel.com. Общая админка с brasiltours.ru указана Алексеем. Проверить URL/ID-модель на выборке и только затем расширять соответствия; смена домена сама по себе не доказывает существование страницы.
3. Затем находить внешние страницы каждого места, страны и программы. Разделять подтверждённую идентичность, функциональный/тематический аналог, публикацию об объекте и неподтверждённого кандидата. Фиксировать точный URL, доказательство, дату и статус.

## Применение к schema.org

Этот реестр подготовлен для будущей отдельной команды Алексея. **Не подключать его к JSON-LD и не расширять sameAs/hasMap автоматически.**

- Точная миграционная пара подтверждает закреплённый источник, но не заменяет проверку актуального содержания двух программ. Аналоги каталогов и пагинация не становятся `sameAs`.
- Профили компании относятся к `https://adatours.ru/#organization`, а не к каждой стране, месту или туру. Исключённые одноимённые компании не использовать.
- `hasMap` требует карты конкретного Place/офиса. Публикации о компании отделять для `subjectOf`; карточку ассоциации можно использовать как доказательство членства, сохраняя корректную модель `memberOf`.
- Архивные исходники без RU-страницы не публиковать. Плановый URL не является существующей страницей.
