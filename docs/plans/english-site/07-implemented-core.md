# RU/EN content overlay: implemented foundation

Дата: 28.10.2026. Исходный код изучен на `b1b14ed3a8abab9773053f836fed28c2ff77204f`.

## Что уже реализовано

`src/lib/i18n/content-overlay.mjs` — отдельное ядро для будущего build adapter. Оно не подключено к текущим Content Collections, не меняет русский сайт, не запускает переводчиков и не публикует английский сайт.

У блока есть постоянный `blockId`, семантическое поле из закрытого списка (`itinerary.text`, `title`, `media.alt` и т. п.), точный исходный текст, список зависимостей от общих фактов. Индекс массива, номер дня и хеш текста не используются как автоматически вычисляемая идентичность блока. `day` остаётся структурным значением; один стабильный блок может поменять позицию.

`SourceSnapshot.shared.facts` и `.media` остаются общими. `LocaleOverlay` содержит только тексты, provenance и редакторские статусы. Нельзя передать через него `priceFrom`, `id`, `route`, `media.src`, `hero`, произвольные JSON-пути или неизвестные ключи. Возвращаемые общие данные берутся только из актуального SourceSnapshot; overlay с неверным `entityId`/типом/языком отклоняется.

Функция `sourceFingerprints` отдельно хеширует тексты, факты и медиа. Проверка готовности производится адресно по каждому текстовому блоку и объявленным зависимостям. Новая WebP-фотография того же объекта не требует повторного перевода всех абзацев. Alt зависит от фактической идентичности фотографии (`/media/hero/subjectId`), а при замене объекта требует проверки. Цена в общем поле обновляется общим источником; текст с явно записанной ценой обязан зависеть от `/facts/priceFrom` и `/facts/currency`.

`word_exact` требует `fileId`, версии Word, SHA-256 документа, точного locator фрагмента и SHA-256 текста. Сборка проверяет эти значения по закреплённому реестру извлечённых фрагментов и требует точного сохранения текста, включая пробелы и пунктуацию. При изменении Word исходный английский текст сохраняется, но блок становится устаревшим. Сборка не скачивает Word по сети; актуальность закреплённого реестра проверяет отдельная подготовительная стадия.

`draft`, `review`, отсутствие перевода, изменение исходника, отсутствие Word evidence, неполный состав блоков и чужие/удалённые блоки запрещают сборку через этот API. `approved` требует записанную проверку смысла, голоса и фактов. `approval.approvedContentHash` привязывает проверку к точному тексту, полю, исходному evidence, зависимостям и provenance; правка текста или переназначение источника не может унаследовать старое одобрение. Даже успешный `readyForAssembly` означает только пригодность входа для будущего адаптера. Библиотека пока не подключена к сборке/деплою и не является действующим production gate. Статуса `published` в overlay нет: публикацию должен подтверждать независимый журнал релиза с SHA/deploy receipts.

`reconcileOverlay` сохраняет английскую/русскую редакторскую версию буквально и возвращает адресные причины устаревания. `applyTranslationPatch` сравнивает полный предыдущий хеш изменяемого блока, включая текст и approval/provenance. Если второй редактор успел изменить целевой блок, запоздавшая запись получает `TranslationConflictError`. Это локальная проверка: хранилище дополнительно обязано применить CAS SHA/версию документа. Ядро само не является распределённым lock/queue.

## Контракт

```js
const source = {
  schemaVersion: 1,
  entityId: 'tour_stable_id',
  entityType: 'tour',
  locale: 'ru',
  shared: {
    facts: { priceFrom: 1200, currency: 'USD' },
    media: { hero: { src: '/media/shared.webp', subjectId: 'place_stable_id' } },
  },
  blocks: [{
    blockId: 'arrival:paragraph', // из утверждённой карты блоков
    field: 'itinerary.text',
    text: 'Исходный русский абзац.',
    dependsOn: [],
  }],
};
```

Overlay имеет `entityId`, `entityType`, целевой `locale`, исходный `sourceLocale` и массив блоков. Каждый блок содержит `blockId`, `field`, `text`, `state`, `sourceTextHash`, `dependencyHashes`, `provenance`; у `approved` также обязательна запись `approval` с `approvedContentHash: translationApprovalHash(block)` после фактической предметной проверки.

`sourceBlockEvidence(source, blockId)` возвращает точный набор `sourceTextHash` / `dependencyHashes`, который работник получает при захвате. Не нужно пересчитывать и принимать свежие хеши только ради снятия `stale`: сначала требуется смысловое сопоставление новых исходников и утверждение нового результата.

Схемы: `data/i18n/schema/source-snapshot.schema.json`, `data/i18n/schema/locale-overlay.schema.json`. JSON Schema проверяет структуру, а код — полный набор идентичностей, зависимостей и хешей.

## Перед подключением к Astro

1. Создать стабильную sidecar-карту блоков для реальных MD. В текущем `src/content.config.ts` элементы `Tour.itinerary`, `contentBlocks`, `subsections`, `highlights` не имеют собственных стабильных ID. Присвоение ID нельзя подменить индексом массива или `day: 1`.
2. Составить полный извлекатель. Он должен включить body, title/lead/summary, все видимые пункты услуг и условий, FAQ, alt/hover/caption, SEO overrides и остальные выбранные посетительские поля. Само ядро не может обнаружить блок, который извлекатель забыл объявить.
3. Нормализовать смешанные поля текущей схемы. `Tour.route` и `itinerary.places` сейчас содержат русские строки; это не полноценные языконезависимые идентификаторы. Маршрут и географию следует ссылать на общие ID, а видимые имена получать из перевода сущностей. Аналогично `Excursion.duration`, `format`, `language`, отдельные факт-значения требуют нормализации/меток, а не бесконтрольного глубокого merge.
4. Разбивать смешанные Word + AI passages на отдельные стабильные текстовые сегменты. `word_exact` запрещает смешивать внутри одного блока исправленный Word и новый машинный абзац, называя весь блок точной цитатой. Обычный `applyTranslationPatch` также запрещает замену `word_exact` на `ai_translation`/`editorial`, даже с обычным CAS и QA. Законную минимальную адаптацию голоса или подтверждённое исправление Word должен выполнять отдельный master-reviewed маршрут: сохранить исходные fileId/locator/hash, конкретную причину и `authorityRecord`. Такой controlled override пока не реализован; это ограничение foundation, а не постоянный запрет на редакторское решение Анны/мастера. Обновлённый Word exact принимается с новой закреплённой ревизией, точным текстом, новым QA hash и CAS целевого блока.
5. Снабдить тексты с ценами, датами, включениями, гостиницами, питанием, режимом optional/included и ограничениями зависимостями. Код сравнивает объявленные зависимости, но не умеет доказать, что редактор перечислил их все или не изменил смысл prose. Для этого обязательна смысловая приёмка.
6. Адаптер должен собирать итоговую страницу по текущей структуре и `blockId`, используя только `assembleLocalizedContent`. При ошибке не добавлять страницу в EN sitemap/hreflang; политика удержания предыдущего безопасного релиза или снятия stale страницы определяется релизом. Нельзя подставлять русский текст на EN-URL.
7. Связать изменение RU/EN источника с очередью адресных задач. Ядро поддерживает оба направления, но не определяет само авторитетность параллельно изменённого Word/RU/EN: эту политику задаёт mapping/редакторский журнал. Независимые целевые правки не перезаписываются автоматически.
8. Слой хранения должен дать общий CAS, owner/token/generation/lease, idempotent submission и recovery, описанные в `docs/workflows/agent-swarms.md`. Эти функции отсутствуют в ядре, массовый рой пока не готов к запуску.

## Проверка

`node tests/i18n/content-overlay.test.mjs` — 22 теста пройдено (Node 24.22.1): изменение общих цен и медиа, точная Word provenance, стабильные ID после перестановки, отсутствие fallback, запрет неизвестных ключей, source stale, Word revision/text stale, approval hash binding, двухстороннее редактирование, CAS-конфликт, защита от старого source evidence и от подмены Word новым AI-текстом. Это синтетические фикстуры, а не переведённые туры Анны.

Обычный `node --test tests/i18n/content-overlay.test.mjs` в данной среде тоже завершился успешно на первой редакции, но вывел только одну агрегированную строку тестового файла; отдельный прямой запуск последней редакции дал детализированное подтверждение всех 22 сценариев. Полная Astro-сборка не запускалась: runtime сейчас не подключён, предметный риск ограничен библиотекой.
