# PageSpeed: измеряемые циклы ускорения

Журнал: https://docs.google.com/spreadsheets/d/1ipkbSCyD26_BfzMPP2mG-u8C52WUCTK9xiaPhGBgz7w/edit

Методика перенесена из реального журнала PrepCenter: отдельные прогоны, изменения, медианы; отчет повторного использования не считается новым измерением.

## Цикл

1. Вместе с Алексеем обсуждаем одну гипотезу, охват, ожидаемую метрику и условия отката.
2. Записываем P01 / P02… в Changes. Меняем только согласованное, сохраняем commit и успешный deploy.
3. На тех же контрольных URL проводим три независимых PSI-прогона отдельно для Mobile и Desktop. Все повторы сохраняем, не выбираем лучший результат.
4. Проверяем уникальность report ID / fetchTime, неизменность страницы, Lighthouse и условия устройства. ERROR / REUSED / DRIFT сохраняем, исключая из сводки.
5. Сравниваем медианы и диапазоны, проверяем возможные регрессии CLS/TBT. Δ Performance — пункты; Δ LCP/TBT — относительное изменение; при нулевом знаменателе процент не определен.
6. Обсуждаем с Алексеем результат и следующий шаг. Следующую оптимизацию автоматически не запускаем.

## Постоянные данные

- `data/performance/pages.json`: 25 контрольных страниц и типы. Детальные Country, Destination, Tour, Excursion и Case имеют самостоятельные шаблоны; каталоги проверяются по типам карточек. Редиректы, архив и 404 исключены. Соседние служебные страницы и пагинация относятся к тому же семейству шаблона, не ко всем отдельным URL сайта.
- `data/performance/runs/B00.json`: исходная серия после lazy load. Числа взяты из официальных PSI-отчетов; ссылки и даты сохраняются.
- `data/performance/summaries/B00.json`: проверяемая сводка, которую можно пересчитать локально.
- `data/performance/experiments.json`: состояние циклов, решения и связанные исходные данные.
- Google Sheets: PSI Runs — факты, Summary — формулы, Changes — гипотезы/решения/откат, Pages — выборка, Protocol — правила.

Точка B00 уже содержит lazy load. Замеров до этой правки нет, ее улучшение задним числом не вычисляем. Лабораторные PSI показатели не выдаем за полевую статистику CrUX.

B00 от 11.10.2026 содержит 150 VALID строк, 43 исключенных DRIFT и одну ERROR. После параллельной публикации тура HTML семи страниц изменился: их серии пересняты, а прежние отчеты сохранены. Итоговые контрольные HTML совпали с проверкой перед повторной серией. У неизменившихся страниц сохранена первая серия; deploy и версия указаны для каждого отчета отдельно.

### Бразилия и видео

`/brazil/` всегда отдельная строка для каждого устройства. Текущий HeroVideo включает видео на десктопе, но сохраняет постер для телефонов и reduced motion. В этой базе Mobile оценивает постер. Чтобы измерить цену видео, нужен отдельно обсужденный A/B цикл на **одном и том же устройстве** с video-on/video-off; разницу Desktop/Mobile нельзя считать эффектом видео.

## Команды

```sh
node scripts/pagespeed.mjs plan --cycle P01
node scripts/pagespeed.mjs snapshot --cycle P01 --output /tmp/P01-before.json
# Собственный API key задается в окружении; не сохранять ключ в Git или журнале.
node scripts/pagespeed.mjs collect --cycle P01 --version <deployed-commit>
node scripts/pagespeed.mjs summarize --cycle P01 --compare data/performance/runs/B00.json
node scripts/pagespeed.mjs summarize --input data/performance/runs/B00.json
```

`collect` требует `PAGESPEED_API_KEY`. Без ключа API в исходной сессии вернул quota=0, поэтому B00 собран через официальный интерфейс pagespeed.web.dev. Оба метода допустимы, но источник фиксируем и версии Lighthouse не смешиваем без пометки. UI одновременно создает два отдельных Lighthouse-измерения; один report ID можно использовать по одному разу на каждом устройстве.

Для свежего UI отчета Analyze получает нейтральные query-параметры `psi_cycle` / `psi_run`; URL остается канонической статической страницей. Отдельно сохраняем canonical URL и фактически запрошенный URL. Для API в параметр прогона добавляется устройство. Повторный fetchTime / report ID исключается, а не молча добавляется к выборке.

Числовые параметры ссылки калькулятора Lighthouse в DOM отчета сохраняют точность основных метрик (мс). UI diagnostics, включая LCP breakdown, округлены; они не обязаны складываться в моделируемый LCP. Не снятые поля оставляем пустыми: пустое не равно нулю. API сохраняет полный raw JSON локально в `data/performance/raw/`, а компактные метрики — в журнале. Не публиковать API ключи; raw отчеты не коммитить автоматически.

Коллектор сохраняет checkpoint после каждого результата и проверяет HTML до/после серии. При параллельном наполнении сайта фиксируем deploy и контрольные SHA-256; изменившиеся страницы измеряем заново. Предварительная проверка версии по SHA не гарантирует, что удаленный PSI попал на ту же CDN копию: такую неопределенность указываем явно.

При заполнении Sheets добавляем строки без перезаписи старой истории. В Summary копируем формулы на новый этап, меняем этап в A и эталон в N; фильтры включают только VALID. Новые строки Summary и PSI Runs должны находиться внутри диапазонов формул; текущий резерв — до строки 1995. При расширении журнала расширяем диапазоны во всех формулах вместе.
