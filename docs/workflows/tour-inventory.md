# Актуальная опись туров Drive и сайта

Читаемая опись: [`docs/audits/tour-inventory.md`](../audits/tour-inventory.md).
Редактируемый реестр: [`data/audits/tour-inventory-drive-20261009.json`](../../data/audits/tour-inventory-drive-20261009.json).

## Что означает статус

Опись учитывает отдельно программы/варианты Drive, файлы и Tour ID сайта. Несколько именованных программ могут соответствовать одному Tour ID; один Word может соответствовать активной странице и её архивному дублю. Это разные единицы учёта, их количества не складываются.

Повторные копии одной именованной программы объединены и сохраняют все ссылки. Другую длительность или существенно другой маршрут считаем отдельным вариантом. Другой год/цена сами по себе не означают новую программу. Не переносить статус активного тура на похожую программу автоматически.

`entityIds` — подтверждённые соответствия. `candidateEntityIds` — подсказки, которые не влияют на закрытие очереди. Подтверждённая активная замена из `duplicateOf` архивного реестра тоже считается соответствием.

Наличие активной страницы и проверка содержания — независимые факты. Опись не подтверждает перенос всех услуг/дат/цен и не подтверждает deploy по наличию MD. Публикация завершается обычным успешным Actions build/deploy; состояние исходников описи отражается в `main`.

## После создания или восстановления тура

1. Найти программу по короткому ключу `P001`–`P168`, стабильному `id` или точному Drive file ID. Ключи не перенумеровывать; новым программам выдавать следующий свободный номер. Проверить всю программу, длительность, маршрут, формат обслуживания и даты; кандидаты не являются подтверждением.
2. При создании нового тура добавить его stable ID в `entityIds` соответствующей программы. Если соответствие уже есть, сохранить его; не переименовывать ID программы, Tour ID или Drive file ID.
3. Восстановить архив только в рамках явно заказанной работы, по `archive.md`. Наличие файла на 2027 год само по себе архив не снимает. Архивный дубль с активной заменой не восстанавливать как второй тур.
4. После проверки содержания обновить `work`: `not_started`, `in_progress`, `needs_update`, `reviewed` или `done`. Записать конкретную заметку и дату `updatedAt`; генератор их не стирает. `done` допустим только после сверки программы и успешной публикации. Уже существующая активная страница сама не переводит `work` в `done`.
5. Синхронизировать source-index обычным workflow. Выполнить `node scripts/sync-tour-inventory.mjs --apply` и включить реестр/генерируемый Markdown в тот же логический commit.

Проверка без записи:

```sh
node scripts/sync-tour-inventory.mjs --check
node --test tests/tour-inventory.test.mjs
```

GitHub Actions `Update tour inventory` пересчитывает Markdown после изменения туров, каталога, архива или редактируемого реестра в `main`. Он обновляет только опись и не меняет программы, архивные статусы или соответствия. Запуск `workflow_dispatch` доступен для ручного пересчёта. Если другие чаты изменили `main`, workflow повторно читает новую ветку и не выполняет force push.

## После новой сверки Google Drive

Drive зафиксирован снимком от 09.10.2026, а состояние сайта читается из текущего репозитория. Генератор и сборка сайта не обращаются к Drive.

По отдельному запросу перечитать указанную папку и все её подпапки. Сопоставлять файлы по Drive ID, проверять даты изменений и содержание. Для новых копий добавить файл в существующую программу; для нового варианта добавить новую программу со стабильным ID. Если файл перемещён, обновить раздел, не создавать дубль программы. Исчезновение файла или отсутствие тура в этой папке не является основанием для удаления/архивирования сайта.

Сохранять все прежние ссылки, подтверждённые соответствия и историю `work`. У изменённой программы отметить `needs_update` до сверки текста; не закрывать её по совпадению названия. После полной сверки обновить `driveSnapshotAt`. Значения `modifiedTime` и `textSha256` помогают определить, какие документы изменились.

Ручные изменения генерируемого Markdown запрещены: он полностью пересобирается. Новые пометки и связи сохраняются в JSON. Не сбрасывать реестр при следующем проходе.
