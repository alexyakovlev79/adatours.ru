## 1. Решение владельца и пределы прежних этапов

Алексей указал, что ранее переведённые URL и меню вновь выводятся
по-русски. Требование: всё уже переведённое показывать по-английски,
непереведённое оставлять по-русски. Изображения, логика, связи и другие
одинаковые для языков вещи должны оставаться общими. Подготовка роя
предыдущего чата сохраняется; сначала исправляется действующая выкладка.

Этот контракт уточняет [32-full-canonical-en-stage.md](32-full-canonical-en-stage.md)
и отменяет скрытие готовых текстов до готовности целой страницы.
Он также заменяет промежуточное решение
[31-en-staging-translation-precedence.md](31-en-staging-translation-precedence.md)
из main `57020af`: вывод 22 страниц демонстратора с каталогом только
трёх Tour и отдельным `/en/tours-ru/` больше не является целевой сборкой.
Оба документа и прежние доказательства сохраняются как история.

Текущий `/en/tours/` использует полный канонический каталог
(353 активных Tour на момент этого этапа), обычные фильтры и пагинацию.
Каждый канонический URL сохраняет полную структуру соответствующей
страницы. Готовые EN-поля подставляются внутрь общего шаблона;
непереведённые соседние поля не препятствуют их выводу.

## 2. Одна база данных и общие шаблоны

- Исходный Astro content loader читает существующие RU MD из `src/content/`.
  Для отдельной EN staging-сборки он создаёт проекцию в памяти.
  Файлы исходного контента не изменяются и не копируются в `adatours-en`.
- В проекции разрешена замена только известных текстовых слотов по stable ID.
  Числа, цены, валюта, media URLs, идентификаторы, маршруты, длина и порядок
  структурных массивов, ссылки и связи остаются из текущей общей записи.
- Все потребители коллекций — страницы, карточки, каталоги, общие
  Tour/Excursion/Country/Destination layouts — получают ту же проекцию.
  У отдельной EN-версии нет независимого каталога либо владельца связей.
- Старые source-bound EN overlays и Word evidence переиспользуются.
  Для Tour проверяется утверждение и актуальность каждого блока;
  отсутствующий/устаревший блок использует RU без потери остальных.
  У старых Excursion/географических overlays пока один Git blob receipt:
  несоответствие держит этот overlay на RU до адресного обновления.
- Семантические исходные значения, используемые общей логикой
  фильтрации/ранжирования, не меняются ради отображения. Например,
  `format` остаётся общим, а английская подпись хранится как
  `_i18n.formatLabel` в производной модели.
- Английский UI берётся из единого словаря и коротких общих подписей.
  HTML-проход переводит только известные текстовые узлы/подписи;
  он не переписывает программы, скрипты, коммерческие факты или медиа.
- Собранные общие страницы перемещаются в `/en/<canonical-path>/`,
  внутренние ссылки остаются внутри этого дерева. Медиа продолжают
  обслуживаться через `img.adatours.ru`, JS/CSS — общие assets.

Не вводится второй Tour MD, копия ценовой таблицы как новый источник
истины или второй набор фото. Дополнительные локализованные HTML
являются результатом сборки, а не независимыми редактируемыми записями.

## 3. Реализация и отчёт сборки

Основные точки реализации:

| Путь | Назначение |
| --- | --- |
| `src/lib/i18n/shared-content-loader.mjs` | Проекция готовых EN-полей поверх текущего канонического entry, актуальность и RU fallback |
| `src/content.config.ts` | Подключение проекции к существующему glob loader, без отдельных EN коллекций |
| `src/lib/i18n/shared-ui-locale.mjs` | Общий выбор языка интерфейса и точные известные RU/EN подписи |
| `src/lib/i18n/shared-ui-html.mjs` | Применение известного UI-словаря к общему HTML, включая запасную оболочку |
| `scripts/i18n/prepare-en-pages-site.mjs`, `ru-fallback.mjs` | Полная общая EN staging-сборка без подмены каталога демонстратором |
| `scripts/i18n/verify-ru-fallback-output.mjs` | Проверка полных маршрутов, переводов, assets и staging-ограничений |
| `tests/i18n/shared-*.test.mjs` | Адресные проверки проекции/UI, сохранности общих данных и fallback |
| `.github/workflows/en-pages-reusable-deploy.yml`, `i18n-en-github-pages-check.yml` | Один build-контракт `EN_SHARED_CONTENT=1`, проверки и receipts |

Проекция включается только при `EN_SHARED_CONTENT=1` в разрешённом
контексте отдельной EN staging-сборки. Обычный RU build использует
исходный loader. Прежний private pilot остаётся источником текстов и
доказательств, но не заменяет основные полноразмерные страницы.

Каждая сборка создаёт `.astro/ada-en-shared-content.json`; подготовка
Pages переносит его в `translation-receipt.json`. В отчёте фиксируются
канонический SHA, stable IDs, количество применённых полей, состояния
translated/partial/stale/invalid и причины fallback. CI сохраняет
`en-shared-translation-receipt`. Отчёт описывает реально применённые
тексты; существование исходного перевода само по себе не доказывает его
публикацию.

Принятый массовый Rio b001 подключён к этой проекции только для чтения:
workflow выбирает immutable snapshot `691306df7cdae1e1cb899cbac2bfc4dcbe781230`
в соседний `translation-preview`, читая только индекс, `state/1a.json`,
`jobs/1a.json` и exact result JSON. `EN_ACCEPTED_TRANSLATIONS_ROOT`
указывает на этот временный checkout; новые копии переводов в основном
репозитории не создаются.

Проверяются detached SHA, состояние ready, все шесть независимых QA checks,
acceptedBlobSha и фактический Git blob результата, исходные SHA256/Git blob,
тот же выбранный Word и его revision. Восемь готовых блоков имеют приоритет
над прежним пилотом; четыре формулировки обновлены, уникальное покрытие Rio
остаётся 52 поля. Receipt сохраняет `acceptedMassSnapshot` и per-entry
`acceptedMass` с количеством применённых блоков и изменённых текстов.
`ready` в массовой staging не равно опубликованной странице. Включение этих
восьми блоков подтверждено полной EN preflight-сборкой и опубликованным
receipt первой успешной Pages-выкладки #41592607214.
`publicationEnabled=false`, `releaseEligible`, очередь и результаты
не меняются данным исправлением.

### Доработки после полной сборки

- Astro 7.3.4 возвращает Markdown body через `parsed.content.trim()`.
  Approved hashes относятся к точному исходному body. Loader сохраняет raw
  body при чтении текущего Markdown и принимает только равенство raw либо
  raw.trim(); source/approval hashes остаются прежними. Изменение самого
  источника продолжает давать fallback. Этот случай воспроизведён на трёх
  реальных Tour: 169 полей до исправления, 172 после него.
- Detail metadata использует уже подготовленные `title/name` и `lead/summary`,
  без русского суффикса из RU SEO helpers. Непереведённые значения сохраняются.
- Клиентские сообщения карт используют тот же UI-словарь. Provider preference,
  координаты, порядок точек и данные общие. URL pop-up берутся из canonical
  JSON и проходят общий EN rebasing; поиск сопоставляет EN Pagefind URL с
  canonical GEO key, сохраняя английский результирующий href.
- У динамического UI-шаблона количества дней разрешены только числовые дни;
  неизвестная строка «Маршрут путешествия» не превращается в частичный перевод.
- Общий динамический интерфейс использует английские подписи меню, селекторов,
  видео и формы. Известные словарные подписи распознаются без учёта регистра;
  неизвестные слова не переводятся по приблизительному совпадению.

## 4. Приёмка и подтверждение публикации

1. Полный каталог и все канонические страницы остаются доступны на
   обычных `/en/`-маршрутах; нет подмены трёхтуровым showcase и
   обязательного перехода в отдельный `/en/tours-ru/`.
2. Меню, кнопки, известные подписи фильтров и каталог `/en/tours/`
   используют общий английский UI. Отсутствующие переводы сохраняют RU.
3. Готовые поля трёх Tour, 11 Excursion, трёх Country и четырёх Destination
   применяются при совпадении источника; частичные/устаревшие поля
   отдельно отражены в receipt. Изображения, цены и связи не теряются.
4. Переходы, фильтры, пагинация, поиск и общая оболочка работают с полной
   базой. Языковые атрибуты соответствуют фактическому тексту, а не
   одному префиксу URL.
5. Проверен обычный RU build; отдельный EN HTML сохраняет noindex,
   не включает живые формы, аналитику, публичные canonical/hreflang/JSON-LD.
6. Перед merge нужны успешные соответствующие CI, затем отдельный
   успешный EN Pages run и чтение опубликованных типовых URL/receipt.
   До этого статус — «подготовлено», а не «выложено».

### Приоритет текущего поручения

Сначала подключить существующие английские тексты к общим полноценным
шаблонам и источникам: готовый EN используется для соответствующего поля,
отсутствующий перевод сохраняет RU. Не терять изображения, разделы,
фильтры, связи, коммерческие факты и другие элементы общей страницы.
Никакой второй базы цен/медиа/MD в `adatours-en`; этот репозиторий остаётся
минимальным вызовом общей публикации. Не восстанавливать урезанные
демо-страницы как замену полного сайта.

При исправлении вывода не менять leases, результаты и gates массовой
очереди, не пересоздавать seed, не переводить заново принятые блоки и не
запускать рой вместо задачи текущей выкладки. Возможности worker до
60 пакетов/чат, lease 90 минут и renew/checkpoint 20 минут сохраняются.
Новые массовые результаты и их публикация остаются отдельной операцией
по существующим immutable receipts и source hashes.
