# Рой Ada Tours: мобильные обрезки главных фотографий

Команда запуска любого одного Work-чата:

> Рой ADA: мобильные hero. В alexyakovlev79/adatours.ru прочитай docs/tasks/WORK_ADATOURS_MOBILE_HERO_SWARM_20261023.md на ветке feature/mobile-hero-swarm-20261023. Работай по ней: резервируй один готовый пакет, обрабатывай, сохраняй и автоматически бери следующий, максимум 12 пакетов.

## Область и готовая очередь

Ветка работников: `feature/mobile-hero-swarm-20261023`. Корень: `data/media/hero-mobile-swarm-20261023/`. Манифест `manifest.json` заморожен; его не переписывать при выдаче заданий. `jobs/bNNN.json` — неизменяемые задания; `packets/bNNN.json` — независимый резерв и результат пакета; `results/` и `receipts/` — итоговые решения и подтверждения загрузки. Один оригинал назначен только одному пакету; все его использования перечислены внутри задания. Не выбирать задания вручную и не создавать новые пакеты.

Проверенная опубликованная сборка: commit `197b0b09286653ba3cbb8881306040e97caef39b`, успешный Pages run `39848320053`, архив SHA-256 `295f7c0be6c348d8bbfb0a457d8117bf85e404b4d495109c1d5f24a8f447721d`. SHA-256 — контрольная сумма содержимого файла. Последующие до `a4ec2518a8705c1a3a277caa13637ef8c3c20588` изменения затрагивали только отчеты и журналы, не страницы или фотографии.

Из 6134 сформированных HTML-файлов найдены 5629 активных страниц с главной фотографией, 2066 уникальных исходных путей. Полностью готовые12 исходников и одно общее фото команды сохранены в `retained.json`; 2053 исходника образуют206 пакетов:205 по10, последний3. 35 архивных использований, включая26 источников только в архиве, исключены. Видеокадры, галереи и карточки в эту очередь не входят. Фото в неактивном шаблоне запасного показа видео входит; первый кадр ролика обрабатывается отдельно и здесь не меняется.

У частично покрытого прежними экспериментами исходника в `jobs[].usages` перечислены только еще не покрытые использования; `retainedUsageIds` и `existingCrops` сохраняют предыдущую работу. Нельзя удалять старые готовые мобильные кадры. На главной здесь обрабатывается только ее hero; другие карточки не изменяются.

## Один проход

1. Сохрани уникальный `ownerId` на весь чат. Для новой партии создай новый `token`. Через диспетчер зарезервируй **один готовый пакет**. Сохрани `packetId`, `generation`, `expiresAt`, исходные данные и весь ответ локально вне Git. Будущие пакеты не резервировать.
2. Скачай исходники, проверь известные контрольные суммы и размеры, просмотри каждый оригинал и прежние удачные обрезки. До выбора фокуса ничего не считать рассмотренным автоматически.
3. Запиши решения по всем требуемым использованиям. Один проверенный кадр можно переиспользовать для одинаковой геометрии; разные профили и ручные фокусы нужно проверить отдельно. Не требуется вручную смотреть1400 одинаковых страниц одного источника: сгруппируй по профилю, геометрии и ручному фокусу, проверь представителей и случаи с длинным текстом.
4. Запусти пакетную обрезку. Просмотри все превью повторного `object-fit: cover`, то есть обрезки готового файла внутри реального блока, и проверь живую геометрию нескольких характерных страниц. При длинном заголовке блок может быть выше минимальной высоты; добавляй соответствующий `geometry.previewSizes` в локальную копию задания для симуляции, не меняя замороженный файл. Запиши `visualQA` для каждого решения только после просмотра. QA — проверка качества.
5. Только после готовности файлов получи индивидуальный временный доступ и загрузи файлы напрямую в хранилище. Каждый файл скачать обратно, сравнить размер и SHA-256. Действующий объект с иными байтами не перезаписывать.
6. Одним `submit` сохрани все результаты пакета вместе с подтверждениями. Диспетчер атомарно коммитит три текстовых файла: состояние, результаты, подтверждения. После успеха автоматически бери следующий пакет с новым `token`, пока не выполнено12 проходов или не осталось свободных заданий.

Работники не меняют `main`, кроме индивидуального **публичного** запроса допуска к хранилищу; не меняют общий `src/data/media/direct-s3-uploads.json`, компоненты сайта, статьи, старые очереди и измерения скорости. Бинарные оригиналы, кадры, превью и приватные ключи — вне Git. Публикация — отдельный мастер после сведения результатов.

## Правила выбора кадра

Полная политика: `docs/workflows/mobile-hero-crops.md`. Сначала удачный ручной фокус **конкретного блока**. Далее головы/лица людей и животных; руки, тело, хвост, крылья могут выходить за край. Совместное частичное изображение двух персонажей допустимо. Если убедительного фокуса нет, центрировать видимую полосу; не отклонять фотографию только из-за невозможности вместить весь объект.

Не запускать нейросетевую перерисовку или автоматический детектор вместо визуального решения. По умолчанию — полная исходная высота, ширина `floor(height*3/4)`, выбранное горизонтальное смещение. `photo-lead` — отдельный короткий блок: нужен явно выбранный прямоугольник, нельзя без проверки применять вертикальный3:4. `preserve-full-image` — групповое фото команды с сохранением всех краев, уже исключено из новой обработки.

CSS — каскадные таблицы стилей. Процент `object-position` выравнивает свободное пространство, а не задает координату лица: `left=(sourceWidth-visibleWidth)*position`. Для готового кадра можно использовать `center top`, `center bottom` или проверенный процент. Новый файл выбирается только до479 CSS-пикселей; выше остается горизонтальный оригинал. Видео и отложенная загрузка сохраняют прежнее поведение.

## Подготовка локального инструмента

Нужен Node.js24 или новее. Используй отдельный checkout ветки роя, не чужую рабочую директорию. Загрузи программы из **точного** рабочего ref. В проекте отдельная закрепленная зависимость `sharp-hero-crops` указывает на Sharp0.35.5; обычный Sharp сайта остается прежним. Для облегченного рабочего окружения зависимости можно установить вне checkout: `npm install --prefix /tmp/hero-tooling sharp@0.35.5`, затем подключить этот `node_modules` через локальную символическую ссылку. Не менять `package.json` или lock-файл проекта; версия Sharp для обработки проверяется программно. Проверки инфраструктуры: `npm run test:mobile-hero`.

Исходный файл задания сохраняй вне Git, например `/tmp/hero-worker/b001/jobs.json`. Для чтения с сохранением байтов используй Git checkout/fetch или GitHub-коннектор; большой ответ с1400 использованиями не печатай целиком в чат. Для выбора фокуса сначала скачай и просмотри оригиналы; используй режим осмотра инструмента:

```sh
node scripts/mobile-hero-crop-batch.mjs --mode inspect --packet /tmp/hero-worker/b001/jobs.json --out /tmp/hero-worker/b001/inspect --sources /tmp/hero-worker/sources
```

Решения `decisions.json`:

```json
[{"assetId":"ТОЧНЫЙ_ID_ЗАДАНИЯ","sourceSha256":"64_HEX_ИЗ_ОСМОТРА","recipes":[{"profile":"compact","usageIds":["ТОЧНЫЙ_USAGE_ID"],"left":200,"objectPosition":"center top","focusReason":"Голова птицы в правой части; крылья и хвост допустимо обрезаны.","inspection":{"sourceViewed":true,"notes":"Просмотрен полный оригинал и прежний ручной фокус блока."}}]}]
```

`usageIds` должен охватить требуемые использования; для многих одинаковых страниц формируй массив из задания программно. Для короткого блока передавай `crop:{left,top,width,height}`. Увеличение разрешения запрещено; инструмент создает480,720 и нативную ширину только там, где они помещаются, формат WebP, качество78. Файлы получают стабильные имена по исходнику и рецепту; повтор не создает новую версию без изменения байтов.

```sh
node scripts/mobile-hero-crop-batch.mjs --packet /tmp/hero-worker/b001/jobs.json --decisions /tmp/hero-worker/b001/decisions.json --out /tmp/hero-worker/b001/prepared --sources /tmp/hero-worker/sources
```

Результат: `result.json`, `gallery.html`, контактные листы и `upload-batch-N.json` максимум по30файлов. Статус `PREPARED` означает только технически подготовленный файл. Просмотри контактные листы и отдельные спорные превью; это не физические телефонные скриншоты. При необходимости исправь фокус и пересоздай до загрузки. Формат `result.items` затем переводится в результаты диспетчера, добавляя ручную проверку и подтверждения загрузки.

## Вызов диспетчера из Work

Сначала найди актуальные инструменты GitHub-коннектора. В `functions.exec` можно загрузить portable-модули следующим способом; здесь нет Node-зависимостей:

```javascript
const repository_full_name='alexyakovlev79/adatours.ru';
const ref='feature/mobile-hero-swarm-20261023';
const unwrap=r=>{if(r.isError)throw Error(JSON.stringify(r));return r.result??r.structuredContent??r;};
const paths=['scripts/mobile-hero-swarm-core.mjs','scripts/mobile-hero-swarm-remote.mjs'];
const [a,b]=await Promise.all(paths.map(path=>tools.mcp__codex_apps__github_fetch_file({repository_full_name,path,ref})));
const names=['SWARM_ROOT','SWARM_BRANCH','SWARM_REPOSITORY','packetPath','checkPacketId','checkIdentity','hashString','canonical','sha256','digest','validatePacket','stateRecord','activeLease','requireLease','take','renew','release','requeue','mergeReceipts','validateReadyResult','previousSubmission','saveResults','summarize'];
const core=new Function(unwrap(a).content.replace(/^export /gm,'')+';return {'+names.join(',')+'};')();
const swarm=new Function(unwrap(b).content.replace(/^export /gm,'')+';return runMobileHeroSwarm;')();
// В следующих вызовах восстанови эти модули; identity и текущий lease сохраняй.
const ownerId='hero-'+Date.now().toString(36)+'-'+Math.random().toString(36).slice(2,14);
const token='lease-'+Date.now().toString(36)+'-'+Math.random().toString(36).slice(2,14);
const response=await swarm(tools,core,{action:'claim',ownerId,token,pass:1});
store('heroWorker',{ownerId,token,pass:1,packetId:response.packet?.id,generation:response.packet?.generation});
store('heroPacket',response.packet);
text({status:response.status,lease:response.packet?.lease,packetId:response.packet?.id,
  jobs:response.packet?.jobs.map(j=>({id:j.id,source:j.source,usages:j.usages.length}))});
```

Сохрани идентификаторы **также локально**: память инструмента может исчезнуть. После обрыва повтори `claim` с прежними `ownerId`, `token` и **`packetId`**, не забирай новую партию вместо поиска старой. Если резерв истек, перечитай состояние и получи новое поколение; старое `generation` больше не имеет права писать.

Каждые20минут, а также перед длительной загрузкой:

```javascript
await swarm(tools,core,{action:'renew',packetId,ownerId,token,generation});
```

Диспетчер обходит всю очередь от распределенной начальной позиции. `busy` означает, что незавершенные пакеты заняты; `exhausted` означает, что весь список пакетов завершен, но это еще не означает отсутствие `review/retry`. Не считать очередь пустой по первому занятому пакету. Для сводки `status` читать страницы `from/count`, переходя по `nextFrom` до конца.

## Загрузка и атомарное сохранение

Точный протокол: `docs/workflows/direct-s3-upload.md`, раздел параллельных сеансов. Сначала все обрезки и визуальные проверки, затем `media-work-session.mjs init`. Создай через GitHub-коннектор **один** новый файл `main:data/media/upload-session-requests/<requestId>.json`, только публичные поля запроса, без `[skip ci]`. Приватный ключ не публиковать. Найди запуск `issue-media-upload-token.yml` по точному SHA коммита, проверь `requestId`, получи зашифрованный пакет и загрузи максимум30файлов за вызов `upload`. Не использовать общий `upload-session-request.json` параллельно. Для нескольких частей объединяй подтверждения по ключу, отвергая разные байты одного ключа.

Перед `submit` составь объект с неизменяемым `submissionId`:

```javascript
const request={action:'submit',packetId,ownerId,token,generation,
  submissionId:'submit-'+packetId+'-'+token,
  results:prepared.items.map(item=>({...item,status:'ready',
    recipes:item.recipes.map(recipe=>({...recipe,
      visualQA:{sourceViewed:true,previewsViewed:true,notes:'Конкретно: какой смысловой объект сохранен, на каких геометриях проверен, какая частичная обрезка допустима.'}}))})),
  receipt:mergedVerifiedReceipt};
// request нужно сохранить локально до вызова; утверждения QA заполнять после реального просмотра.
const response=await swarm(tools,core,request);
text({status:response.status,commit:response.commit,packetId});
```

В `results` не нужны локальные `file`, `previews` и `originalPreview`: удаляй их перед сохранением; размеры, ключи, хеши, параметры обработки и решения должны остаться. `ready` требует Sharp0.35.5, качества78, координат в границах исходника, покрытия всех нужных использований, визуального заключения и точного подтверждения каждого файла. Проверенные старые кадры из `existingCrops` разрешено переиспользовать после проверки соответствующей геометрии и SHA-256.

Ошибка чтения/загрузки: несколько адресных повторов, затем конкретный `retry`, а не выдуманное `ready`. `review` — требуется решение о композиции/неподдерживаемой геометрии; `stale_source` — исходник изменился. У этих результатов обязательна `note`, они не подключаются к сайту. Не останавливай весь рой из-за одной фотографии.

`saved`, `saved_after_uncertain_response`, `already_saved` — успешное сохранение на рабочей ветке. Потерян ответ: повтори **тот же payload и submissionId**, не создавай второй итог. Конфликт параллельного коммита: диспетчер перечитает свежую ветку, проверит резерв и сохранит чужие изменения. Запрещены force push и полный откат ветки.

При длительной работе можно вызвать `checkpoint` с уже готовыми подмножеством результатов и их подтверждениями, отдельным устойчивым `submissionId`. Принятые готовые результаты не переделываются новым владельцем. После восстановления дополни их оставшимися; финальный `submit` должен учесть все10заданий с учетом уже сохраненных. Если уходишь до завершения — сохрани checkpoint и вызови `release` только своего резерва. При обрыве через60минут пакет можно перезанять, checkpoint сохраняется.
