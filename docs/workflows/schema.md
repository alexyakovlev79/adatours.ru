# Schema.org: единая разметка всех страниц

## Контракт

`BaseLayout.astro` один раз рендерит основной slot. Для явно переданных breadcrumbs JSON-LD-цепочка всегда начинается с «Главная»; дочерняя страница пагинации добавляет свой номер последним уровнем. `page-schema.ts` загружает данные коллекций, `structured-data-html.mjs` читает фактически выведенные блоки, `structured-data.mjs` формирует один связный JSON-LD `@graph` в исходном HTML. Клиентский JavaScript и внешние запросы для разметки не нужны. Старые отдельные JSON-LD дочерних страниц поглощаются; дубли Person/Trip не остаются. При переносе сайта root/base меняются через существующие SITE_ORIGIN/SITE_BASE.

| Страница | Главные сущности и источник |
|---|---|
| Все содержательные страницы | Organization + TravelAgency, WebSite, конкретный тип WebPage, BreadcrumbList, ImageObject |
| Тур, экскурсия | TouristTrip, provider, маршрут ItemList/Place, численно заданные дни Trip/subTrip; поля текущей записи |
| Цена «от» | Offer + PriceSpecification.minPrice; только опубликованная положительная округлённая цена и валюта при наличии видимого блока цены |
| Страна | CollectionPage → Country + TouristDestination; Антарктида → Place + TouristDestination |
| Место | CollectionPage → TouristDestination; город дополнительно City; containedInPlace → страна |
| Интерес | CollectionPage → DefinedTerm → DefinedTermSet; списки фактических блоков |
| Каталог, включая пагинацию | CollectionPage → ItemList; только карточки текущей HTML-страницы, их порядок и позиции |
| Команда | ProfilePage → Person; роль, организация, опубликованная экспертиза и проверенные профили |
| Кейсы, статьи | Article, headline, publisher; даты/автор только из явных данных, автор только при отображении на странице |
| О компании, контакты | AboutPage / ContactPage → Organization |
| DMC, для агентств, MICE, делегации, VIP, multi-country | Service; тип услуги закреплён в модуле. VIP и multi-country используют один Service с canonical корня на всей серии пагинации; география берётся из полного соответствующего набора туров |
| Отзывы | Review и ItemList только для реально показанных текста и автора; без выдуманных звёзд |
| FAQ | FAQPage/Question/Answer из видимых FAQ основного шаблона **и** SEO-GEO раздела; H2/H3, без выдуманных ответов; ссылки внутри ответа становятся mentions |
| Документы, 404 | WebPage с реальными метаданными |
| Старые URL | Технический WebPage + WebSite, связь с целевой страницей; canonical/редирект/noindex сохраняются |

## Дополнительный SEO-GEO семантический граф (16.10.2026)

Единственным источником дополнительных связей является **одобренный** `data/seo-geo/articles/<canonical>/index.md`, уже отображаемый через `SeoGeoSection.astro`. Новый `src/lib/seo-geo-schema.mjs` анализирует `headingHtml`/`bodyHtml`/`lead` этой же версии статьи при сборке. Страница с SEO-GEO статьей получает внутри единого `@graph`:

- `WebPage.hasPart → Article` с `@id = canonical#seo-geo-article`, `isPartOf` текущей страницы, издателем Ada Tours, видимым заголовком, вводной и адресом фактического якоря статьи; **без** второго canonical, фиктивного автора или даты публикации.
- `Article.hasPart → WebPageElement` для H2 и вложенных H3, с `isPartOf`, `name`, коротким описанием из видимого абзаца и якорным URL, когда он существует. Ограниченный размер графа, повторные ссылки дедуплицируются.
- `Table` для каждой реально выведенной сравнительной таблицы: заголовки колонок, текст фактических ячеек, ее раздел и упомянутые канонические объекты. Числовые данные не домысливаются; статические и вычисленные значения читаются из готового HTML.
- `FAQPage/Question/Answer` из реально присутствующих H2/H3-вопросов и ответов статьи вместе с FAQ основного шаблона. Ссылки ответа дают `Answer.mentions`, заголовки вопросов получают URL своих существующих якорей.
- `Article.mentions`, `WebPageElement.mentions`, `WebPage.significantLink` по внутренним ссылкам. `about` и обратные `subjectOf` назначаются лишь основной сущности страницы и тем объектам, которые прямо названы в заголовке фрагмента и имеют явную ссылку в нем. Случайное упоминание не создает `subjectOf`.
- У страны `containsPlace` содержит только действующие места **своей** страны, фактически упомянутые ссылками в ее статье; дочерние места сохраняют `containedInPlace`.
- Для конкретных статических `multi-country` и `VIP + страна + интерес` каталогов по каноническим slug формируется точный `Service` с `areaServed`, `provider`, тематическим `category` при явной теме и ссылкой из `WebPage.about`. `ItemList` продолжает описывать исключительно фактически показанные карточки.
- У тура для `subTrip` названия мест дня связываются с опубликованными Destination **только по однозначному совпадению** с заранее записанными `destinations` тура; иначе остается обычная подпись `Place`.
- Корпоративные `sameAs` и `Organization.subjectOf` дополняются **исключительно подтвержденными** профильными и редакционными URL с высокой уверенностью в `data/external-identity/external-profiles.json`, без кандидатов, других одноименных фирм, рейтингов и предположений о датах.
- `Country`, `Destination`, `Tour` и `Excursion` получают `sameAs` на `adatours.com` только по строгим записям со статусом `confirmed` из `data/external-identity/adatours-com-correspondences.json`, с проверкой стабильного ID, типа, RU canonical и внешнего домена. Непроверенные аналогичные программы и каталог-подборка не считаются идентичными страницами.

Для архивной/noindex страницы, страницы пагинации, отсутствующего SEO-GEO материала и нерелевантной ссылки дополнительные сущности не создаются. Нельзя создавать `subjectOf` из любого случайного анкора. Определенная по ссылке сущность должна быть опубликована, иметь действующий canonical и точный стабильный ID. Производные каталоги без самостоятельной сущности размечаются как WebPage, а не выдуманный Tour/Product. Во все графы входят только локально сгенерированные факты и подтвержденные внешние профили.

## Обновление содержания

Новый тур, место, экскурсия или другая запись, проходящая штатный шаблон, автоматически получает разметку. Отдельный JSON вручную не добавлять. Страны, темы, места, каталоги и фотографии берутся из текущих данных/ссылок. Резерв без опубликованной страницы не становится внутренней ссылкой в графе. В каталогах сохраняются действующие правила сортировки; полный список не подменяет видимую страницу пагинации.

Архивные страницы сохраняют сущность программы, но не Offer. Они остаются `noindex, nofollow` и не попадают в публичные списки. Preview остаётся `noindex`; внедрение разметки не снимает это ограничение. Организация имеет стабильный production @id, а страницы, фото и website используют текущий origin/base.

Цены 0/null/без валюты/«по запросу» не считаются бесплатными. Не добавлять InStock, даты заездов, оценку, количество отзывов, часы работы, координаты, авторство или foundingDate без подтверждения. Регистрационная дата юрлица не заменяет согласованную дату основания бренда. Общий каталог Evintra не является идентичным профилем Ada Tours и не используется в sameAs. Проверенные точные URL можно добавить в organization.sameAs в `page-schema.ts` после проверки владельцем. Не копировать туда произвольные упоминания компании.

Schema.org не определяет duration для Trip: длительность остаётся в фактическом description, а дни маршрута представлены subTrip. Тур не маскируется под Product ради расширенного сниппета. Период кейса не превращается в выдуманную дату публикации. dateModified не равняется времени сборки.

## Приёмка

`npm run test:schema` — unit-тесты графа и HTML. `npm run build` дополнительно автоматически запускает `scripts/check-schema.mjs` на **каждом** готовом HTML, до Pagefind. Проверяются единый JSON-LD, ID и ссылки, canonical/base, типы, реальные карточки и позиции, FAQ/отзывы, архивы и цены. Ошибка останавливает публикацию. Полный отчёт: `dist/schema-coverage.json` (сводка и постраничное покрытие). Это внутренний контроль проекта, не сертификат Google Rich Results Test или validator.schema.org.

При добавлении нового класса страниц использовать BaseLayout, дать реальные title/description/canonical. Для специфической семантики расширить генератор и тесты; не обходить его вторым скриптом. `RedirectLayout` использует отдельный минимальный технический граф. JSON-LD всегда сериализовать через safeJsonLd.

## Основания

- https://schema.org/TouristTrip

- https://schema.org/PriceSpecification
- https://schema.org/itemOffered

- https://developers.google.com/search/docs/appearance/structured-data/sd-policies
- https://developers.google.com/search/docs/appearance/ai-features

Разметка помогает однозначно интерпретировать содержание и связи; она не гарантирует позиции, расширенный сниппет или цитирование ИИ. Специального обязательного «GEO-типа» schema.org нет. Видимое содержание, доступность индексации и качество источников остаются необходимыми.
