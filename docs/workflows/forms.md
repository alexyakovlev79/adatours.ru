# Ada Tours — общая форма перед подвалом

Версия: 1.3 · 07.10.2026

## Размещение

`src/layouts/BaseLayout.astro` выводит один `src/components/forms/LeadForm.astro` после содержимого страницы и непосредственно перед `SiteFooter`. Это распространяется на все страницы с общим layout: главную, страны, места, экскурсии, туры, интересы, общие и фильтрованные каталоги, все страницы пагинации, коммерческие, редакционные и служебные страницы. Технические redirect aliases формы не имеют, так как сразу переводят на канонический адрес.

Якорь `#request` и `data-lead-location="footer"` присутствуют один раз. Нижняя ссылка «Обсудить поездку» ведет на `#request`. Форма помечена `data-pagefind-ignore`, чтобы повторяющийся набор полей не засорял поисковый индекс.

## Модальная форма и CTA

На странице остается ровно один реальный экземпляр формы. При открытии модального окна JavaScript временно переносит этот же `form[data-lead-form]` из нижнего блока в модалку и при закрытии возвращает на исходное место. Копия формы, второй телефонный селектор и второй набор полей не создаются.

`PrimaryCTA` открывает модалку, если прежняя цель CTA была `/contacts/` либо подпись равна «Оставить заявку». В HTML такой CTA получает `data-lead-modal="true"` и fallback `href="#request"`. Поэтому без JavaScript пользователь попадает к нижней форме этой же страницы, а с JavaScript открывается модалка. Обычная навигационная ссылка «Контакты» остается ссылкой на `/contacts/`.

Это распространяется на конверсионные кнопки «Оставить заявку», «Получить программу», «Заказать экскурсию», «Заказать этот тур» и другие `PrimaryCTA`, которые раньше отправляли на страницу контактов. CTA с другой явной целью сохраняют свою ссылку.

Модалка повторяет актуальную логику GAEO.ru после commit `5b987c17`: без верхней служебной плашки, с компактными вертикальными отступами, textarea высотой около 104 px, закрытием по кресту / Escape / фону и focus trap. После успешной отправки показывается короткое уведомление и модалка закрывается через 650 мс.

## Контекст

Дочерний layout передает в `BaseLayout` необязательные `leadTitle`, `leadEntityId`, `leadTourId`. Отсутствующий контекст получает общий заголовок и логический URL страницы. Тот же `leadTitle` используется как заголовок модалки. Каталоги интересов передают stable ID темы; URL отражает текущую страну и номер страницы. На архивной странице используется предложение «Подобрать другую поездку» с пустым `tour_id`, а не возможность заказать архивный продукт.

Повторный импорт и вставка `<LeadForm>` в дочерние layouts запрещены.

## Поля и клиентская логика

Форма содержит имя, телефон с выбором страны и маской, email, комментарий и предпочтительный способ связи: телефон / WhatsApp / Telegram / email. Служебные поля — `entity_id`, `tour_id`, `page_url`, `locale`.

Способ связи включается только когда заполнен соответствующий канал: телефон активирует Телефон / WhatsApp / Telegram, email активирует Email. Если выбранный канал очищен, его вариант автоматически снимается. Отправка без выбора доступного способа связи блокируется.

Телефонный компонент `PhoneField.astro` использует реальные изображения флагов FlagCDN. Флаги списка начинают загружаться одним пакетом при первом открытии селектора, без `loading="lazy"`; при сетевой ошибке показывается нейтральный fallback, а не двухбуквенный ISO-код. Маска национального номера отбрасывает ведущие пробелы и дефисы после отдельно показанного кода страны, поэтому Молдова отображается как `0000-0000`, а не `-0000-0000`. Исправление Backspace/курсора из GAEO `5e293ff1` сохраняется.

Остальная клиентская логика:

- имя обязательно; нужен хотя бы телефон или email;
- телефон проверяется по полной маске выбранной страны, email — браузерной email-валидацией;
- есть honeypot `company_website`, время начала и отправки формы, referrer, UTM и click-id;
- во время POST кнопка блокируется; ошибка сервера показывается в самой форме;
- после успешного ответа показывается верхнее уведомление;
- honeypot получает внешне такой же success-flow и не отправляет запрос;
- если endpoint не задан, форма показывает ошибку и не имитирует успешную заявку.

Под кнопкой есть ссылки на политику конфиденциальности и обработку персональных данных.

## Серверная отправка

GitHub Pages остается статическим. Клиент отправляет JSON в отдельную Yandex Cloud Function; публичный URL функции хранится только в `public/form-config.js` как `window.ADATOURS_FORM_ENDPOINT`. Это публичная конфигурация, секретов в ней нет.

Канонический серверный исходник: `serverless/adatours-form/index.py`. Схема та же, что на GAEO.ru: Yandex Cloud Function → Yandex Cloud Postbox → email. Обработчик проверяет Origin, допустимый URL Ada Tours, размеры и форматы полей, honeypot и слишком быструю отправку. Содержимое заявки и персональные данные в лог не пишутся.

До фактического развертывания функции `public/form-config.js` остается с пустым endpoint. После развертывания туда записывается ее публичный invocation URL; отдельные секреты во frontend не добавляются.

## Получатели заявок

Получатели задаются только на серверной стороне Cloud Function / Postbox.

Первый этап тестирования:
- отправлять заявки только на `ya@gaeo.ru`;
- `Anna@adatours.com` и `Operations@adatours.com` в тестовые отправки пока не включать.

После успешных тестов и отдельного подтверждения пользователя перейти на рабочий список получателей:
- `ya@gaeo.ru`;
- `Anna@adatours.com`;
- `Operations@adatours.com`.

До этого подтверждения единственный адрес доставки заявок — `ya@gaeo.ru`.

## Автоматическая проверка

Штатный `scripts/check-interest-presentation.mjs` проходит весь сформированный HTML сайта: на каждой реальной странице ровно одна форма и один якорь, форма расположена перед footer, присутствуют пользовательские, контекстные, телефонные и anti-spam поля, статус отправки и legal-ссылки; старая заглушка `onsubmit="return false;"` запрещена. На каждой реальной странице есть хотя бы один `data-lead-modal="true"`, а такие CTA имеют fallback `href="#request"`, а не `/contacts/`. Redirect aliases исключаются по техническому перенаправлению.
