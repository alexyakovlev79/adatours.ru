# Ada Tours — создание известной экскурсии

Версия: 1.0 · 2026-10-02 · Репозиторий: `alexyakovlev79/adatours.ru`, ветка `main`.

Применять, когда пользователь просит добавить известную экскурсию из реестра или следующую экскурсию из закрепленной очереди. Это перенос выбранного материала в готовый `ExcursionLayout.astro`. Извлечение экскурсий из программы тура описано отдельно в `docs/workflows/tour-excursion-linking.md`.

## 1. Точный вход

Общие правила и завершение задачи: `docs/workflows/master.md`. Индекс: `data/source-index/index.json`; выбранная `entry`: `data/source-index/entries/<entityId>.json`. Все входные данные экскурсии брать из `entry`; каталог `src/data/catalog/destinations.json` используется кодом и сборкой.

В записи использовать `id`, `name`, `slug`, `contentPath`, `url`, `sourceUrl`, `countryIds`, `destinationIds`, `destinations`, `destinationName`, `text.selected`, `media.images`, `readiness`. Открыть точный текст по `text.selected.driveId` / `url`; `name` и `kind` внутри `selected` определяют файл и вид источника. Фотографии уже заданы как `{url, role, order, alt}`. Для этой задачи не использовать очередь `PENDING` туров из `TOUR_EXCURSION_MAPPING_REGISTRY.md`.

Реестр: `1ZPptMdEcIDA3ZFMOQcFuc5jU88LJlFw9R4URCQSBmmc`, лист `Страницы`. Читать выбранную строку и целевой production MD, если он существует. Не повторять обход Drive, всего репозитория, всех туров или экскурсий. Если выбранная сущность уже опубликована, продолжить ее точечное обновление либо перейти к следующей записи согласно запросу пользователя; дубль не создавать.

`page_texts_original` и `page_texts_newstep` не взаимозаменяемы. Использовать `text.selected`, без обязательного поиска второго текста и без предположений по имени папки. Недоступный файл — адресный блокер; искать замену текста в интернете не нужно.

## 2. Поля текущей схемы

Файл: `entry.contentPath` в `src/content/excursions/`. Slug и URL `/ekskursii/<slug>/` брать готовыми из записи. Источник схемы: `src/content.config.ts`; имена полей — camelCase.

| Поля | Правило |
|---|---|
| `id`, `locale: ru`, `slug`, `country` | `entry.id`, `entry.slug`, подтвержденная страна из `entry.countryIds` |
| `title`, `lead`, основной Markdown после frontmatter | Готовый русский текст этой экскурсии |
| `status` | `approved` для готовой к публикации сущности |
| `destination`, `destinationName` | Основной ID из `entry.destinationIds` и готовое `entry.destinationName` / имя из `entry.destinations`, в том числе до публикации места |
| `searchAliases`, `themes`, `route` | Подтвержденные значения; иначе `[]` |
| `duration`, `format`, `language` | Только явно указанные условия; отсутствующие необязательные значения не придумывать |
| `priceFrom`, `currency`, `priceNote` | Точная цена и ее основание из источника, если они есть |
| `hero: {src, alt}`, `gallery: [{src, alt}]` | Закрепленные raw URL фотографий этой экскурсии |
| `included`, `notIncluded`, `notes` | Все подтвержденные услуги, исключения и условия; при отсутствии `[]` |
| `sourceUrl`, `sourceSnapshot`, `updatedAt` | Непустой `entry.sourceUrl`, точная ссылка `entry.text.selected.url` либо подтвержденный источник блока тура, дата изменения |

`lead` обязателен: перенести готовый вступительный текст; если отдельного lead в источнике нет, кратко сформулировать его из того же текста без новых фактов. `language` — массив строк, `priceFrom` — число или `null`, `duration` — строка. Не переносить примеры полей из старых snake_case-схем.

Если `entry.sourceUrl` равен `null`, поле `sourceUrl` в MD опустить: схема допускает отсутствующий URL, но не `null`. Для новой экскурсии из блока тура `sourceSnapshot` может указывать на подтвержденный источник этого блока; отдельную legacy-страницу не выдумывать.

## 3. Сохранить содержимое без нового исследования

Перенести готовый текст, включая маршрут, продолжительность, время встречи, цены с их единицами, варианты по размеру группы, транспорт, язык гида, включенные услуги, исключения и ограничения, если они есть. Не заменять цену за группу ценой на человека и не терять тарифную таблицу при заполнении одного `priceFrom`: остальные условия сохраняются в `priceNote`, `notes` или body.

Если материал уже утвержден, не проводить повторный полный рерайт или новую редакционную приемку. Структурные поля извлечь из выбранного текста. Если необязательных данных в нем нет, оставить соответствующее поле пустым; недостающее обязательное значение обозначить как конкретный пробел источника. Не восстанавливать факты из интернета и не дополнять экскурсию новыми объектами или услугами.

В `notes` помещать только условия для туриста. Историю миграции, ID источников и технические комментарии хранить в служебной записи реестра. Если собственного legacy source у новой сущности действительно не было, `sourceUrl` и `sourceSnapshot` не выдумывать.

## 4. Фото — готовые ссылки

При первичной публикации использовать `entry.media.images` с raw source `https://brasiltours.ru/image/...` и исходным расширением. `/image/cache/` запрещен. Назначение hero/gallery определяется `role`, порядок — `order`, подпись — `alt`. Не выбирать новые кадры по эстетическим соображениям и не добавлять повтор hero в gallery.

Не скачивать фотографии, не создавать локальные WebP, не обращаться к GPT Image, не искать альтернативы и не повторять media inventory. Уже определенные raw URL использовать из `entry`. Отсутствующий raw URL или оставшийся cache URL обозначить как конкретный дефект записи, без поиска посторонних фотографий и повторного восстановления URL. При обновлении экскурсии сохранять ранее улучшенные локальные изображения.

## 5. Места и связанные страницы

Для места брать ID из `entry.destinationIds`, а название, будущий URL и страну — из готового `entry.destinations: [{id, name, url, countryId}]`; для одного связанного места также задано `entry.destinationName`. Дополнительное чтение каталога или страницы места не нужно. Записать `destination` уже сейчас, даже если MD места пока отсутствует; `destinationName` позволяет вывести известное название до его публикации. Создавать Destination рядом с экскурсией не требуется. Если запись содержит несколько мест, использовать уже выбранное основное; при отсутствии основного определить его по точному маршруту этой экскурсии, не перечитывая соседние сущности. Бразильскую и аргентинскую стороны Игуасу не объединять и не определять страну по одному слову «Игуасу».

Если `entry.destinationIds` намеренно пуст, поля `destination` и `destinationName` могут отсутствовать. Это допустимое состояние экскурсии, а не поручение искать или создавать место.

При появлении Destination общий шаблон использует ее название, описание, фото и ссылку. Обратный блок на странице места также подхватывает экскурсию по `Excursion.destination`. Создатель экскурсии не проверяет содержимое соседних мест, не создает им страницы и не меняет их вручную.

Существующие структурированные связи тура с экскурсией хранятся в `excursionRef`. Рекомендации других экскурсий вычисляет шаблон по совместному присутствию в турах: одна экскурсия учитывается один раз на тур, текущая исключается, сортировка по числу общих туров и русскому title, максимум 10. Если связей пока нет, блок отсутствует. `relatedExcursions` и другие ручные списки не создавать; туры ради наполнения блока не перечитывать.

Добавление самостоятельной экскурсии не является задачей массового поиска ее упоминаний в старых турах. Такой разбор выполняется при создании или отдельной нормализации конкретного тура.

## 6. Один рабочий цикл

1. Открыть точную запись и указанный текст; проверить только целевой production MD.
2. Собрать один Excursion MD из готовых данных и закрепленных фотографий. Все связанные места указать каноническими ID, без создания дополнительных сущностей.
3. Отправить один подготовленный логический commit по `docs/workflows/master.md`.
4. Использовать один успешный Actions build этого изменения: `npm run build` уже включает offline-проверку схемы, references и запрета cache URL. Отсутствие MD запланированного места ошибкой не считается. Дождаться успешного deploy; отдельно локальную сборку и дополнительные проверки опубликованной страницы не запускать.
5. Один раз обновить строку реестра после успешного deploy: E — `Добавлена`, F — дата первого добавления, H — stable ID, I — необходимый служебный комментарий; A/B — точные production/source URL. G (`Принята`) не менять; дату уже опубликованной страницы сохранять.
6. Сообщить название, ссылку и результат публикации. При сбое продолжать с сохраненной стадии выбранной записи.

Если эта экскурсия создается как необходимая часть нового тура, не делать отдельную публикацию и отдельный цикл: ее MD входит в общий commit тура, а ее строка — в итоговое пакетное обновление затронутых строк реестра.
