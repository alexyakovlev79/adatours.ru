# Ada Tours — как Анне редактировать сайт через ChatGPT / Codex

**Назначение:** рабочий вход для ассистента Анны и пошаговая памятка самой Анне.  
**Обновлено:** 2026-10-29.  
**Репозиторий:** https://github.com/alexyakovlev79/adatours.ru  
**Ветка публикации:** main. **Рабочий адрес:** https://adatours.ru/

## 1. Сначала правильно определить систему

- Это **не WordPress**. У сайта нет WordPress-админки и не требуется /wp-admin/, /wp-login.php или вход через браузерный редактор.
- Действующий проект — **Astro 7, статический сайт, GitHub Pages**. Исходники и текстовые данные — в этом репозитории. Публикация кода и текстов — через .github/workflows/deploy.yml после попадания изменения в main.
- **Новые фотографии от любого редактора**, включая Анну, проходят реальный GPT Image edit исходного файла → защищенную загрузку оригинала и улучшенного WebP в Yandex Object Storage → подтвержденные SHA-256 receipts и реестр `method: gpt-image`. Использовать **docs/workflows/editor-image-intake.md** и `scripts/editor-photo-publish.mjs`, затем PR. Новые бинарные медиа в Git не коммитить, ссылки на незагруженные фото не придумывать. Для видео по-прежнему действует docs/workflows/direct-s3-upload.md.
- GitHub, подключенный к обычному ChatGPT для поиска и анализа, не равнозначен среде с правами записи. Для внесения файлов использовать **Codex Cloud с опубликованной средой этого репозитория** либо другой действительно доступный инструмент GitHub-записи. Не заменять отсутствие прав попытками найти CMS.

## 2. Маршрут агента при каждом поручении Анны

1. Работать только в alexyakovlev79/adatours.ru; начать со свежего main. Прочитать корневой AGENTS.md и применимый для задачи документ. Этот файл — краткий маршрутизатор, а не замена AGENTS.md или специализированных workflow.
2. Найти **существующий** файл, содержащий нужные факты/текст. Для узкой правки не проводить общее исследование сайта, не создавать новый объект и не переделывать шаблоны.
3. Сверить точную фразу/сотрудника/объект с данными. Менять только согласованный фрагмент, сохраняя идентификаторы, связи, значения чужих полей и имена медиа.
4. Для задач Анны через Codex по умолчанию создать отдельную ветку от актуального main и **Pull Request в main**. Не делать прямой push в main или merge без отдельного явного поручения. Не переписывать параллельные изменения других исполнителей.
5. Для одной текстовой/JSON-правки выполнить адресную синтаксическую проверку и git diff --check; полный npm run build запускать только если его требует конкретный актуальный workflow или изменение кода. После merge штатный GitHub Actions проверит и опубликует сайт.
6. Сообщить Анне ссылку на PR, точный список измененных файлов и что именно ей нужно нажать. До merge и успешного Pages deploy нельзя говорить «опубликовано». Если нет прав записи, данных или технической возможности — назвать конкретный блокер, не изображать успех.

| Обновить конкретный тур | Точный production MD из data/source-index/entries/<entityId>.json | Применить docs/workflows/tours.md; для существенного обновления и Word 2027 учитывать более новый AGENTS.md и docs/workflows/tour-2027-daily.md. |

| Добавить/заменить фотографию | docs/workflows/direct-s3-upload.md и специальный workflow | Без подтвержденной загрузки в S3 не назначать новый image src. |

## 4. Проверка одной небольшой редакторской правки

После изменения team.json достаточно адресной проверки корректности JSON, например:

~~~bash
node -e "JSON.parse(require('node:fs').readFileSync('src/data/organization/team.json','utf8')); console.log('team.json OK')"
git diff --check
~~~

Это подтверждает только синтаксис и чистоту diff, **не публикацию**. Дальше: Pull Request → проверка измененных строк Анной → Merge → успешный GitHub Actions «Deploy to GitHub Pages» по соответствующему commit → обновленная страница на adatours.ru. Если Actions не завершились успешно, записать ссылку на сбой, не обещать результат.

Для теста на живом сайте подойдет одна точная правка существующей биографии, которую Анна согласна опубликовать. Сама эта инструкция ничего в биографиях не меняет.

## 5. Настройка на стороне Анны (один раз)

1. В своем аккаунте ChatGPT открыть https://chatgpt.com/codex/ .
2. Проверить **Settings → Codex Cloud → Environments**. Если уже опубликована среда с репозиторием alexyakovlev79/adatours.ru — использовать ее, дубликат не создавать.
3. Если среды нет: **Create environment** → выбрать alexyakovlev79/adatours.ru (при необходимости пройти GitHub Connect/Authorize под своим GitHub-аккаунтом) → **Get started** → проверить подготовленную среду → **Publish**. Для текстового редактирования сайта не нужны WordPress-логин, S3-ключи, GitHub PAT и прочие секреты. Не включать лишние внешние сервисы.
4. В новой задаче выбрать **Work in → Cloud** и опубликованную среду Ada Tours, затем дать поручение с ссылками на AGENTS.md и эту памятку.
5. После получения PR проверить фрагмент, затем нажать **Merge pull request**, если изменение правильное. Убедиться, что «Deploy to GitHub Pages» завершился успешно.

Если репозиторий не отображается при выборе, проверить доступ **именно GitHub-аккаунта Анны** к нему и авторизацию Codex GitHub. Подключение GitHub к обычному ChatGPT само по себе не гарантирует готовую Codex Cloud среду. Если кнопка Cloud недоступна, это вопрос тарифа/настроек аккаунта или рабочего пространства: нужна диагностика по скриншоту страницы Environments, а не поиск WordPress.
