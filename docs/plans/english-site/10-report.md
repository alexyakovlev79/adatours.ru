# Английская версия Ada Tours: итог подготовки

**Дата: 28 октября 2026.** Исходный код исследован на commit
`b1b14ed3a8abab9773053f836fed28c2ff77204f`.
Рабочая ветка: [`feat/english-site-foundation`](https://github.com/alexyakovlev79/adatours.ru/tree/feat/english-site-foundation).

## Результат

Подготовлены архитектура общего RU/EN сайта, правила перевода, порядок работы
роя, опись английских Word-программ, предварительный реестр соответствий всем
турам, аудит SEO/schema.org и начальный проверенный код локализации. Короткие
тексты интерфейса переведены координатором. Работа сохраняется отдельными
контрольными точками в GitHub.

**Новый английский сайт ещё не опубликован.** Начальное ядро не подключено к
Astro; автоматический диспетчер переводов и двустороннее обновление текстов
ещё предстоит реализовать. Полностью переведённых и принятых Tour — **0**.
Восемь проверенных соответствий Word ↔ Tour — подготовка к переводу, а не
восемь готовых английских страниц. Действующий русский сайт не менялся.

Главное решение: **один исходный репозиторий, одна запись фактов каждого
продукта, одна медиатека, общие шаблоны и отдельные RU/EN тексты**. Английский
origin по умолчанию — `https://adatours.com`; он задаётся конфигурацией и может
быть заменён, не переписывая перевод и не меняя ID туров.

## 1. Как обе версии будут изменяться вместе

Подробный контракт: [01-architecture.md](01-architecture.md).

| Изменение | Предлагаемое поведение |
| --- | --- |
| Цена, дата, маршрут, длительность, состав услуги | Меняется одна общая запись. Карточки, фильтры, SEO и JSON-LD обоих языков используют её; зависимые текстовые упоминания проходят адресную проверку. |
| Новый тур, место, экскурсия | Создаётся один устойчивый ID и связи; автоматически возникают задания отсутствующим языкам. Новая страница публикуется после готовности её текста. |
| Фото, улучшение, обложка, кадрирование | Меняется общий media reference. Оба языка используют результат одной обработки. Текстовая очередь затрагивается лишь при изменении смысла подписи/alt. |
| Фильтр, компонент, программное исправление | Один исходный код попадает в обе сборки. Наличие английских строк проверяется вместе с изменением интерфейса. |
| Правка русского текста | В очередь попадают только изменённые блоки и зависимые фрагменты EN. Утверждённый Word и независимая английская редактура защищены от перезаписи. |
| Правка английского текста | Работает тот же процесс в обратную сторону. Фактическое исправление относится к общим данным; стилистическая правка не требует дословно переписывать русский. |
| Новая редакция Word на Drive | Проверяется revision/hash, строится адресный diff, обновляются соответствия и задачи зависимым блокам. Сама сборка сайта использует закреплённые источники и не ходит в Drive. |

«Автоматически» имеет два разных практических результата. Общие факты и код
распространяются общей сборкой. Изменение свободного текста автоматически
создаёт задачу перевода/согласования, затем проходит проверку. Это сохраняет
независимую редактуру и предотвращает бесконечный обратный перевод RU → EN → RU.
У изменения есть собственный ID и ссылка на породившее его изменение.

Для одновременных правок сохраняется последняя согласованная пара текстов,
новый исходник и текущая целевая редакция. Если изменились обе стороны,
появляется предметный конфликт; позднейшая запись не затирает предыдущую.

Сначала совместимым источником остаются текущие Markdown-файлы. Адаптер
выделит из них общие факты, медиа и русский текст; английский текст хранится
отдельным слоем без собственной копии цены и маршрута. Массовый перенос всей
существующей базы в новую систему хранения для первой версии не требуется.

### Общий тур и разные предложения

Одинаковый маршрут может продаваться с разным языком гида, включениями,
минимальной группой или размещением. Это варианты предложения одного продукта,
а не разные переводы одной цены. Язык сайта сам по себе не выбирает язык гида.

Нужны структурные условия тарифа: `per_person`, `per_group` или `per_tour`,
размещение и применимость. Нельзя вычислять SEO-цену «от» как минимум среди
несопоставимых тарифов. Найденные Word-расхождения подтверждают необходимость
этого ограничения; они описаны ниже.

### Публикация

Из одного зафиксированного commit собираются RU и EN. Выпуск считается
согласованным только после подтверждения обеих публикаций. Если один хостинг
не обновился, журнал показывает частичный выпуск и запускается адресное
повторение либо откат. Два независимых deploy не являются общей атомарной
транзакцией; это нельзя скрывать за словом «синхронизация».

У GitHub Pages один project site на репозиторий. Поэтому практичный отдельный
EN target на Pages потребует второго репозитория **с результатом сборки**,
но без второй копии исходного кода. Другой подход — статический хостинг с
несколькими доменами. Переносить русский сайт ради перевода не требуется.
См. [официальное описание GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

### Почему недостаточно «скачать текст и подставить»

1. **Обычное текстовое представление Drive пропускало таблицы цен.** Полный
   DOCX позволил проверить 977 непустых сегментов и 98 таблиц в восьми файлах.
   Подготовлен extractor с происхождением фрагментов; при полном процессе
   нужны также проверки изображений с текстом, примечаний и других вложений.
2. **Mexico Lindo: коммерческий конфликт.** В английском Word SGL/DBL/TPL
   стоят 2 372 / 1 908 / 1 855 USD; в текущем русском Tour —
   5 870 / 5 336 / 5 219 USD. Маршрут соответствует, цены — нет. Переводчик
   не имеет права выбирать одну из них как «правильную». Нужна сверка
   редакции/комплектации либо отдельные подтверждённые предложения.
3. **Язык гида не совпадает с языком страницы.** В части бразильских Word
   указаны английский/испанский, а текущий RU продукт предполагает русский.
   Нельзя автоматически превращать одно в другое.
4. **В Word бывают уже исправленные на сайте ошибки.** В Colombia Essential
   английский документ называет Isla Majagua; в RU сохранено уточнение
   San Pedro de Majagua на Isla Grande. Подтверждённое исправление нужно
   сохранить с отдельной записью адаптации, а не восстановить старую ошибку.
5. **Текст дня может включать общую Excursion.** Её перевод принадлежит самой
   экскурсии и используется несколькими турами. Копирование полного Word-дня
   в Tour без карты блоков создаст повтор описания и будущую рассинхронизацию.

## 3. Правила и порядок работы переводящего роя

Подробно: [редакционный контракт](03-translation-editorial.md) и
[runbook](04-swarm-runbook.md).

Сначала координатор завершает соответствия, закрепляет редакции источников,
устойчивые ID блоков и владельца каждого общего объекта. Затем выдаёт
ограниченные непересекающиеся пакеты:

1. Туры с подтверждённым Word 2027: название и совпадающие по смыслу куски
   берутся из утверждённого английского текста. Только непокрытые куски
   переводятся по русскому источнику.
2. Туры, которым не найдено подходящего 2027: тот же процесс с Word 2026.
   Числа, даты и услуги сверяются с действующим продуктом; календарь 2026
   нельзя переносить в действующее предложение 2027 как стилистический текст.
3. Туры без подходящих источников обоих годов: AI-перевод после записанной
   отрицательной проверки. Кандидат, не дошедший до проверки, не равен
   отсутствующему источнику.
4. Страны, места, самостоятельные экскурсии и SEO/GEO: отдельные задания
   с общими зависимостями. Один объект переводится один раз.

Точный Word сохраняется с file ID, редакцией, hash документа, адресом
фрагмента и hash текста. Нельзя смешать исходный Word с новым AI-абзацем и
пометить весь результат как дословный. Минимальная правка фактической ошибки
или чужого голоса требует отдельной записи адаптации и сохранения исходника.
Обычный переводчик не может обойти эту защиту простой сменой метки.

### Человеческий язык и голос Ada Tours

- Пишем от Ada Tours: «We will…», «Your guide…», прямое описание маршрута.
  Исключаем «the itinerary states», «the programme lists», «it is advertised
  as» и другие формулировки стороннего наблюдателя. Не нужно механически
  начинать каждый абзац с «we».
- Сохраняем степень обещания: возможность остаётся возможностью, пример —
  примером, optional — отдельной услугой. Не добавляем гарантий погоды,
  встречи животных, private service, hotel category или включённого питания.
- Показываем конкретный опыт и помогаем выбрать: темп, переезды, особенности
  места, кому подходит маршрут, что включено и что надо уточнить — в пределах
  имеющихся фактов. Не выдумываем личный опыт гида или клиента.
- Сохраняем ритм и структуру русского материала, избегаем канцелярита,
  одинаковых вступлений, рекламных превосходных степеней без основания и
  серий пустых эпитетов. Фактическая полезность важнее искусственного
  «процента человечности» или попыток обмануть AI-detector.
- «Индивидуальный» обычно означает **tailor-made**. **Private** допустимо,
  только когда действительно подтверждён приватный характер услуги.
- Новые английские тексты получают единый словарь и правила написания.
  Хороший утверждённый Word не переписывается ради смены варианта английского.
- Географические названия, единицы, ссылки, FAQ и коммерческие условия
  проверяются вместе с переводом. Англоязычный посетитель не считается
  автоматически гражданином Великобритании/США; визовые условия не
  переадресуются другой аудитории без проверки.

Runbook определяет роли, зависимость общей экскурсии, ограничение пакетов,
резервирование задания, срок аренды, повторную выдачу и подтверждение приёма.
Это проектный регламент. Работающий CAS-диспетчер, восстановление после
падения и проверка конкурирующих исполнителей — обязательный следующий этап,
а не уже работающая услуга. Текущие SEO/GEO/photo очереди не подменяются
английской очередью.

## 4. Интерфейс, SEO и schema.org

### Короткие тексты

Координатор подготовил **218 пар RU/EN**: меню, кнопки, формы, поиск,
пагинация, ошибки, ARIA, карты, архив и другие небольшие строки. Полный список:
[08-ui-copy.md](08-ui-copy.md). Дополнительно готовы **15 наборов** английских
текстов интересов: названия/вводные/заголовки и английские формы числа.
Они лежат в `src/data/i18n/` и ожидают подключения к компонентам.

Примеры принятых решений: «Отправить заявку» → **Send an enquiry**,
обращение по туру → **Enquire about this tour**, индивидуальный маршрут →
**tailor-made**. Это фактические заготовки перевода, не заявление, что
английское меню уже появилось на публичном сайте.

### Title, H1, description

Аудит проследил реальную цепочку: исходные шаблоны/контент → компоновка
title → ценовые дополнения → отдельное RU-правило «русский гид» → видимые
метатеги, Open Graph/Twitter и JSON-LD. H1 живёт отдельной цепочкой.

Подготовлены **89 записей английской спецификации шаблонов/правил** и
**16 пунктов интеграции** с точными source hashes. Динамическое количество,
год, цена и прочие параметры остаются динамическими. Найдены жёстко русские
ветви в SEO/GEO, caption override, поиске, карте, social previews,
послесборочной оболочке и redirect-страницах. Поэтому простой `locale=en`
сейчас выдал бы часть русского текста под английскими метками.

См. [05-seo-schema-audit.md](05-seo-schema-audit.md) и
[`en-metadata-template-spec.json`](../../../data/i18n/en-metadata-template-spec.json).

### Идентичность и поисковая разметка

Сохраняется одна Organization с устойчивым ID
`https://adatours.ru/#organization`. Для EN в `sameAs` добавляется
`https://adatours.ru/`. У каждой языковой страницы собственный URL,
self-canonical, WebPage/WebSite ID и `inLanguage`. Взаимные `hreflang`
появляются только для подтверждённых опубликованных пар. Нельзя указывать
несуществующую английскую страницу или канонизировать весь EN на RU.

`translationOfWork`/`workTranslation` относятся к переводимому CreativeWork,
а не механически ко всякой паре туристических сущностей. Если английский
текст независимо написан в Word, одного одинакового Tour ID недостаточно,
чтобы объявить русскую страницу его исходным произведением.

Соответствующие вспомогательные функции уже написаны и проверены, но ещё
не включены в JSON-LD текущего сайта. При замене действующего `adatours.com`
дополнительно нужна карта старых английских URL → новых английских URL и
редиректы. Старый EN→RU mapping — справочный источник, не готовая карта
переводов нового сайта.

Основания:
[Google: локализованные версии](https://developers.google.com/search/docs/specialty/international/localized-versions),
[Google: многоязычные сайты](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites),
[Schema.org: sameAs](https://schema.org/sameAs),
[Schema.org: translationOfWork](https://schema.org/translationOfWork).

## 5. Что реализовано и как проверено

| Уже создано | Практическая роль |
| --- | --- |
| `content-overlay.mjs` | Разрешённые текстовые поля, устойчивые ID блоков, происхождение Word/AI, раздельные fingerprints, проверка готовности и защита от перезаписи чужой правки. |
| `locale-site.mjs` + `sites.json` | Заменяемые домены, EN planned, проверка URL, публичные языковые связи только с подтверждением публикации, единая Organization. |
| `messages.mjs` + словари | Строгие UI-ключи, параметры, английские формы числа, отсутствие молчаливого RU fallback. |
| DOCX extractor + candidate builder | Повторяемое извлечение и построение кандидатов по закреплённым источникам. |
| Source/overlay JSON schemas | Контракт данных следующей интеграции. |
| `npm run i18n:status` | Быстрое read-only состояние подготовки; явно не живой диспетчер. |
| README, workflow, AGENTS, runbook | Понятная передача следующему чату без повторного обследования. |

Пройдено **35 предметных unit tests**, **19 проверок целостности источников**,
проверки синтаксиса JavaScript и разбора JSON. Из безопасных manifest и точных
Git blobs baseline повторно получены **все 392 строки** реестра кандидатов
без расхождений. Протокол:
[`foundation-validation.json`](../../../data/i18n/foundation-validation.json).

Тесты покрывают, в частности, замену домена, запрет случайного публичного
статуса EN, отсутствие русского fallback, перенос блока без потери ID,
изменение Word/цены/медиа, привязку QA к точному тексту и конфликт целевой
редактуры. Отдельная проверка исправила несколько существенных дефектов,
описанных в [09-foundation-review.md](09-foundation-review.md).

Полная Astro-сборка не запускалась: новые модули изолированы и не подключены
к runtime. Живой распределённый диспетчер не проверялся, потому что ещё не
реализован. JSON schemas разобраны как JSON; внешняя формальная проверка
соответствия стандарту Schema не заявляется.

## 6. Следующие этапы и условия перехода

Подробный пошаговый план: [06-rollout-plan.md](06-rollout-plan.md).

1. **Довести matching и блоковую карту.** Содержательно проверить оставшиеся
   активные Tour; для восьми уже найденных пар выделить блоки, общие экскурсии
   и коммерческие конфликты. Затем можно выдавать переводчикам точные пакеты.
2. **Подключить представление языка к Astro.** Адаптер общей записи, словари,
   локальные метаданные/поиск/карта/формы/JSON-LD, отсутствие RU fallback.
   Проверить неизменность действующего RU вывода и английский preview.
3. **Реализовать диспетчер и небольшой настоящий пилот.** Конкурентная выдача,
   защищённая запись, истёкшая аренда, повторная отправка, падение работника,
   самостоятельная правка обоих языков. После этого разрешать массовую выдачу.
4. **Перевести по волнам 2027 → 2026 → AI gaps**, параллельно обрабатывая
   общие страны/места/экскурсии по зависимостям. Принимать текст, факты, voice
   и структурную корректность в одном цикле.
5. **Подключить обновления и общий release pipeline.** Реальные hooks для
   всех путей изменения текущего контента, наблюдение за Word, две сборки,
   receipts публикаций, видимый backlog и восстановление частичного выпуска.
6. **Подготовить домен и миграцию.** Выбрать доступный EN target, проверить
   HTTPS, canonical/hreflang, формы/CORS, redirects, sitemap и старые URL.
   Перед публикацией закрепить окончательный origin. При последующей смене
   уже публичного домена одной настройки мало: нужны постоянные редиректы.

Ближайшие предметные решения — какие предложения стоят за расходящимися
тарифами/языками гида и какой EN-домен дадут для запуска. Они не мешают
продолжать matching и программную интеграцию сейчас. Прерванные сессии
исполнителей не должны превращать эти решения в потерянные задания.
