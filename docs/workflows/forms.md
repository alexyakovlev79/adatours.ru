# Ada Tours — общая форма перед подвалом

Версия: 1.2 · 06.10.2026

## Размещение

`src/layouts/BaseLayout.astro` выводит один `src/components/forms/LeadForm.astro` после содержимого страницы и непосредственно перед `SiteFooter`. Это распространяется на все страницы с общим layout: главную, страны, места, экскурсии, туры, интересы, общие и фильтрованные каталоги, все страницы пагинации, коммерческие, редакционные и служебные страницы. Технические redirect aliases формы не имеют, так как сразу переводят на канонический адрес.

Якорь `#request` и `data-lead-location="footer"` присутствуют один раз. Нижняя ссылка «Обсудить поездку» ведет на `#request`, не уводя посетителя на контакты. Форма помечена `data-pagefind-ignore`, чтобы повторяющийся набор полей не засорял поисковый индекс.

## Контекст

Дочерний layout передает в `BaseLayout` необязательные `leadTitle`, `leadEntityId`, `leadTourId`. Отсутствующий контекст получает общий заголовок и логический URL страницы. Каталоги интересов передают stable ID темы; URL отражает текущую страну и номер страницы. На архивной странице используется предложение «Подобрать другую поездку» с пустым `tour_id`, а не возможность заказать архивный продукт.

Повторный импорт и вставка `<LeadForm>` в дочерние layouts запрещены: иначе возникают дубли и несколько телефонных селекторов/якорей. Существующие специальные заголовки MICE, B2B, тура, экскурсии и страны сохранены через свойства layout.

## Поля и клиентская логика

Форма содержит имя, телефон с выбором страны и маской, email, комментарий, способ связи: телефон / WhatsApp / Telegram / email. Служебные поля — `entity_id`, `tour_id`, `page_url`, `locale`. Телефонный компонент `PhoneField.astro` используется без копирования его реализации.

Клиентская логика повторяет рабочую GAEO-форму в состоянии после commit `5e293ff1`:

- имя обязательно; нужен хотя бы телефон или email;
- телефон проверяется по полной маске выбранной страны, email — браузерной email-валидацией;
- способ связи должен соответствовать реально заполненному каналу;
- Backspace и курсор корректно работают внутри форматированной телефонной маски;
- есть honeypot `company_website`, время начала и отправки формы, referrer, UTM и click-id;
- во время POST кнопка блокируется; ошибка сервера показывается в самой форме;
- после успешного ответа показывается короткое верхнее уведомление, а форма скрывается через 650 мс;
- honeypot получает внешне такой же success-flow и не отправляет запрос;
- если endpoint не задан, форма показывает ошибку и не имитирует успешную заявку.

Под кнопкой есть ссылки на политику конфиденциальности и обработку персональных данных.

## Серверная отправка

GitHub Pages остается статическим. Клиент отправляет JSON в отдельную Yandex Cloud Function; публичный URL функции хранится только в `public/form-config.js` как `window.ADATOURS_FORM_ENDPOINT`. Это публичная конфигурация, секретов в ней нет.

Канонический серверный исходник: `serverless/adatours-form/index.py`. Схема та же, что на GAEO.ru: Yandex Cloud Function → Yandex Cloud Postbox → email. Обработчик проверяет Origin, допустимый URL Ada Tours, размеры и форматы полей, honeypot и слишком быструю отправку. Содержимое заявки и персональные данные в лог не пишутся.

До фактического развертывания функции `public/form-config.js` остается с пустым endpoint. После развертывания туда записывается ее публичный invocation URL; отдельные секреты во frontend не добавляются.

## Получатели заявок

Получатели задаются только на серверной стороне Cloud Function / Postbox.

Первый этап тестирования:
- отправлять заявки только на `ya@gaeo.ru`;
- `Anna@adatours.com` и `Operations@adatours.com` в тестовые отправки пока не включать.

После успешных тестов и отдельного подтверждения пользователя перейти на рабочий список получателей:
- `ya@gaeo.ru`;
- `Anna@adatours.com`;
- `Operations@adatours.com`.

До этого подтверждения единственный адрес доставки заявок — `ya@gaeo.ru`.

## Автоматическая проверка

Штатный `scripts/check-interest-presentation.mjs` проходит весь сформированный HTML сайта: на каждой реальной странице ровно одна форма и один якорь, форма расположена перед footer, присутствуют пользовательские, контекстные, телефонные и anti-spam поля, статус отправки и legal-ссылки; старая заглушка `onsubmit="return false;"` запрещена. Redirect aliases исключаются по техническому перенаправлению, а не по произвольному списку URL. Обычное добавление новой сущности получает форму автоматически без ручной правки каталогов.
