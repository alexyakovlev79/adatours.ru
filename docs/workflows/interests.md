# Ada Tours — интересы: разметка и автоматические тематические страницы

Версия: 1.0 · 2026-10-05. Действующий контракт. Канонические исходники — GitHub, ветка `main`.

## 1. Единый закрытый справочник

Источник идентификаторов и порядка: `src/data/interest-registry.json`. Существующие 9 ID и английские URL сохранены, добавлены 4 согласованных интереса. Новые интересы, синонимичные ID и изменения slug допускаются только по прямому согласованию с пользователем. VIP/Luxury и MICE — сегменты сервиса, а не дополнительные интересы. Трекинг, горы, археология и бердвотчинг не создают отдельных страниц.

## 2. Что размечается вручную

**Tour:** `primaryThemes` — 1–2 интереса, ради которых реально выбирают поездку. `themes` — только остальные существенные интересы. Массивы не пересекаются, не содержат дублей. Для попадания в подборку используется объединение обоих массивов, а не только `themes`.

```yaml
primaryThemes: [theme_adventure, theme_wildlife]
themes: [theme_culture]
```

**Excursion:** `themes` описывают саму экскурсию. Обзорная экскурсия по Рио не получает приключения из-за присутствия в adventure-туре. Собственный текст экскурсии — основание, `excursionRef` — связь, но не основание для наследования меток.

**Destination:** `themes` относятся к самому месту по его самостоятельному описанию. Парк может быть природным, винодельческий регион гастрономическим. Встречаемость города в приключенческих турах не делает город приключенческим.

Для экскурсии/места `themes: []` допустим, когда собственный материал не даёт основания для конкретного интереса. Это осознанное решение; не заполнять догадками ради формального покрытия. Для активного тура обязательны 1–2 `primaryThemes`; отсутствие источника для выбора — адресный пробел контента, не разрешение придумать интерес.

**Country:** не содержит ни `themes`, ни `relatedThemes`. **Theme:** не содержит `featuredCountries`, `featuredDestinations`, `featuredTours` и ручных `relatedThemes`. Даже пустые устаревшие поля в MD не добавлять. География, туры, впечатления и соседние интересы вычисляются, а не курируются отдельными списками.

Читать название, lead/summary и программу выбранного источника. Заголовок помогает определить назначение продукта, но не заменяет программу. Не назначать туровые метки по SEO-алиасам, подписям фото, перечню доступных развлечений, факультативным услугам или упоминанию отеля. Существенность определяется содержанием и временем программы, а не наличием отдельного слова. Общая городская/природная программа и узкий специализированный продукт могут иметь разную основную тему.

## 3. Источник и поддержка разметки

Текущие `primaryThemes`/`themes` хранятся в production MD сущности и совпадают с полями `data/source-index/entries/<id>.json` и её записи в `data/source-index/catalogs/<collection>.json`. При создании/содержательной правке выбранного объекта уточнить метки по его же источнику и обновить эти записи в одном commit. Не обходить соседние объекты и весь Drive ради одной записи.

`data/interest-annotations.json` — журнал разового прохода по базе 05.10.2026 с точными ID и sourcePath; это **не runtime-источник и не команда повторно перезаписать отредактированные метки**. При новой явной массовой миграции журнал обновляется отдельно. Текущие страницы всегда читают MD; добавление нового размеченного тура сразу влияет на сборку тематических страниц.

Самостоятельные новые экскурсии, выделенные из тура, размечаются отдельно. Будущие резервы мест не получают опубликованные пустые MD ради темы. Статусы и источники не менять из-за разметки. Архивные сущности не размечать заново и не возвращать в активный каталог.

## 4. Модель связей и сортировки

Реализация: `src/lib/interest-model.mjs`. Один и тот же расчёт применяется к странице интереса, полному тематическому каталогу и его страновым подкаталогам. Нет регулярных выражений по названиям, поиска слов в тексте, случайной сортировки и fallback на прежние ручные списки.

**Тур:** вес интереса 2 для `primaryThemes`, 1 для `themes`, 0 иначе. Сначала вес по убыванию. Внутри равного веса — действующая коммерческая формула `2 × число уникальных основных стран − |durationDays − 13|`, затем русское название. Основные страны — `routeCountries ?? countries`; при неизвестной длительности коммерческий рейтинг ниже всех известных. Сильный коммерческий балл не перескакивает через уровень тематической релевантности.

**Страна:** сумма по **всем** подходящим активным турам `вес интереса × вес страны`. Основная страна получает 1, только дополнительная в `countries` — 0,25. Каждый тур учитывается один раз. Сортировка: сумма, число тематических туров, русское название. Счётчик показывает число уникальных тематических туров, а не сумму весов. Дополнительные посещения подписываются отдельно. Это специальная модель Theme; обычные каталоги/счётчики Country по-прежнему используют основные страны.

**Место:** обязательна собственная метка. Попадает в кандидаты, если присутствует в тематическом туре или связано с тематической экскурсией. Вес — сумма весов тематических туров через место плюс 0,5 за каждую самостоятельную тематическую экскурсию места. `routeDestinations ?? destinations` — основные места с весом 1; только дополнительные — 0,25.

**Экскурсия:** обязательна собственная метка. Вес — число уникальных тематических туров с её явным `excursionRef`, в том числе внутри `contentBlocks`. Повтор одной ссылки в программе не умножает счётчик. Самостоятельная экскурсия без туровых ссылок остаётся допустимой с весом 0; под ней нет выдуманного количества туров.

Места и экскурсии объединяются в одну ленту. При равном тематическом весе — число связанных активных туров всех интересов, затем русское название и ID. Для первых пяти визуальных историй сначала берётся по одному доступному кандидату с фото из разных стран в рассчитанном порядке; второй проход заполняет свободные позиции. Это редакционное разнообразие внутри тематически допустимой выборки, не отдельный ручной рейтинг. Нижний блок не повторяет ID верхнего.

**Связанные интересы:** число общих активных туров в объединении основных и дополнительных меток, затем русское название. Текущий интерес исключается; нулевые связи не показываются.

Активность определяется общим `isActiveEntity`: черновики и архив по статусу/центральному реестру исключаются. Архивные/неактивные страны не служат карточками географии; места/экскурсии такой страны не становятся впечатлениями. Архивные ссылки-дубли экскурсии разрешаются только в подтверждённый активный canonical replacement по общему механизму архива.

## 5. Страница интереса

`Hero + тезис → до 5 визуальных историй → до 10 туров → до 7 стран → до 10 других мест/экскурсий → до 4 связанных интересов → полезный текст темы → CTA/форма`.

При небольшом ассортименте не добивать блок нерелевантными объектами. Пустые блоки впечатлений/стран/соседних интересов скрываются; при отсутствии готовых туров отображается честное предложение индивидуальной программы. Авторитет/эксперт не выдумывается: используется существующая форма Ada Tours. Тексты, hero и `imageTextAlign` самой темы остаются редакционными свойствами.

Сильная первая история крупнее остальных. Фотографии — уже существующие фотографии сущностей, без новых генераций или внешнего поиска. В обычных карточках текст расположен рядом/под фото; глобальное свойство стороны текста относится только к тексту поверх фотографии и не выравнивает обычные абзацы.

## 6. Полные каталоги и ссылки

`/interests/<theme-slug>/tours/` — все активные туры интереса.

`/interests/<theme-slug>/tours/<country-slug>/` — все его туры с данной основной либо дополнительной страной. Карточки стран на Theme ведут сюда, а не на общий Country. Дополнительная география отмечается у тура. Пустые каталоги не публикуются.

Все каталоги используют общую статическую пагинацию по 10 объектов, self-canonical, `/page/2/` и следующие страницы, рабочие обычные ссылки, «Показать ещё», `ItemList` и sitemap. География/связанные интересы считаются **до** ограничения 10 туров. Ссылка на полный тематический каталог доступна даже при небольшом числе туров. Существующие country-first URL объектов, stable ID и старые redirect aliases не меняются.

`/interests/` выводит 13 интересов в порядке справочника с актуальными тематическими счётчиками. Поиск туров учитывает обе группы меток, включая русские названия интересов; архив в поиск не попадает. На Country интересы тоже вычисляются из активных тематических туров.

## 7. Узкая машинная проверка и публикация

`tests/interest-model.test.mjs` проверяет веса, коммерческий порядок, полную географию, необязательные страны, дедупликацию, независимость меток, архивы, пустую тему и связанные интересы. `scripts/check-interest-model.mjs` проверяет реальные 13 HTML-хабов и полные каталоги после сборки. Существующий `check-catalog-pagination.mjs` проверяет также новые каталоги.

Схема/валидация останавливает сборку при неизвестном интересе, дублях, пересечении массивов, неверном количестве основных тем активного тура или возврате ручных списков. Исторические архивные MD не переписываются ради этого ограничения. Сборка офлайн по источникам: внешние материалы не читаются.

Один подготовленный production commit, штатные build/deploy с привязкой к SHA. При параллельной работе сохранить все чужие изменения, особенно медиа. Project Sources — копии канонических MD; после изменения контракта обновить доступные копии, а при отсутствии доступа передать пользователю точные обновлённые файлы без заявления об их автоматической замене.
