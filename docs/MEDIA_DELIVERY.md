# Ada Tours — медиа на Yandex Object Storage

**Релизная схема с 09.10.2026.** Страницы сайта — Astro + GitHub Pages. Изображения и будущие короткие видео — Yandex Object Storage на `https://img.adatours.ru/media/`, пока без дополнительного CDN.

## Публикация новых изображений

1. Существующие 2 981 файла перенесены и сверены с S3 по SHA-256 на этапе 08–09.10.2026. Исходный Git остается резервом без удаления и переписывания истории.
2. Новые файлы **не сохраняются в Git**. ChatGPT Work использует инструкции `docs/workflows/direct-s3-upload.md`: локальный WebP/MP4 за пределами репозитория → одноразовые локальные X25519-ключи → публичный запрос в GitHub → краткоживущий IAM-токен, зашифрованный в GitHub Actions → расшифровка только в Work → прямая отправка файла в S3 → проверка SHA-256 и размера.
3. `/media/...` остается каноническим логическим путём в MD, фотореестрах, каталоге источников. Новая версия всегда получает новое имя файла. Существующий S3-объект с отличающимися байтами не перезаписывать.
4. Для нового S3-файла `src/data/media/direct-s3-uploads.json` хранит только `key`, `sha256`, `bytes`, `contentType`, `uploadedAt`, `source`. Один текстовый commit объединяет receipt, измененные MD/JSON, историю фотографий и ссылки. S3-ключи и короткие/постоянные IAM-токены в Git не хранятся.
5. GitHub Actions до сборки проверяет отсутствие новых/измененных `public/media` объектов в истории после установленного cutoff-коммита и реальное существование файлов из receipt в S3. Затем прежние валидаторы контента принимают либо исторические локальные файлы, либо новые объекты из подписанного рабочим процессом ledger. Если проверка неудачна, деплой останавливается.
6. Перед Pagefind готовая сборка переписывает все локальные медиассылки на `img.adatours.ru`; `dist/media` удаляется только из публикуемого артефакта GitHub Pages, но исходные файлы и история Git не удаляются.

**Ограничение:** обычный чат без Work-компьютера, локального файла и HTTPS-доступа к Object Storage не может завершить прямую загрузку. В таком случае статус честно отмечается как блокер, а бинарный файл не вносится в Git в обход правил.

## Видео в hero отдельных стран и туров

На отдельных страницах Country видеофон включается полем `heroVideo: {src, sourceUrl}`. Первый пример — Бразилия: исходный ролик Pexels 4875313, также встроенный на adatours.com/brazil, без сжатия. CountryLayout передает это поле только верхнему Hero; карточки и другие баннеры сохраняют `hero.src`. Поддержка Tour требует отдельного задания.

- Оригинальный `hero.src` WebP обязателен как poster для загрузки, мобильных, сниженного движения и ошибок воспроизведения; он же сохраняется для Open Graph и JSON-LD.
- Необязательный `heroVideo` — отдельное поле с версионированным MP4 и ссылкой на источник; постер берется из `hero.src`. Автовоспроизведение только без звука, `muted loop autoplay playsinline`; есть кнопка паузы. Вне видимой области и в скрытой вкладке воспроизведение приостанавливается.
- Предпочтительный старт: H.264 MP4 с `faststart`, без аудио, 5–12 секунд, до 1280×720/24fps, ориентир 2–6 МБ; WebM допустим дополнительно. Видео не должно мешать отображению постера или LCP.
- Горизонтальное видео загружается только на десктопе шире 820 px. На мобильных, в `prefers-reduced-motion`, `Save-Data` и при неудачной загрузке оставляем WebP. Вертикальный ролик для мобильных добавляется отдельным заданием. Сжатие исходного ролика Бразилии оставлено на второй шаг по указанию пользователя.
- URL видео и фото едины для будущих языковых версий и не требуют повторного хранения файлов.

Никаких постоянных ключей S3 в чате, исходном коде или браузерном JS. IAM-федерация допускает только известную ветку GitHub `main`.
